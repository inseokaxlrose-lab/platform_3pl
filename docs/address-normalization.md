# 주소 정제 · 배송센터 결정 (사용법)

결정 기록: `docs/decisions/0076-region-center-map.md`. 코드: `src/lib/regions/`.

납품처·주문(주소가 직접 들어오는 경우)·권역 시뮬레이터가 같이 쓰는 공통 모듈이다.
**원본 주소·우편번호는 바꾸지 않는다.** 정제 결과는 따로 저장한다.

## 1. 주소 정제 `normalizeAddress(db, { address, zipCode?, detail? })`

### 등급 기준

| 단계 | 방법 (`method`) | 등급 | 설명 |
| --- | --- | --- | --- |
| ① | `API_EXACT` | A 건물 확정 | 원본 그대로 도로명주소 API 검색, 결과 1건 |
| ② | `API_CLEANED` | A 건물 확정 | 층·호·동호수·괄호·특수문자·중복 공백을 지우고 상세주소를 뗀 뒤 다시 검색, 결과 1건 |
| ③ | `MULTI_SAME_ZIP` | B 우편번호 확정 | 결과가 여러 건이지만 모두 같은 우편번호 (받은 후보가 전체일 때만). 법정동이 섞이면 법정동은 비움 |
| ④ | `TEXT_PARSE` | C 법정동 추정 | 주소 글자를 지역 마스터 이름과 맞춰 읍면동·리까지 확인 |
| ⑤ | `ZIP_ONLY` | D 시군구 추정 | 주소는 못 찾았지만 원본 5자리 우편번호가 지역 마스터에 있음 (글자 해석 시군구와 어긋나면 쓰지 않음) |
| ⑤ | `TEXT_PARSE` | D 시군구 추정 | 시군구까지만 확인 |
| ⑥ | `TEXT_PARSE` | F 실패 | 확인 불가 |

- 원본 5자리 우편번호가 정제 결과와 다르면 정제 결과를 쓰고 `zipMismatch: true`.
- 여러 건이 검색되면 `candidates`(최대 20건)를 돌려준다. 화면에서 고를 때 쓴다.
- 6자리 구우편번호는 대조표가 없어(2차) 쓰지 않는다.

### 글자 해석(④⑤)이 알아듣는 것

- 시도 줄임말·옛 이름: 서울·서울시, 경기, 충북, 강원도, 전라북도.
- 광주광역시·전라남도 → **전남광주통합특별시(12)**. 2026 자료부터 바뀌었다. 단, '광주시'는 경기도 광주시다.
- 시도 없이 시군구만 쓴 주소, 구 없이 시만 쓴 주소(수원시 → 그 아래 구 전부), 세종(시군구 없음).
- 행정동 이름은 법정동 이름으로 바꿔 찾는다: 역삼1동 → 역삼동, 영주제1동 → 영주동.
- 괄호 안 참고항목 `(역삼동, …)`.
- 같은 이름의 시군구(중구·동구·고성군)는 뒤의 읍면동으로 가린다.
- 오타(강낭구)는 알아듣지 못한다. 이건 API(①②)의 몫이다.

### 주소 API · 캐시

- 도로명주소 검색 API는 `.env`의 `JUSO_CONFM_KEY`를 쓴다.
  - 키가 없거나 연결에 실패하면 ①~③을 건너뛰고 ④부터 한다. 결과의 `apiUnavailable`에 이유가 남는다.
- 검색기는 `AddressSearcher` 약속으로 바꿔 끼운다. 지금은 테스트용 가짜 검색기가 있고, 대량 처리용 로컬 DB 검색기(2차)도 같은 약속을 따른다.
- 캐시(`tb_address_norm_cache`)
  - 키: 정리한 주소(공백 제거)와 원본 우편번호의 SHA-256. 띄어쓰기·괄호·상세주소만 다르면 같은 키다.
  - 꺼낼 때: A·B는 계속 쓰고, C·D·F는 지역 마스터 버전이 같을 때만 쓴다. 캐시에서 꺼낸 결과는 `method: 'CACHE'`, 처음 방법은 `sourceMethod`에 있다.
  - 저장하지 않는 것: API를 못 쓴 결과, 고를 후보가 남은 C·D·F.

## 2. 배송센터 결정 `resolveCenterByAddress(db, operatorId, normResult, tempZone = 'ALL')`

등급마다 보는 우편번호만 다르고, 판단 방식은 같다.
1. 우편번호마다 해당 온도대 행을 찾고, 없으면 ALL 행을 본다.
2. **모두 같은 센터면 그 센터**로 정한다.
3. 센터가 섞였거나 미배정 우편번호가 있으면 `needConfirm`과 후보 센터를 돌려준다.

| 등급 | 보는 우편번호 | `resolveLevel` |
| --- | --- | --- |
| A·B | 그 우편번호 | `ZIP` |
| C | 그 법정동의 우편번호 전부 (읍면동이면 아래 리까지) | `BJD` |
| D (우편번호만 확인) | 그 우편번호 + "확인 권장" | `ZIP` |
| D | 그 시군구의 우편번호 전부 (구가 있는 시면 아래 구 전부) + "확인 권장" | `SIGUNGU` |
| F | 없음 → 확인 필요 | — |

- 운영사 `region_auto_grade`(기본 D)보다 낮은 등급이면, 센터를 알려 주되 `needConfirm`으로 돌려준다.
- 센터 상태
  - 일시중지: 경고만 붙인다.
  - 폐쇄: 확인 필요 ("권역 재배정 필요").
- 결과의 `resolveLevel`과 `resolveKey`는 납품처·주문에 저장해, 어떤 기준으로 정했는지 추적하는 데 쓴다.

## 3. 지역 기본 배송센터 `getDefaultCenter(db, operatorId, { zipCode | bjdCode | sigunguCode }, tempZone)`

- 화면에서 배송센터를 직접 고를 때 미리 골라 둘 값이다. 그 범위의 우편번호가 모두 같은 센터일 때만 돌려주고, 아니면 `null`이다.
- 사용자가 다른 센터를 고르면 화면에서 경고한다. 예: "이 지역의 기본 배송센터는 이천센터입니다".
