## 1. 한 줄 요약

3PL 운영사가 여러 센터·창고에서 여러 화주사의 물건을 입고·보관하고, 화주사는 웹 포털에서 품목·입고예정을 등록하고 자기 재고를 조회하는 B2B 웹 솔루션.

## 2. 용어 정리

### 조직 · 위치

| 용어 | 뜻 |
|---|---|
| 운영사 | 센터를 운영하며 물류를 대행하는 3PL 회사 (이 시스템의 주인) |
| 센터 | 운영사의 물류센터. 여러 곳이며, 센터마다 입고·출고가 동시에 일어남 |
| 창고 | 센터 안의 보관 구역. 센터마다 여러 개 |
| 입고대기 창고 | 입고 확정 후 적치 전까지 재고가 잠시 머무는 센터별 창고 |
| 로케이션 | 창고 안의 보관 위치 (예: A-01-02 = A구역 1열 2단) |
| 배송권역 | 센터가 배송을 담당하는 지역 구분 |

### 화주 · 품목

| 용어 | 뜻 |
|---|---|
| 화주사 | 운영사에 물건 보관·배송을 맡기는 회사 |
| 거래처 | 화주사의 고객사. 화주사 출고 시 물건을 받는 곳 |
| 품목 (SKU) | 화주사가 맡긴 상품의 관리 단위. 화주사별로 따로 관리 |
| 기본단위 | 재고를 세는 기준 단위 (EA, KG 등). 재고는 항상 기본단위로 저장 |
| 환산단위 | 기본단위를 묶은 단위 (BOX, CARTON, PLT) |
| 입수량 | 환산단위 1개에 들어있는 기본단위 수 (예: 1 BOX = 12 EA) |
| 로트번호 | 같은 조건으로 생산된 묶음 번호. 화주사·품목에 따라 사용 여부 선택 |
| 유통기한 | 상품의 판매·사용 가능 기한. 화주사·품목에 따라 사용 여부 선택 |

### 업무

| 용어 | 뜻 |
|---|---|
| ASN (입고예정) | 화주사가 "이 물건을 언제 몇 개 보낼게요"라고 미리 알리는 문서 |
| 입고 유형 | 화주사입고(화주사가 보낸 물건), 수송입고(다른 센터에서 이동해 온 물건) |
| 출고 유형 | 거래처출고(화주사의 거래처로 배송), 수송출고(다른 센터로 이동) |
| 검수 | 도착한 물건의 수량·상태·로트·유통기한을 확인하는 작업 |
| 관리 라벨 | 검수 후 운영사가 발행해 물건에 부착하는 라벨 (바코드 포함) |
| 입고 확정 | 검수가 끝나 재고로 인정하는 단계 → 입고대기 창고에 재고 생성 |
| 적치 | 입고대기 창고의 재고를 실제 보관 로케이션으로 옮겨 등록하는 작업 |
| 재고 실사 | 시스템 재고와 실제 재고를 세어서 비교하는 작업 |
| 재고 조정 | 실사 차이·파손 등으로 재고 수량을 바로잡는 작업 (사유 필수) |
| 재고 이력 | 재고가 바뀔 때마다 남기는 기록 (은행 거래내역과 같은 개념) |

## 3. 사용자와 역할

| 역할 | 누구 | 주로 하는 일 | 볼 수 있는 데이터 |
|---|---|---|---|
| 운영사 관리자 | 운영사 본사 | 시스템 관리(기준정보 등록), 권한 관리, 정산·보고용 자료 추출 | 전체 |
| 센터 운영자 | 센터 사무직 | 화주사 전표(ASN 등) 수신, 작업 지시, 센터 사무 업무 | 소속 센터 |
| 센터 작업자 | 센터 현장 직원 | 입고 검수, 라벨 부착, 적치, 피킹, 출고, 상차 | 소속 센터 |
| 화주사 사용자 | 화주사 담당자 | 품목 등록, ASN 등록, 배송요청 등록, 자기 재고 조회 | 자기 화주사 |

**핵심 원칙**
- 화주사는 절대 다른 화주사의 데이터를 볼 수 없다.
- 센터 운영자·작업자는 소속 센터의 데이터만 다룬다.

### 권한 관리

- 권한은 **권한그룹**으로 묶어 관리하고, **사용자별로 추가·제외**도 할 수 있다.
- 권한 단위: **메뉴** 접근 + 메뉴 안의 **버튼**(조회, 등록, 수정, 삭제, 확정, 출력, 엑셀 등)
- 버튼을 숨기는 것뿐 아니라 서버에서도 같은 권한을 검사한다.

## 4. MVP 범위 (첫 버전)

### 포함 ✅

**1) 기준정보 관리**
1. 운영사 정보 관리
2. 센터 관리
3. 센터별 창고 관리 (센터 생성 시 입고대기 창고 자동 생성)
4. 창고별 로케이션 관리
5. 센터별 배송권역 관리
6. 화주사 정보 관리 (기본값 설정: 로트번호·유통기한 사용 여부, 라벨 단위 PLT/BOX)
7. 화주사 품목 관리 (기본단위, 환산단위·입수량, 로트번호·유통기한 사용 여부, 라벨 단위, 유통기한 임박 기준 일수)
8. 화주사 거래처 관리

**2) 입고 관리**
1. ASN 등록
   - 등록 주체: 화주사 사용자(포털) 또는 센터 운영자(대리 등록)
   - 등록 방식: 화면에서 직접 등록 / 엑셀 업로드 (양식 다운로드 → 검증 미리보기 → 등록)
2. ASN 조회
   - 라인별 예정 / 누적 확정 / **잔량** / **초과 수량** / 적치 수량 표시
   - **잔량 마감**: 더 이상 도착하지 않을 잔량을 사유와 함께 마감 처리
3. 입고 검수 + 관리 라벨 발행·부착
   - 라벨 단위: PLT(기본) 또는 BOX — 품목 설정에 따름
   - 라벨 코드: QR 또는 Data Matrix (많은 정보를 담기 위한 2D 코드)
   - 인쇄: 브라우저 인쇄 → 윈도우 프린터 드라이버 (프린터 기종 무관)
   - 라벨 용지: PLT / BOX별 양식 2가지 중 사용자가 선택
4. 입고 확정 → 센터의 입고대기 창고에 재고 생성
   - ASN 전체가 끝나지 않아도 **검수된 수량 일부만 확정** 가능 (여러 번 나눠서 확정)
   - 예정보다 많이 도착하면 **초과분까지 확정** 가능 (확인 메시지 표시)
5. 적치 등록 → 입고대기 창고 재고를 보관 로케이션으로 이동
   - **입고 확정으로 생성된 재고만** 적치 가능
- 입고 상태 흐름: `예정 → 검수중 → 부분확정 → 확정완료` 또는 `→ 마감`
- 적치 상태 흐름: `적치대기 → 부분적치 → 적치완료`

**3) 재고 관리**
1. 재고 조회
   - 위치 기준: 센터별 / 창고별 / 로케이션별
   - 소유 기준: 화주사별 / 품목별
   - 로트번호 / 유통기한별 (품목별 임박 기준에 따라 "임박" 표시)
2. 재고 조정
   - 실사 차이 확인 및 조정 등록
   - 조정 사유 등록 (필수)
3. 재고 이력 조회

**4) 공통**
1. 로그인 + 권한에 따른 메뉴·버튼 표시
2. 권한그룹 관리 + 사용자별 권한 관리
3. 정산·보고용 자료 엑셀 추출 (그리드 내보내기)

### UI 요구사항

- 최신 트렌드의 깔끔하고 심미적인 디자인, 라이트/다크 모드
- 목록 화면은 공통 그리드로 통일 (정렬, 검색, 필터, 페이지, 컬럼 설정, 내보내기)

### 제외 ❌ (MVP 이후)

- 출고 관리 (배송요청 등록, 피킹, 패킹, 상차, 거래처출고)
- 센터 간 이동 (수송입고, 수송출고)
- 정산·청구 계산
- 바코드 스캐너 / 모바일 작업 화면
- 쇼핑몰·택배사 외부 연동
- 여러 운영사가 함께 쓰는 SaaS 구조 (MVP는 운영사 1곳 기준)

> 단, 출고·수송은 MVP 이후 바로 붙일 수 있도록 **입고 유형, 재고 구조, 역할**은 처음부터 이를 고려해 설계한다.

## 5. 성공 기준

- 화주사가 ASN을 등록하면 → 작업자가 검수·라벨 발행 → 입고 확정 → 적치하고, 화주사가 포털에서 늘어난 재고를 확인할 수 있다.
- 로트·유통기한을 쓰는 화주사와 쓰지 않는 화주사가 같은 화면에서 문제없이 처리된다.
- 모든 재고 수량 변화가 재고 이력으로 추적된다.
- 화주사 A 계정으로 화주사 B의 데이터에, 센터 X 직원으로 센터 Y 데이터에 접근할 수 없다.
- 권한이 없는 버튼은 보이지 않고, 서버에서도 거부된다.

## 6. 열린 질문 (나중에 결정)

- 라벨 양식 4종의 정확한 크기와, 사람이 읽도록 인쇄할 항목은? (크기 초안은 0003 결정 6 참고) → M5 전까지
- 재고 실사 방식: 전체 실사 / 로케이션 지정 순환 실사? → M6 전까지 (추후 결정)
