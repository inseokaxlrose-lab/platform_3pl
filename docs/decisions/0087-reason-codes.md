# 0087. 사유 코드와 귀책 (M8 A1)

- 날짜: 2026-11-20
- 상태: 채택
- 관련: 0030·0040 (공통코드·상수 경계), 0052 (ASN 잔량 마감), 0053 (검수), 0061 (실사·조정), 0045 (재고 변경 공통 함수), 기준정보 누락 검토 1-4·2-3·3-5
- 코드: `src/config/defaults/codes.ts` (사유 그룹), `src/config/db-codes.ts` (`FAULT_PARTY_LABELS`), `src/lib/common-code/` (귀책 저장·사용처), `src/components/common/confirm-dialog.tsx` (`reason.codeGroup`), `src/components/common-code/reason-text.tsx`
- 마이그레이션: `20261120080000_reason_codes`

## 배경

검수 불량·재고 조정·ASN 잔량 마감의 사유가 자유 입력이라 "누구 책임인지" 집계할 수 없었다. 3PL은 화주 귀책(입고 불량)과 센터 귀책(보관 중 파손)을 나눠야 보상·정산이 된다.

## 사용자 결정 (2026-11-20)

- 귀책은 **공통코드에 속성 칸을 추가**해서 둔다 (추천안). 운영사가 사유를 추가·수정할 수 있고, 귀책은 표시·집계용이다.

## 결정

### 공통코드 귀책

- `tb_code_group.fault_party_yn`: 'Y'면 이 그룹의 코드마다 귀책을 둔다. 공통코드 화면 [그룹 수정]의 **귀책 구분 사용**.
- `tb_code_item.fault_party_cd`: SHIPPER 화주 / CENTER 센터 / CARRIER 운송사 / ETC 기타 (상수 `FAULT_PARTY_LABELS` + DB 검사, 값 목록 일치 테스트). 그룹이 귀책을 쓰지 않으면 저장할 때 비운다.
- 범용 속성 칸(`attr1` 등) 대신 **이름 있는 칸**으로 둔 이유: 지금 필요한 속성은 귀책 하나이고, 값 목록을 DB 검사로 묶을 수 있다. 다른 속성이 필요해지면 그때 칸을 추가한다.

### 사유 그룹 (시스템 그룹, 귀책 사용)

| 그룹 | 쓰는 곳 |
| --- | --- |
| `DEFECT_REASON` 검수 불량 사유 | `tb_inbound_inspection.defect_reason_cd` — 불량 수량이 있으면 필수 |
| `ADJUST_REASON` 재고 조정 사유 | `tb_stock_adjust.reason_cd`(필수) → 확정 때 `tb_stock_txn.reason_cd`로 |
| `HOLD_REASON` 재고 보류 사유 | 재고 상태 변경 (A2) |
| `ASN_CLOSE_REASON` 입고 잔량 마감 사유 | `tb_asn.close_reason_cd` — 마감 때 필수 |
| `CANCEL_REASON` · `RETURN_REASON` | 출고 취소·반품 (출고 기능에서) |

- 기존 운영사에는 마이그레이션이, 새 운영사에는 `provisionOperator`가 넣는다(없으면 만들기).
- 사유 **코드**(필수) + 사유 **메모**(자유 입력, 선택)를 함께 둔다. 예전 자유 입력 칸(`reason`·`close_reason`·`remark`)은 메모가 된다. 이전 줄은 코드가 비어 있다(되채우지 않음).
- 공통코드 사용처(`code-usage.ts`)에 등록해, 쓰인 사유 코드는 지울 수 없다(사용 중지만).
- `adjustStock`은 사유 코드나 사유 글자 중 하나가 있으면 된다(재고 조정은 사유 필수 규칙 유지). 코드 검사는 부르는 쪽(실사·조정 등록)이 한다.

### 화면

- 공통코드: 코드 목록에 **귀책** 열, 코드 팝업에 귀책 고르기, 그룹 팝업에 귀책 구분 사용.
- 검수: 불량 수량을 넣으면 **불량 사유** 고르기(필수), 검수 기록에 불량 사유 열.
- 실사·조정: **사유**(고르기, 필수) + **사유 메모**. 목록·상세·재고 이력은 "사유 이름 — 메모".
- ASN 잔량 마감: 공용 확인 대화상자에 `reason.codeGroup`을 주면 사유를 고르고(필수) 글자 칸은 메모가 된다.

## 버린 안

- **사유를 상수 + DB 검사로 고정**: 운영사마다 사유가 달라 화면에서 추가할 수 있어야 한다. 프로그램이 귀책에 따라 동작을 바꾸지 않으므로 공통코드가 맞다(0030 경계).
- **기존 자유 입력 사유를 'ETC'로 되채우기**: 실제 사유를 모르는데 '기타'로 바꾸면 집계가 왜곡된다. 비워 둔다.
