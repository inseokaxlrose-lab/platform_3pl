# 0027. 센터별 창고 관리

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0026 (센터·창고 기본 구조), 0025 (코드 체계), 0016 (데이터 범위)
- 화면: `/admin/master/warehouses` (목록), `/new` (등록, `?centerId=`로 센터 미리 고르기), `/[id]` (수정)
- 코드: `src/lib/warehouses/`, `src/app/admin/master/warehouses/`

## 결정

### 창고 항목

| 묶음 | 항목 |
|---|---|
| 기본 정보 | 센터\*(등록 시 선택, 이후 변경 불가), 시스템 코드(`WH000001`), 창고 코드(같은 센터 안 중복 금지, 비우면 시스템 코드), 창고명\* |
| 창고 성격 | 유형(일반 / 입고대기 — 입력받지 않음), **보관 조건**(상온 / 냉장 / 냉동, 사용자 결정으로 추가) |
| 외부 코드 | SAP · ERP |
| 상태 | 사용 / 사용 중지 (삭제 없음) |

- 보관 조건: 냉장 물건을 상온 창고에 적치하는 실수를 나중에(적치·품목 작업) 경고하는 데 쓴다. 기존 창고는 상온으로 채웠다.
- 사용자 코드 규칙(영문·숫자·하이픈·밑줄 2~20자, 대문자, 시스템 코드 모양 금지)을 `userCodeField`·`looksLikeSystemCode`로 공통화했다. 센터도 같은 함수를 쓴다.

### 입고대기 창고 보호 (서버에서 검사)

| 할 수 있음 | 할 수 없음 |
|---|---|
| 창고명·보관 조건·외부 코드 수정 | 새로 만들기(센터 등록 때 자동으로만), 유형 변경, 코드(`INBOUND`) 변경, 사용 중지 |

- 이유: 센터마다 입고대기 창고가 **항상 1개, 늘 사용 중**이어야 입고 확정이 들어갈 곳이 있다.
- 사용자가 만드는 창고는 항상 일반 유형이다. 입력 규칙에 유형 칸이 없어서, 보내도 버려진다.
- 사용 중지된 센터에는 창고를 추가할 수 없다.

### 권한·데이터 범위

- 메뉴 권한 `master.warehouses.read/create/update`
- 센터 직원은 소속 센터의 창고만 보고 다룬다. 목록의 센터 고르기·등록의 센터 선택에도 소속 센터만 나온다. 다른 센터 창고 주소는 "찾을 수 없음"이다.
- 창고 추가는 센터 등록과 달리 **자기 범위 안에서는 센터 직원도 가능**하다(권한이 있으면). 자기 범위를 벗어나지 않기 때문이다. 기본 그룹에서는 센터 운영자·작업자 모두 창고 조회만 가진다.

### 화면

- 목록: 툴바의 센터 고르기(모든 센터 / 센터별). 사용자가 정렬을 고르지 않으면 센터 → 창고 코드 순서로 묶어서 보여준다.
- 등록·수정: 입력은 왼쪽 단, 수정 화면 오른쪽에 상태(입고대기는 사용 중지 대신 안내)와 로케이션 요약(최대 20개 미리보기).
- 센터 상세의 창고 목록: 줄을 누르면 창고 수정으로(창고 조회 권한), [창고 추가]는 그 센터를 미리 고른 등록 화면으로(창고 등록 권한, 사용 중인 센터만).

## 함께 고친 것

- 마이그레이션 폴더 이름 순서 문제를 발견해 고쳤다 (0026 "주의" 참고).

## 확인

- 테스트: 입력 규칙 3개, 서버 액션 9개 (같은 센터 안 중복·다른 센터 허용, 입고대기 보호, 사용 중지 센터, 범위, 권한).
- 브라우저(admin):
  - 이천센터 상세의 [창고 추가]로 들어가자 센터가 미리 골라져 있었다.
  - `c01` / 냉장으로 저장하자 `C01`, 시스템 코드 `WH000004`가 붙었다.
  - 입고대기 창고 화면은 코드가 잠겨 있고, 사용 중지 버튼 대신 안내가 보였다.
  - 목록은 센터별로 묶여 보였다.
- `center.manager`(이천, 조회만): 이천 창고는 읽기 전용, 김해 창고는 404, [창고 등록] 없음, 센터 고르기에 김해 없음.
- 확인용 창고는 지웠다.
