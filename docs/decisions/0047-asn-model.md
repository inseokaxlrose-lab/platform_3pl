## 구조

| 표 | 한 줄 | 주요 칸 |
| --- | --- | --- |
| `tb_asn` (ASN 헤더) | 입고예정 한 건 | 센터·화주사, ASN 번호, 입고 유형(`InboundType` SHIPPER·TRANSFER), 등록 경로(`AsnChannel` PORTAL·PROXY·EXCEL), 예정일, 화주사 문서 번호, 입고 상태(`AsnStatus`), 적치 상태(`PutawayStatus`), 마감 사유·마감자·일시, 공통 칸 + 논리 삭제 |
| `tb_asn_line` (ASN 라인) | 품목 하나의 예정 | 라인 번호, 품목, 예정 수량(기본단위), 입력 단위·수량(표시용), 예정 로트·유통기한(참고), **누적 확정·적치·마감 수량** |
| `tb_inbound_receipt` (입고확정) | 확정 한 번 | 확정 번호, ASN, 확정 일시·확정자 |
| `tb_inbound_receipt_line` | 확정 한 줄 | ASN 라인, 만들어진 재고 줄·재고 이력, 로트·유통기한, 확정 수량·그중 적치 수량 |

- 잔량 = max(예정 − 누적 확정, 0), 초과 = max(누적 확정 − 예정, 0), 적치 가능 = 누적 확정 − 누적 적치 → **저장하지 않고 계산** (0003).
- "확정된 재고만 적치"는 입고확정 라인의 `putaway_qty ≤ confirm_qty`로 지킨다: 적치는 입고확정 라인을 골라서 한다(M5 적치 작업).
- ASN 라인은 헤더와 통째로 바뀌는 하위 표 → 감사 칸 없음(헤더 이력). 입고확정은 문서라 확정자만 남긴다.
- 운영사 거르기(`TENANT_MODELS`): 4개 표 모두. 공통 칸·논리 삭제: ASN 헤더만.

## 추천안으로 정한 것 (검토 필요)

- **문서 번호 모양**: `접두어 + 한국 날짜 YYMMDD + '-' + 일련번호 5자리` (예: `AS261116-00001`, 입고확정 `RC…`). 일련번호는 종류별 DB 시퀀스로 날짜가 바뀌어도 이어진다(날짜마다 1부터 다시 시작하지 않음) → 동시에 등록해도 겹치지 않고 구현이 단순. 기준정보 시스템 코드(`CT000001`)와 구분하려고 날짜를 넣었다. `src/config/document-numbers.ts`, `src/lib/documents/doc-no.ts`.
- **ASN 지우기**: 예정(PLANNED) 상태에서만, 논리 삭제(`del_yn`). 검수가 시작되면 지울 수 없고 잔량 마감으로 끝낸다.
- **입력 단위 기록**: 라인에 입력한 단위·수량(예: BOX 3)을 함께 남겨 화면에서 그대로 보여 준다. 계산은 항상 기본단위 `expected_qty`.
- **예정 로트·유통기한**: 화주사가 알면 ASN에 적을 수 있지만 참고용. 실제 값은 검수에서 넣는다.
- 검수 결과·라벨 표는 각 작업(M5 검수·라벨)에서 따로 만든다.

## DB가 막는 것

- ASN: 마감 상태면 사유(공백 아님)·마감자·일시 필수, `del_yn` Y/N.
- 라인: 예정 > 0, 누적 확정·적치·마감 ≥ 0, **적치 ≤ 확정**, 입력 수량 > 0, 로트 빈 글자 금지, 라인 번호 > 0, ASN 안에서 라인 번호 하나. 초과 확정(확정 > 예정)은 허용(0003).
- 입고확정 라인: 확정 > 0, 0 ≤ 적치 ≤ 확정.
