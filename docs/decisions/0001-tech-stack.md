# 0001. 기술 스택 선택

- 날짜: 2026-11-13
- 상태: 채택

## 배경

- 웹 기반 B2B 관리 솔루션 (표, 폼, 검색 화면이 대부분)
- 운영사 화면과 화주 포털 두 개의 화면이 필요
- 1인 + AI(바이브 코딩)로 개발 → 관리할 프로젝트가 적을수록 유리
- 재고 데이터는 정확해야 함 → 트랜잭션을 지원하는 관계형 DB 필요

## 결정

| 영역 | 선택 | 이유 |
|---|---|---|
| 프레임워크 | Next.js (App Router) | 화면과 서버 API를 한 프로젝트에서 관리. 자료와 AI 학습 데이터가 가장 많음 |
| 언어 | TypeScript | 데이터 모양(입고, 재고 등)을 타입으로 정해두면 AI가 실수할 때 바로 잡힘 |
| DB | PostgreSQL | 재고처럼 정확해야 하는 데이터에 강한 관계형 DB, 트랜잭션 지원 |
| ORM | Prisma | DB 구조를 `schema.prisma` 한 파일로 읽기 쉽게 관리 |
| 인증 | Better Auth (M1에서 최신 문서 확인 후 확정) | 역할 / 조직 개념 지원 |
| UI | Tailwind CSS + shadcn/ui | 관리자 화면용 표·폼 컴포넌트를 빠르게 조립 |
| 표 | TanStack Table | 정렬·필터·페이지가 많은 B2B 목록 화면용 |
| 검증 | Zod | 폼 입력과 API 입력을 같은 규칙으로 검사 |
| 테스트 | Vitest (단위), Playwright (브라우저) | |
| 패키지 매니저 | npm | 이미 설치되어 있음 |

## 대안과 버린 이유

- **React + 별도 백엔드(NestJS 등)**: 구조는 깔끔하지만 프로젝트가 두 개가 되어 1인 개발에 부담. 나중에 필요하면 분리 가능.
- **Firebase / NoSQL**: 재고·입고처럼 관계가 많은 데이터에 불리.

## 아직 정하지 않은 것

- 로컬 DB 실행 방법 (Docker 미설치 → Postgres.app / Homebrew / 클라우드 DB 중 M0에서 결정)
- 배포 위치 (M5에서 결정)
