# 0069. 상단 메뉴 탭 (책갈피 방식) + 새 창 열기 + 변경 중 표시

- 날짜: 2026-11-16
- 상태: 채택 (사용자 결정: 책갈피 탭 + 새 창 열기, 변경 중이면 ● 표시)
- 관련: 0022 (사이드바·즐겨찾기), 0031 (입력 화면·변경 감지), 0036 (페이지 틀)
- 계기: 사용 중 불편 — "메뉴가 하나만 열린다"

## 정한 것

상단 바 바로 아래에 **메뉴 탭 줄**을 둔다 (운영사 화면·화주 포털·플랫폼 화면 공통, `src/components/app-shell/menu-tabs.tsx`).

| 하는 일 | 동작 |
| --- | --- |
| 메뉴를 연다 (사이드바·링크·주소) | 그 메뉴 탭이 생기거나, 있으면 그 탭이 선택된다. 홈 탭은 늘 맨 앞, 닫을 수 없다 |
| 탭을 누른다 | 그 메뉴에서 **마지막으로 보던 주소**로 (검색 조건·페이지·하위 화면 `/asn/123` 그대로) |
| 탭 [×] | 닫는다. 보던 탭이면 오른쪽 → 왼쪽 → 홈으로 옮긴다 |
| [전체 닫기] (탭 줄 오른쪽 끝, 메뉴 탭이 있을 때만) | 메뉴 탭을 모두 닫고 홈으로. 보던 탭은 홈으로 옮긴 뒤 닫으므로, 변경 중이면 확인 창이 먼저 뜨고 [계속 작성]이면 그 탭만 남는다. 탭이 많아 줄이 밀려도 오른쪽에 고정 |
| 탭 [↗] (마우스를 올리면 보임) | 그 탭을 새 창으로 연다. 사이드바 메뉴도 Ctrl/⌘ + 클릭이면 새 창 |
| 저장하지 않은 변경이 있다 | 그 탭에 **●** (마우스를 올리면 ×). 다른 탭으로 가거나 닫으면 기존 확인 창 ("저장하지 않은 변경") |
| 탭 개수 | 최대 10개, 넘으면 가장 오래 안 쓴 탭부터 닫는다 |
| 탭 폭 | **고정 폭**: 메뉴 탭 176px(`w-44`), 홈 탭 96px(`w-24`). 이름 길이에 따라 움직이지 않고, 넘치면 … |
| 선택된 탭 | 위쪽 브랜드 색 띠(`border-t-primary`) + 아이콘 브랜드 색 + 굵은 글자. 탭 줄 바탕은 `bg-muted`, 선택된 탭만 본문과 같은 `bg-background`라 본문과 이어져 보인다 |

- **책갈피 방식**: 탭은 화면을 뒤에 살려 두지 않고, 다시 열 주소만 기억한다. 화면을 떠날 때 확인 창이 먼저 뜨므로 변경 중인 화면은 늘 하나(보고 있는 탭)다.
- 탭 목록은 **브라우저 창마다 따로** (`sessionStorage`, 영역별 키 `menu-tabs:admin` 등): 새 창은 자기 탭 줄을 갖고, 새로고침해도 남는다. 저장소를 못 쓰면 그 화면에서만 기억한다.
- 권한이 바뀌어 볼 수 없게 된 메뉴의 탭은 그리지 않는다. 저장된 값은 메뉴 주소로 시작하는 주소만 받는다.

## 구현 메모

- 순수 계산 `menu-tabs-state.ts`(열기·닫기·전체 닫기·최대 개수·읽기 검사) + 보관 `menu-tabs-store.ts`(useSyncExternalStore, 서버에서는 빈 목록).
- 변경 중 표시: `src/lib/navigation/page-dirty.ts` — `useDirtyGuard`가 변경 여부와 "떠나도 될지 묻기" 함수를 알리고, 탭이 읽는다. 보던 탭 [×]도 같은 확인 창을 쓴다.
- 상단 바 + 탭 줄을 함께 고정(3.5rem + 2.5rem = 6rem). 페이지 헤더(`AppPage` `top-24`)와 섹션 목차 위치(`BELOW_HEADER`)를 그만큼 내렸다.

## 버린 안

- **펼쳐두기 탭**(열린 화면을 뒤에 살려 둠, 입력값 유지): App Router는 주소 하나에 화면 하나라 공통 틀을 크게 바꿔야 하고, 화면을 많이 열면 무거워진다. 검색 조건이 이미 주소에 있어 책갈피로도 대부분 해결된다.
- **메뉴마다 새 창**: 창이 계속 늘고 오가기 불편, 팝업 차단. → 나란히 볼 때만 [↗]로.
