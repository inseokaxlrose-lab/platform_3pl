# 0076. 권역설정 (우편번호 → 배송센터) · 지역 마스터 · 주소 정제

- 날짜: 2026-11-17
- 상태: 채택 (1단계 지역 마스터·적재 / 2단계 주소 정제·결정 함수 / 3단계 권역설정 화면·갱신 배치·기존 배송권역 제거 — 모두 완료)
- 관련: 0033·0072 (기존 배송권역 — 이 결정으로 **교체**), 0073 (센터 상태·온도대), 0074 (온도대 상수)

## 배경

납품처의 배송센터는 등록·I/F에서 받는 것이 원칙이지만, 빠지는 경우를 대비해 **주소로 배송센터를 자동 지정**하는 기준이 필요하다.
기존 배송권역(시도·시군구 단위 + 겹칠 때 우선순위, 0033·0072)은 경계가 굵고 겹침 규칙이 필요했다.
사용자 스펙(docs/specs/region.md)은 **우편번호(5자리)별 배정표 하나**를 단일 기준으로 한다.

## 결정

| 항목 | 정한 것 |
| --- | --- |
| 기존 배송권역 | **교체** (사용자 결정). 데이터 0건. 표·메뉴·결정 함수는 3단계에서 새 화면이 대신할 때 지운다. 거래처의 지정 배송 센터(`delivery_center_id`)는 남겨 결정 1단계로 쓴다 |
| 배정 기준 | (운영사, 우편번호, 온도대) 하나에 센터 하나 — **DB 고유 인덱스**로 중복 차단. 지역 단위로 고르면 그 아래 우편번호 전체를 **덮어쓴다** (우선순위 규칙 없음) |
| 온도대 | 기본 `ALL` 한 줄, 특정 온도대만 다를 때 그 온도대 행 추가 (온도대 행이 ALL보다 먼저) |
| 코드 값 | 배정 구분·작업 유형·정제 등급·정제 방법은 **플랫폼 상수 + DB 검사 조건** (`src/lib/regions/region-codes.ts`). 스펙은 공통코드였으나 프로그램이 값으로 동작을 바꾸므로 (0030·0040) |
| 구우편번호(6자리) 대조표 | 공식 제공 여부를 확인하지 못해 **만들지 않음**. 정제 ④는 주소 글자 해석만 |
| 우편번호만 맞는 경우 | 원본 5자리 우편번호가 지역 마스터에 있고 주소 검색이 모두 실패하면 **D 등급**(사용자 결정, 오입력 위험) |
| 자동 지정 등급 | `tb_operator.region_auto_grade`, 기본 `D` (A~D 자동). 화면 노출은 운영사 2차 섹션 때 |
| 데이터 확보 | 파일·승인키는 사용자가 받아 둔다 (회원가입·신청 필요) |

## 데이터 출처 (조사, 2026-11-17)

| 자료 | 출처 | 쓰는 곳 | 갱신 |
| --- | --- | --- | --- |
| 법정동코드 | 공공데이터포털 '국토교통부_법정동코드' CSV (또는 code.go.kr 법정동코드 전체자료) — 법정동코드·법정동명·폐지여부 | `tb_region_bjd` | 수시 → 월 적재 때 함께 |
| 주소DB 전체분 | juso.go.kr 주소DB(도로명주소 한글), 시도별 txt, `\|` 구분. 주소(건물)마다 법정동코드·기초구역번호(우편번호) | 집계해서 `tb_region_zip`·`tb_region_zip_bjd` (대표 주소 = 주소가 많은 도로 2곳의 건물번호 범위) | 전체분 + 매일 변동분 제공 |
| 도로명주소 검색 API | juso.go.kr, 무료, 시스템당 승인키 1개 → `.env` `JUSO_CONFM_KEY` | 주소 정제 실시간 단건 (2단계) | 실시간 |

- 확인 필요: API 개발·운영키 구분, 호출 한도, 기초구역 자료의 정확한 갱신 주기.
- 받는 곳: 주소DB는 파일 다운로드(공공데이터포털 파일데이터 또는 juso.go.kr 전체분)로 충분하다. juso.go.kr '데이터 연계신청'(프로그램 URL 필요)은 변동분 자동 연계용이라 쓰지 않는다.

### 실데이터 적재 결과 (법정동코드 2026-09-29 · 주소DB 2026-09, 개발 DB)

- 법정동 53,402건(파일 53,387 + 덧붙임 15), 주소 6,424,765건 전부 반영, 우편번호 34,402건, 적재 약 12초.
- **법정동 파일이 주소DB보다 오래된 경우**: 대구 달성군 구지면 → 구지읍 승격으로 바뀐 새 코드(리 15개, 주소 2,663건)가 법정동 파일에 없었다. 처음엔 조용히 빠졌으나, 주소DB 줄의 시도~리 이름으로 법정동을 덧붙이고 건수·이름을 출력하도록 고쳤다.
- **우편번호가 시군구를 넘는가**: 117건(0.3%). 115건은 같은 시의 다른 구(고양 덕양/일산동 등), 1건은 인천 서해구/검단구(2026 개편), 다른 시군 1건(영월/태백, 883곳 중 1곳). → **우편번호 단위 배정은 안전**. 우편번호의 시군구는 처음 읽은 줄이 아니라 **주소가 가장 많은 시군구**로 정한다.
- macOS는 파일 이름 한글을 자모로 풀어(NFD) 저장하므로 스크립트가 파일 이름을 완성형으로 맞춰 비교한다.

## 적재 (1단계)

- 원본 파일을 `data/region/`에 둔다 (git 제외): 이름에 '법정동'이 들어간 법정동코드 파일 1개 + 주소DB 전체분 txt(시도별 여러 개).
- `npm run region:load -- --ver 202611` (기준 데이터 연월). 인코딩(UTF-8·CP949)은 자동 판단, 파일 모양이 다르면 줄 번호와 함께 멈춘다.
- 처리: 법정동 넣기·고치기·폐지 표시 → 주소DB를 읽으며(스트리밍) 우편번호별로 모음 → 우편번호 넣기(신규는 최초 버전)·이번에 없는 우편번호는 폐지 → 우편번호↔법정동 바꾸기. 결과는 `tb_region_load_hist`.
- **갱신 주기 제안: 월 1회 전체분 재적재.** 신규 우편번호는 적재 결과로 받아 3단계 갱신 배치가 "추천 배정"한다. 매일 변동분은 1차에서 쓰지 않는다.

## 주소 정제·배송센터 결정 (2단계)

사용법·등급 기준·테스트 케이스: `docs/address-normalization.md`.

- 검색기를 바꿔 끼우는 구조(`AddressSearcher`): 지금은 도로명주소 API와 테스트용 가짜 검색기다. 대량용 로컬 DB 검색은 2차에 같은 약속으로 붙인다.
- 키가 없으면 API 단계를 건너뛰고 글자 해석(④⑤)만 한다. 이 결과는 캐시하지 않는다(키를 넣으면 더 좋아질 수 있으므로).
- 글자 해석은 지역 마스터 이름 사전으로 한다. 사전은 적재가 바뀔 때만 다시 만든다.
  - 2026 자료의 **광주·전남 통합(12)**이 반영되어 있고, 옛 이름(광주광역시·전남)도 받는다.
  - 세종은 시도 단계 기록이 없어서, 모든 기록에서 시도 이름을 모은다.
- 결정 함수는 등급별로 "볼 우편번호 범위"만 정하고, 판단은 하나로 같다(모두 같은 센터면 그 센터).
- 서버 액션(화면용 API)은 3단계 권역설정 화면과 함께 만들었다 (`src/app/admin/master/regions/actions.ts`: 시뮬레이터 `simulateRegionAction` 등). 바깥 시스템(I/F)용 API는 인증 방식이 정해지는 I/F 작업 때.

## 권역설정 화면·갱신 배치 (3단계)

화면 `/admin/master/regions` (권한 `master.regions` 조회·수정·엑셀, 기존 `master.delivery-zones` 권한을 옮김). 사용법은 도움말 `src/content/help/admin/master/regions.md`.

| 항목 | 정한 것 |
| --- | --- |
| 배치 | 위 요약 → 탭 [배정](지역 트리 + 우편번호 표) [변경 이력] [시뮬레이터] (사용자 결정) |
| 트리 | 시도 → 시군구(구가 있는 시는 '수원시 권선구'처럼 한 단계) → 읍면동. 펼칠 때 불러온다. 시도·시군구는 우편번호의 시군구(주소가 가장 많은 곳), 읍면동은 우편번호↔법정동 기준 |
| 저장 | 모든 저장이 미리보기(`planRegionChange`)를 거치고, 저장 때 같은 계산을 다시 해 작업 단위 1건 + 배정표 + 이력을 한 트랜잭션으로 (`applyRegionChange`) |
| 경계 우편번호 | 읍면동 지정 때 미리보기에서 포함/제외, 기본 제외 (사용자 결정) |
| 이력 | 센터가 바뀐 것만 이력 줄 (DB 검사 조건 `before ≠ after`). 추천 확인처럼 같은 센터면 작업 단위(CONFIRM)·배정표의 최종 작업으로 남는다. 작업자는 작업 단위에 직접 넣는다 (감사 칸 자동 채움 대상이 아님) |
| 날짜 기준 조회 | `centerAtDate(operatorId, zip, at, tempZone)`: 이력으로 그 시각의 센터 (온도대 행 → ALL) |
| 센터 규칙 | 배정된 우편번호가 있으면 폐쇄 차단("권역 재배정 필요"), 배정에 쓰인 온도대는 센터에서 뺄 수 없음, 일시중지 센터는 배정 유지 + 경고, 배정할 수 있는 센터는 준비중·운영중 |
| 엑셀 | 다운로드 = 배정표 전체 / 업로드 = 우편번호·온도대·센터코드(비우면 해제), 1,000행까지, 검사 미리보기에 바뀌는 배정 요약 |
| 갱신 배치 | 적재 스크립트가 적재 뒤 `suggestNewZips`: 신규 우편번호를 같은 읍면동에서 가장 많이 배정된 센터로 운영사별 '자동 추천'(확인 전). 폐지 우편번호의 배정은 유지하고 수를 센다. 화면 위 안내로 알린다 (알림 기능은 아직 없음) |
| 기존 배송권역 | 제거 (마이그레이션 `20261117180000_remove_delivery_zone`: 표 2개·시퀀스, 외부코드 대상 DELIVERY_ZONE, 권한 코드 이전). 거래처 목록의 '배송 센터'는 지정 → 권역설정(배송지 우편번호, 없으면 법정동) → 미배정 |
