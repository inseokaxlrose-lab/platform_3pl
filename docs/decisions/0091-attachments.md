## 사용자 결정 (2026-11-20)

- **저장소 추상화 + 지금은 로컬 폴더** (추천안). 운영 저장소(S3 호환·Vercel Blob 등)는 배포 방법(0067)을 정할 때 구현 하나를 더해 연결한다.

## 결정

- **표**
  - `tb_file`: 운영사, 저장 키, 원래 이름, 형식, 크기, SHA-256, 등록자·일시. 실제 바이트는 저장소에.
  - `tb_file_link`: 여러 장 붙는 곳 — `ITEM`(품목, 용도 `IMAGE`) · `INSPECTION`(검수, 용도 `PHOTO`). 파일 하나는 한 곳에만. 대상 종류·용도는 상수 + DB 검사.
  - 운영사 로고·직인은 `tb_operator.logo_file_id`·`stamp_file_id`가 파일을 바로 가리킨다(외래 키, 파일이 지워지면 비움). 마이그레이션 때 가리킬 파일이 없던 값은 비웠다.
  - 두 표 모두 운영사 표(prisma.ts `TENANT_MODELS`). 기록 보존용이 아니라서 버전·논리 삭제 없이 실제로 지운다(떼면 저장소 파일까지).
- **저장소**(`FileStorage`: put·get·remove): 지금은 `LocalFileStorage`(기본 `storage/`, git 제외, `.env FILE_STORAGE_DIR`). 저장 키는 `{운영사}/{연}/{월}/{UUID}` 모양만 허용(경로 벗어나기 차단), 원래 이름은 경로에 쓰지 않는다.
- **올리기 규칙**: 이미지(PNG·JPEG·WEBP·GIF)만, 형식은 **파일 앞부분(매직 바이트)**으로 판정(브라우저가 알려 준 형식은 믿지 않음), 한 장 10MB, 대상 하나에 20장. 저장소에 넣은 뒤 DB가 실패하면 저장소 파일도 지운다.
- **권한·범위**: 서버 액션은 로그인만 확인하고(`signed-in`) 대상 메뉴의 권한으로 다시 검사한다 — 보기: 품목 조회(운영사)·포털 품목 조회(화주) / 검수 조회, 바꾸기: 품목 수정·포털 품목 수정 / 검수 수정, 로고·직인: 운영사 수정. 대상은 사용자 데이터 범위 안이어야 한다(품목: 화주사·이용 센터, 검수: ASN의 센터·화주사).
- **내려받기** `/api/files/[id]`: 로그인(임시 비밀번호 상태 제외) + 같은 운영사 + 대상이 범위 안(로고·직인은 운영사 사람 모두). 볼 수 없으면 없는 것과 똑같이 404. `Cache-Control: private`, `nosniff`.
- **화면**: 운영사 화면 **로고·직인**(한 장 칸, 바로 저장), 품목 수정(운영사·포털) **이미지**(여러 장, 바로 저장), 검수 기록의 카메라 버튼 → **검수 사진**. 검수 기록을 지우면 사진도 지운다.

## 버린 안

- **DB에 바이트 저장(BYTEA)**: 백업·조회가 무거워지고, 운영 저장소로 옮기기 어렵다.
- **public 폴더·공개 주소**: 다른 운영사·화주가 주소만 알면 볼 수 있다. 내려받을 때마다 범위를 확인한다.
- **지금 바로 S3·Blob 연결**: 배포 방법이 정해지지 않아 접속 정보·비용 구조를 모른다. 추상화만 두고 나중에 구현 하나를 더한다.
- **PDF 등 문서 파일**: 지금 필요한 곳(로고·사진)은 이미지뿐이다. 인증서·허가증이 필요해지면 형식 목록과 미리보기를 넓힌다.
