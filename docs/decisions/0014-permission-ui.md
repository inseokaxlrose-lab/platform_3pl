# 0014. 화면 권한 표시 (메뉴·버튼·화면 접근)

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0011 (권한 코드), 0013 (권한 계산)

## 결정

### 권한 전달

- 레이아웃(서버)에서 `getCurrentPermissions()`로 한 번 계산 → `AppShell` → `PermissionProvider`(브라우저)로 화면 전체에 전달.
- 화면 부품은 `usePermission().can(code)` 또는 `<Can permission="…">`로 확인.
- **화면에서 숨기는 것은 편의일 뿐**이고, 서버 액션에서 같은 코드로 다시 검사한다 (다음 작업: 서버 권한 검사 공통 함수).

### 메뉴

- `filterNavigation`: 필요 권한이 없는 메뉴는 숨긴다 ("준비 중" 포함). 메뉴가 남지 않은 묶음은 제목까지 숨긴다. 홈은 항상 보인다.

### 버튼

- 권한이 없으면 **숨긴다** (비활성화하지 않는다). 할 수 없는 일을 보여줄 필요가 없다.

### 화면 접근 (주소 직접 입력)

```tsx
// 각 화면(page.tsx) 맨 위
if (!(await hasPermission('inbound.asn.read'))) return <AccessDenied />
```

- Next.js `forbidden()`은 아직 실험 기능(`authInterrupts`)이라 쓰지 않고, 안내 화면(`AccessDenied`: "접근 권한이 없습니다" + 홈으로)을 보여준다.
- 404로 숨기는 방식은 사용자를 헷갈리게 해서 쓰지 않는다.

## 확인

- 단위·화면 부품 테스트: 메뉴 걸러내기 4개, `Can`·`AccessDenied` 4개.
- 브라우저: 일부 권한 직원 → 입고(ASN 등록·조회)·재고(재고 조회)만 표시, 기준정보·시스템 묶음 숨김 / 권한 없는 직원 → 홈만. 확인 후 임시 계정·그룹 삭제.
