# 0068. 외부코드 매핑을 별도 메뉴로

- 날짜: 2026-11-16
- 상태: 채택 (사용자 결정: 7개 화면 모두에서 빼고 메뉴 1개로, 줄을 누르면 팝업에서 수정)
- 관련: 0025 (기준정보 코드 3층 — 외부 코드 매핑), 0041 (포털 품목은 외부 코드 숨김)
- 계기: 전체 테스트 체크리스트 메모 "센터 등록 시 외부코드 매핑은 제외하고 별도 매핑 메뉴로"

## 정한 것

- **기준정보 › 외부코드 매핑** (`/admin/master/external-codes`) 한 화면에서 7종 대상의 SAP·ERP 코드를 본다·고친다.
  - 대상: 센터 · 창고 · 배송권역 · 화주사 · 품목 · 거래처 · 단위 (로케이션은 아직 연동 대상이 아니라 뺀다)
  - 맨 위 **대상** 구분 버튼(빈 값 = 센터), 검색어(코드·이름), **매핑** 있음/없음, 상태
  - 목록: 코드 · 이름 · 소속(창고·배송권역 = 센터, 품목·거래처 = 화주사) · SAP 코드 · ERP 코드 · 상태
  - 줄을 누르면 팝업 → 연동 상대마다 한 칸, **비우고 저장하면 그 매핑 삭제** (기존 `saveExternalCodes` 그대로)
- 7개 등록·수정 화면(센터·창고·배송권역·화주사·품목·거래처·단위 팝업)에서 외부 코드 칸을 뺐다. 포털 품목은 원래 숨겨져 있었다.
  - 기준정보를 저장해도 **이미 있는 외부 코드는 그대로** (저장 함수가 매핑을 건드리지 않는다). 대상을 지울 때 매핑도 지우는 것(`deleteExternalCodes`)은 그대로.
- DB는 바꾸지 않는다 (`tb_ext_code` 그대로). 이미 넣은 코드는 새 메뉴에 그대로 보인다.

## 권한

- 새 권한 `master.external-codes` (조회·수정·엑셀). 슈퍼 관리자 + **센터 운영자**(품목·거래처 화면에서 고치던 일을 이어서).
- 데이터 범위는 각 기준정보 화면과 같은 규칙 (센터 직원은 소속 센터 것만, 범위 밖 대상 저장 → 찾을 수 없음).
- **이미 있는 운영사**: 기본 권한그룹은 운영사 등록 때 한 번 복사되므로 새 메뉴 권한이 없다 → 마이그레이션 `20261116150000_external_code_permissions`가 지우지 않은 "슈퍼 관리자"·"센터 운영자" 그룹에 넣는다 (사용자가 만든 그룹은 운영사 관리자가 권한그룹 화면에서 직접 고른다).
  - 앞으로 새 메뉴를 만들 때도 같은 방식(데이터 마이그레이션)으로 기존 운영사의 기본 그룹에 권한을 넣는다.

## 이유

- 외부 코드는 연동 담당자가 한꺼번에 맞추는 일이라, 기준정보마다 들어가 고치는 것보다 한곳에서 대상별로 훑어보며(매핑 없음 거르기) 채우는 편이 빠르다.
- 기준정보 등록 화면이 짧아지고, 등록하는 사람이 연동 코드를 몰라도 된다.

## 나중에

- 엑셀로 한꺼번에 올리기 (대상·코드·SAP·ERP), 화주사별 연동 상대(예: GANA-ERP) 추가 시 연동 상대 관리 화면 (0025).
