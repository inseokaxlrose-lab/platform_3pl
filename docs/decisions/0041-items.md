# 0041. 화주사 품목 — 기본값 상속·환산단위·데이터 범위

- 날짜: 2026-11-15
- 상태: 채택 (운영사 화면 적용 · 화주 포털은 다음 작업)
- 관련: 0003 결정 2·3·6 (로트·유통기한 옵션, 단위와 환산, 라벨), 0025 (코드 3층), 0034 (단위), 0035 (화주사), 0038 (공통 칸), 0039 (멀티테넌트)
- 코드: `src/lib/items/`, `src/components/item/`, `src/app/admin/master/items/`

## 결정 (사용자 결정: 모두 추천안, 2026-11-15)

- **기본값 상속**: 로트·유통기한 사용, 라벨 단위는 품목에 **"화주사 기본값 따름"(null)** / 사용 / 안 함으로 저장한다. 화주사 기본값을 바꾸면 "따름" 품목은 함께 바뀐다. 실제로 적용되는 값은 `effectiveItemOptions`(화면 안내·서버 저장·목록·이후 검수가 같이 씀)로 계산하고, 화면에 "지금 적용: …"으로 보여준다. 목록의 로트·유통기한 거르기도 적용값 기준.
- **라벨 단위의 환산단위**: 없어도 저장은 허용하고 안내만 한다(폼 경고, 목록 ⚠). 라벨 발행(M5)에서 막는다. 품목을 등록할 때는 PLT 입수량을 모를 수 있어서.
- **추가 칸**: 규격, 바코드(같은 화주사 안에서 고유, 나중 스캐너 검수용), 비고.
- **진행**: 운영사 화면 먼저, 화주 포털은 같은 폼(`ItemForm`)으로 다음 작업.

## 구조

- `tb_item`: 운영사·화주사·시스템 코드(`IT00000001`)·품목코드(같은 화주사 안에서 고유, 비우면 시스템 코드, 영문·숫자·`.`·`-`·`_` 2~30자 대문자)·품목명·규격·바코드·기본단위·관리 옵션(null 가능)·임박 기준 일수(`expiry_alert_day_cnt`, 1~3650)·비고 + 공통 칸. 화주사는 등록 후 바꿀 수 없다(재고·이력이 화주사에 묶인다).
- `tb_item_unit`: 품목 + 환산단위 + 입수량(`conv_cnt` DECIMAL(18,3), 0보다 큼). 품목 저장 때 통째로 바꾼다(품목의 이력으로 봄).
- 기본단위는 단위 표의 **기본단위**, 환산단위는 **환산단위**만. 새로 고르는 단위는 사용 중이어야 하고(이미 저장된 단위는 사용 중지돼도 유지), 입수량 소수 자리는 기본단위의 소수 자리수까지(EA면 정수).
- 유통기한을 실제로 쓰지 않으면 임박 기준 일수는 저장할 때 비운다.
- 단위 삭제 전 "품목에서 쓰는 단위" 검사(`findUsedUnitIds`)를 채웠다: 지우지 않은 품목의 기본단위·환산단위.

## 데이터 범위

- 운영사 관리자 = 운영사 전체, **센터 직원 = 소속 센터를 이용하는 화주사의 품목**(`shipper.centers.some.centerId`), 화주사 사용자 = 자기 화주사(`shipperId`).
- 화주사(운영사 전용)와 달리 범위 안이면 센터 직원도 품목을 대신 등록·수정할 수 있다(ASN 대리 등록과 같은 이유, 기본 권한그룹 "센터 운영자"에 품목 권한이 있다).

## 검증

- 빈 DB·개발 사본 적용 후 스키마 차이 없음. 전체 테스트 553개 (입력 규칙 6, 서버 액션 11: 등록·코드/바코드 겹침은 화주사 안에서만·단위 종류/소수·임박 기준 비우기·사용 중지 화주사·수정과 충돌·목록 적용값/거르기/라벨 표시·센터 직원/화주사 범위·삭제/되살리기·단위 사용 검사).
- 브라우저: 임시 품목 등록(가나식품, EA, BOX 24) → 수정 화면, 라벨 PLT 입수량 없음 안내, 목록 적용값·⚠ 확인 후 DB에서 삭제. 빈 고르기에 "선택" 안내가 안 보이던 것을 고쳤다.
