# 0071. 로케이션 명칭·비고, 엑셀 일괄 업로드

- 날짜: 2026-11-16
- 상태: 채택 (사용자 결정: 코드 규칙은 그대로, 엑셀 업로드 추가 + 명칭·비고 칸)
- 관련: 0028 (로케이션 · 일괄 생성), 0050 (엑셀 업로드 공통)

## 배경

- "구역·열·단에 한글을 쓰면 DB에 문제가 생기나?" → **DB는 문제없다** (UTF-8 글자 칸, 글자 종류 검사 조건 없음). 막는 것은 프로그램 규칙(`LOCATION_CODE_PATTERN`: 영문 대문자·숫자·하이픈 1~30자)이다.
- 코드는 현장에서 **바코드·스캐너로 찍는 값**이 될 수 있어 영문·숫자로 둔다: 스캐너는 키보드처럼 입력하므로 한글 입력 상태에서 깨지고, 1차원 바코드(Code128)는 한글을 담지 못하며, 비슷해 보이는 다른 글자가 섞이기 쉽다.
- 대신 사람이 읽기 좋은 이름은 **명칭** 칸(한글 가능)으로 따로 둔다.

## 정한 것

### 명칭·비고

- `tb_location.location_nm` VARCHAR(100) **필수**, `remark` VARCHAR(1000) 선택 (마이그레이션 `20261116160000_location_name`, 기존 줄은 명칭 = 코드).
- 명칭을 비우면 코드와 같게 저장 (한 칸 추가·수정·엑셀). **일괄 생성은 명칭 = 코드**. 입고대기 기본 로케이션도 명칭 = `DEFAULT`.
- 목록: 명칭(코드와 같으면 흐리게)·비고 컬럼, 검색어가 코드·명칭을 함께 찾는다.
- 줄을 누르면 **명칭·비고 수정** 팝업 (코드는 바꿀 수 없음, 버전으로 동시 수정 막기, 권한 `master.locations.update`).

### 엑셀 일괄 업로드

[일괄 생성]의 범위로 만들기 어려운 창고용. 로케이션 목록 머리글 [엑셀 업로드] (권한 `master.locations.create`).

| 칸 | 필수 | 규칙 |
| --- | --- | --- |
| 센터코드 | ✔ | 볼 수 있는 센터 (대소문자 구분 없음) |
| 창고코드 | ✔ | 그 센터의 보관 창고, 사용 중 (입고대기 창고 불가) |
| 로케이션코드 | ✔ | 영문·숫자·하이픈 1~30자 (소문자 → 대문자) |
| 명칭 | | 100자 이하, 비우면 코드 |
| 구역 / 열 / 단 | | 영문 1~3자 / 숫자 1~3자리 / 숫자 1~3자리 |
| 비고 | | 1000자 이하 |

- 미리보기(저장 안 함) → 오류가 하나라도 있으면 전체 거부, 없으면 한 번에 등록 (ASN 업로드와 같은 흐름, 최대 1,000줄).
- 파일 안에서 같은 창고·같은 코드가 두 번이면 오류. **이미 있는 로케이션은 건너뛴다** (일괄 생성과 같이, 다시 올려도 안전).
- 함수: `src/lib/locations/location-upload-template.ts`(양식), `location-upload.ts`(검증·등록).

## 하지 않은 것

- 코드에 한글 허용 (위 이유). 엑셀로 기존 로케이션의 명칭·비고 고치기(지금은 건너뜀).

> **이후 변경 (0075)**: 구역은 별도 표 `tb_zone`, 명칭(`location_nm`)은 설명(`description`)으로 바뀌었고, 일괄 생성은 구역 하나 + 코드 패턴(`{ZONE}-{ROW}-{LEVEL}`, 최대 5,000개) 방식이 되었다. 코드 중복 금지는 창고 단위 그대로다.
