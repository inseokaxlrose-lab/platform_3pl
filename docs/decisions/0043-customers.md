# 0043. 화주사 거래처 — 배송지 법정동코드와 배송권역

- 날짜: 2026-11-15
- 상태: 채택 (운영사 화면)
- 관련: 0003 (위치 계층: 화주사 ─ 거래처), 0025 (코드 3층), 0033 (배송권역), 0035 (화주사 — 담당자), 0038 (공통 칸), 0039 (멀티테넌트), 0041 (품목 — 같은 범위 방식)
- 코드: `src/lib/customers/`, `src/app/admin/master/customers/`

## 결정 (사용자 결정: 모두 추천안, 2026-11-15)

- **운영사 화면만**: 거래처는 출고·배송요청에서 쓰이는데 출고는 MVP 이후라, 화주 포털 화면은 출고 작업 때 품목처럼 같은 부품으로 붙인다.
- **칸**: 기본(코드·명·사업자번호·대표자·대표 전화·이메일·비고) + 배송지(주소·받는 사람·연락처·배송 메모) + 담당자 표(운영사·화주사와 같은 모양, 최대 5명, 대표 1명, `CONTACT_ROLE`).
- **법정동코드 저장**: 주소 검색 결과의 법정동코드 10자리(`region_cd`, 화면 미노출)를 자동 저장한다. 주소를 직접 고치면 비운다(검색 결과와 어긋나지 않게). 목록에 "이 거래처가 드는 배송권역"을 바로 보여 주고, 출고 때 권역을 자동으로 고르는 데 쓴다.

## 구조

- `tb_customer`: 운영사·화주사·시스템 코드(`CU00000001`)·거래처코드(같은 화주사 안에서 고유, 영문·숫자·`.`·`-`·`_` 2~30자 대문자, 비우면 시스템 코드)·명·사업자번호·대표자·전화·이메일·배송지(우편번호·주소·상세·법정동코드·받는 사람·연락처·배송 메모)·비고 + 공통 칸. 검사 조건: 번호는 숫자만, 법정동코드 10자리. 화주사는 등록 후 바꿀 수 없다.
- `tb_customer_contact`: 담당자 (거래처의 이력으로 봄, 공통코드 사용 수 `countCodeUsage`에 등록).
- 외부 코드 `CUSTOMER`. 메뉴 권한에 엑셀(`master.customers.export`)을 더해 다른 기준정보와 맞췄다.

## 배송권역 맞추기

- 배송권역의 담당 지역은 법정동코드 앞 2자리(시·도) 또는 5자리(시·군·구)다(0033). 거래처의 법정동코드 앞 2·5자리와 같은 지역을 가진 **사용 중·지우지 않은 권역** 중, **그 화주사가 이용하는 센터의 권역**만 `센터명: 권역명`으로 보여 준다. 여러 센터를 이용하는 화주사는 센터마다 하나씩.
- 목록 한 페이지의 거래처를 모아 한 번에 조회한다.

## 데이터 범위

- 품목과 같다: 운영사 관리자 = 운영사 전체, 센터 직원 = 소속 센터를 이용하는 화주사의 거래처(대신 등록·수정 가능), 화주사 사용자 = 자기 화주사.

## 검증

- 빈 DB·개발 사본 적용 후 스키마 차이 없음. 전체 테스트 581개 (거래처 8: 등록·번호 숫자만·법정동코드·담당자·외부 코드, 코드 겹침은 화주사 안에서만·없는 담당 업무 거부, 수정·충돌, 배송권역 맞추기 — 센터별·2/5자리·맞지 않는 권역 제외·사용 중지 권역 제외, 센터 직원 범위, 삭제/되살리기, 엑셀 권한. 주소 입력 부품의 법정동코드 전달 테스트).
- 브라우저: 임시 거래처 등록(가나식품) → 목록 확인 후 DB에서 삭제. 카카오 주소 검색 창(iframe)은 자동 조작이 불안정해 주소 검색·권역 표시는 테스트로 확인.
