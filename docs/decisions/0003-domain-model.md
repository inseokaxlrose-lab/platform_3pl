# 0003. 도메인 모델 (데이터 구조의 뼈대)

- 날짜: 2026-11-13
- 상태: 채택 (세부 컬럼은 각 마일스톤에서 확정)

## 배경

- 센터·창고가 여러 곳이고, 센터마다 입고·출고가 동시에 일어난다
- 화주사마다 로트번호·유통기한 사용 여부가 다르다
- 단위가 EA, KG처럼 다양하고 BOX / CARTON / PLT로 환산해야 한다
- 권한은 권한그룹 + 사용자별, 메뉴 + 버튼 단위로 관리해야 한다

## 결정 1. 위치 계층

```
운영사 ─┬─ 센터 ─┬─ 창고 ── 로케이션
        │        ├─ 입고대기 창고 (센터마다 1개, 자동 생성)
        │        └─ 배송권역
        └─ 화주사 ─┬─ 품목 ── 품목 단위(환산단위)
                   ├─ 거래처
                   └─ 이용 센터 (화주사 ↔ 센터 연결)
```

- **창고 유형**을 둔다: `일반`, `입고대기` (MVP 이후 `출고대기` 등 추가 가능)
- 입고대기 창고에도 로케이션 1개(기본 로케이션)를 자동으로 만든다 → 재고는 항상 "로케이션"에 존재한다는 규칙을 예외 없이 지킬 수 있다
- 한 화주사가 여러 센터를 이용할 수 있다 → 화주사-센터 연결 정보를 따로 둔다

## 결정 2. 로트번호 · 유통기한은 "옵션"

- 화주사에 기본값을 둔다: `로트 사용`, `유통기한 사용`
- 품목에서 화주사 기본값을 **그대로 쓰거나 개별 지정**한다 (상속 방식)
- 사용하는 품목은 검수 시 해당 값 입력이 **필수**, 사용하지 않는 품목은 입력란 자체를 숨긴다
- 재고에서는 사용하지 않는 경우 빈 값(null)으로 저장한다
- **유통기한 임박 기준(일수)**은 품목별로 설정한다 (예: 30일 → 유통기한까지 30일 이하 남으면 "임박")
  - 유통기한을 사용하는 품목만 설정 가능
  - 임박 여부는 저장하지 않고 조회할 때 계산한다 (날짜가 지나면 자동으로 바뀌어야 하므로)

## 결정 3. 단위와 환산

- 품목마다 **기본단위** 1개 (EA, KG, L, M 등 단위 코드 목록에서 선택)
- 품목마다 **환산단위** 여러 개: BOX, CARTON, PLT + 각각의 입수량(기본단위 기준)
  - 예: 생수 / 기본단위 EA / BOX = 24 EA / PLT = 1,440 EA
- **재고와 이력은 항상 기본단위로 저장**한다. 화면에서만 환산해서 보여준다
- KG처럼 소수가 필요한 단위가 있으므로 수량은 정수가 아닌 **Decimal**로 저장한다
- 환산 계산은 한 곳(공통 유틸 함수)에서만 하고 테스트로 보호한다

## 결정 4. 재고의 "주소"

재고 1줄은 아래 조합으로 구분한다.

```
센터 + 창고 + 로케이션 + 화주사 + 품목 + 로트번호 + 유통기한 → 수량
```

- 수량은 직접 고치지 않고 **재고 이력(거래 기록)**을 통해서만 바꾼다
  - 이력 유형 예: 입고확정, 적치(이동), 조정, (이후) 출고, 수송
- 수량 변경 + 이력 기록은 하나의 DB 트랜잭션으로 묶는다
- 이력에는 원본 문서(ASN 번호, 조정 번호 등)를 연결해 "왜 바뀌었는지" 추적한다

## 결정 5. 입고 문서 구조 (부분 입고 확정 지원)

ASN 하나에 대해 검수와 입고 확정이 **여러 번 나눠서** 일어날 수 있다.

```
ASN (헤더 + 라인)
 └─ 입고확정 1차 (확정 문서 + 라인) ──→ 입고대기 창고에 재고 생성
 │    └─ 적치 (확정된 재고 중 일부 또는 전부)
 └─ 입고확정 2차 ...
```

비유: 택배 10박스 주문이 3박스, 7박스로 나눠 도착하면, 도착할 때마다 따로 "수령 확인서"를 쓰는 것과 같다.

- **입고 유형** 필드를 처음부터 둔다: `화주사입고` (MVP), `수송입고` (MVP 이후)
- **등록 경로**를 기록한다: `화주 포털` / `센터 대리 등록` / `엑셀 업로드` + 등록자
- 검수 결과는 라인별로: 검수 수량, 불량 수량, 로트번호, 유통기한
- 입고 확정은 검수된 수량 중 **원하는 만큼만** 확정할 수 있고, 확정할 때마다 입고확정 문서가 생긴다
- 수량 계산 규칙 (ASN 라인 기준)
  - 잔량 = max(예정 수량 − 누적 확정 수량, 0)
  - 초과 수량 = max(누적 확정 수량 − 예정 수량, 0)
  - 적치 가능 수량 = 누적 확정 수량 − 누적 적치 수량
  - 잔량·초과 수량은 저장하지 않고 계산해서 ASN 조회 화면에 표시한다
- **초과 입고 허용**: 예정보다 많이 도착해도 받을 수 있고, 초과분까지 입고 확정한다
  - 화면에서 초과 수량을 눈에 띄게 표시하고, 확정 시 "초과 입고" 확인 메시지를 띄운다
- **잔량 마감**: 더 이상 도착하지 않을 잔량을 마감 처리한다
  - ASN 단위로 마감하며, 마감 사유와 마감자·일시를 기록한다 (권한 필요)
  - 마감된 ASN은 추가 검수·확정 불가. 이미 확정된 재고의 적치는 계속 가능
  - 마감된 잔량은 "마감 수량"으로 남겨 나중에 보고서에서 확인할 수 있게 한다
- **적치는 입고확정으로 생성된 재고만** 대상으로 한다
- 상태는 두 갈래로 따로 관리한다
  - 입고 상태: `예정 → 검수중 → 부분확정 → 확정완료` 또는 `→ 마감`
    - 확정완료: 모든 라인의 누적 확정 수량 ≥ 예정 수량
    - 마감: 잔량이 남은 상태에서 마감 처리
  - 적치 상태: `적치대기 → 부분적치 → 적치완료`

### 엑셀 업로드 공통 규칙

- 양식(템플릿) 다운로드 → 업로드 → **검증 결과 미리보기**(오류 행·사유 표시) → 등록
- 오류가 하나라도 있으면 해당 파일은 등록하지 않는다 (일부만 들어가는 혼란 방지)
- 엑셀 업로드는 공통 컴포넌트로 만들어 이후 품목·거래처 일괄 등록 등에 재사용한다

## 결정 6. 관리 라벨

- 라벨 단위는 `PLT` / `BOX` 중 선택하는 **옵션**이며 기본값은 `PLT`
  - 화주사에 기본값을 두고, 품목에서 그대로 쓰거나 개별 지정 (로트·유통기한과 같은 상속 방식)
- 라벨 수량 = 검수 수량 ÷ 해당 환산단위 입수량 (올림, 마지막 라벨은 잔량)
  - 예: 검수 3,000 EA, PLT = 1,440 EA → 라벨 3장 (1,440 / 1,440 / 120)
- 라벨은 고유 번호를 갖고 검수 결과에 연결되며, 재발행할 수 있다
- 라벨 단위 재고 추적(라벨 번호를 재고 주소에 포함)은 스캐너 도입 시점에 다시 검토한다

### 코드 형식

- 담을 정보가 많으므로 **2D 코드**를 사용한다: QR 코드 또는 Data Matrix (설정으로 선택)
- 코드 안에 담는 정보: 라벨 번호, 센터, 화주사, 품목 코드, 로트번호, 유통기한, 수량, 단위
- 데이터 형식은 구분자로 이어 붙인 문자열로 하고, 맨 앞에 형식 버전을 둔다 (나중에 항목이 늘어도 스캐너가 구분 가능)
- 코드 이미지는 웹 화면에서 생성한다 (라이브러리는 M5에서 최신 문서 확인 후 결정)

### 인쇄 방식

- **윈도우 프린터 드라이버 방식**: 웹 화면에서 라벨을 그린 뒤 브라우저 인쇄 → 운영체제에 설치된 프린터 드라이버로 출력
  - 장점: 라벨 프린터 브랜드에 상관없이 드라이버만 설치되면 출력 가능, 별도 프로그램 설치 불필요
- 라벨 크기는 라벨 양식(템플릿)으로 관리하고, 인쇄용 CSS로 용지 크기를 맞춘다
- **라벨 양식은 라벨 단위(PLT / BOX)별로 2가지씩** 제공하고, 사용자가 인쇄할 때 선택한다
  - 각 단위마다 기본 양식 1개를 지정해 두고, 마지막으로 고른 양식을 사용자별로 기억한다
  - 크기 초안 (M5 전에 확정)

    | 단위 | 양식 A (기본) | 양식 B |
    |---|---|---|
    | PLT | 100 × 150 mm | A4 1/2 (210 × 148 mm) |
    | BOX | 100 × 100 mm | 100 × 50 mm |

  - 양식은 MVP에서는 코드로 정의하고, 화면에서 양식을 추가·편집하는 기능은 MVP 이후로 미룬다
- 여러 장을 한 번에 인쇄할 수 있어야 한다 (라벨 1장 = 인쇄 1페이지)

## 결정 7. 권한 구조

```
권한그룹 ── 권한(메뉴 + 버튼) 목록
사용자 ── 권한그룹 1개 이상
      └── 사용자별 추가 / 제외 권한
최종 권한 = 그룹 권한 합 + 사용자 추가 − 사용자 제외
```

- 메뉴와 버튼은 코드에 "권한 코드"로 정의한다 (예: `inbound.asn.create`, `inventory.adjust.confirm`)
- 화면: 권한 없는 메뉴·버튼 숨김 / 서버: 같은 권한 코드로 다시 검사
- **데이터 범위**는 권한과 별개로 사용자 소속으로 정한다
  - 운영사 관리자: 전체 / 센터 직원: 소속 센터 / 화주사 사용자: 자기 화주사

## 대안과 버린 이유

- **재고를 품목별 숫자 하나로만 관리**: 위치·로트별 추적이 불가능
- **환산단위별로 재고 저장**: 같은 물건이 BOX와 EA로 따로 쌓여 합계가 틀어짐
- **역할(Role) 고정 방식 권한**: 사용자별 예외와 버튼 단위 권한을 표현할 수 없음
