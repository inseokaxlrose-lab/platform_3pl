# 0023. 화면별 도움말

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0014 (화면 권한), 0015 (서버 액션, `'signed-in'`), 0022 (메뉴 목록)
- 코드: `src/content/help/` (문서), `src/lib/help/` (읽기·거르기·서버 액션), `src/components/help/` (버튼·패널)

## 결정

### 내용은 코드 저장소의 Markdown 파일

- 메뉴 주소와 파일이 1:1: `/admin/system/users` → `src/content/help/admin/system/users.md`. 따로 연결할 필요가 없다.
- 하위 화면(등록·수정)은 그 메뉴의 도움말을 쓴다 (사이드바와 같은 "가장 구체적인 메뉴 찾기").
- 맨 위 `title`·`summary`(직접 읽는 작은 함수, 패키지 없음) + `##` 단락들.
- 화면을 고칠 때 도움말도 같은 커밋에서 고친다.

### 권한에 맞는 단락만

- 단락 바로 위에 `<!-- 권한: 메뉴.동작 -->`를 두면 그 권한이 있는 사람에게만 보인다. 주석이라 문서를 그냥 읽을 때도 방해가 되지 않는다.
- **서버에서 거른다.** 권한 없는 사람에게는 그 단락이 아예 전달되지 않는다.
- 서버 액션 `loadHelpAction`: 메뉴마다 권한이 달라서 `'signed-in'`으로 받고, 안에서 그 메뉴의 조회 권한을 다시 검사한다. 메뉴 목록에 있는 주소만 파일 경로로 바꾼다 (다른 파일을 읽을 수 없음).

### 화면

- `PageHeader` 오른쪽에 [? 도움말] 버튼이 자동으로 붙는다. 그 메뉴의 도움말 파일이 있을 때만 나온다.
- 오른쪽 옆 패널(Sheet)로 열어, 화면을 보면서 읽을 수 있다. 패널을 처음 열 때 불러온다.
- Markdown 표시: `react-markdown` + `remark-gfm`(표). HTML을 직접 끼워 넣지 않는 방식(기본 설정에서 HTML 태그는 그리지 않음)이라 안전하다. 모양은 바깥 상자의 자손 선택자로 디자인 토큰만 써서 준다.
- 서버 액션은 레이아웃이 넘겨준다 (사이드바 즐겨찾기와 같은 방식) → 부품 테스트에서 가짜 함수로 바꿔 끼울 수 있다.

### 배포

- 실행 중에 파일로 읽으므로 `next.config.ts`의 `outputFileTracingIncludes`에 `src/content/help/**`를 넣었다.

### 도움말 필수 (테스트로 강제)

- `src/content/help/help-files.test.ts`:
  - 완성된 메뉴(`ready: true`, 홈 제외)에 도움말 파일이 없으면 실패한다. 만들어야 할 파일 경로를 알려 준다.
  - 메뉴 목록에 없는 주소의 파일, 제목 없는 문서, 없는 권한 코드·다른 메뉴의 권한 표시가 있으면 실패한다.
- 일부러 파일을 빼고 다른 메뉴 권한을 넣어 보아 두 검사가 실제로 실패하는 것을 확인했다.

## 대안과 버린 이유

- **MDX(문서 안에 React 부품)**: 강력하지만 문서 작성이 개발자 전용이 되고 설정이 늘어난다. 지금은 글·표·목록이면 충분하다.
- **DB에 저장하고 관리 화면에서 편집**: 운영 중 수정은 편하지만, 화면 변경과 도움말이 따로 놀게 된다. 필요해지면 다시 검토.
- **TS 객체로 작성**: 타입 검사는 좋지만 글 쓰기가 불편하다.

## 확인

- 테스트: 문서 읽기 4개, 서버 액션 3개, 버튼·패널 4개, 도움말 파일 검사 4개.
- 브라우저:
  - admin: 사용자 도움말 단락 5개, 권한그룹 도움말 단락 4개가 모두 보였다. 표·목록·굵은 글씨가 다크 모드에서도 토큰 색으로 보였다.
  - 사용자·권한그룹 조회만 가진 확인용 계정: "목록 보기" 단락만 보였다. 사용자 수정(하위 화면)에서도 같은 도움말이 열렸다. 확인 후 계정·그룹은 지웠다.
