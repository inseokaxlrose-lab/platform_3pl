# 0075. 구역·로케이션 정보 확장 (구역 표, 로케이션 칸, 코드 패턴 일괄 생성, 사용 가능 판단)

- 날짜: 2026-11-17
- 상태: 채택 (사용자 결정 — 아래 "결정")
- 관련: 0028 (로케이션), 0071 (명칭·엑셀 업로드), 0073 (상속 칸), 0074 (창고), 0038 (논리 삭제)

## 배경

구역은 로케이션의 글자 칸(`zone_cd`)이었고, 로케이션은 코드·명칭·구역·열·단·상태뿐이었다.
사용자가 구역·로케이션 컬럼 정의(1차·2차)를 주었다. 로케이션은 센터당 수천~수십만 건이라 조회·일괄 생성을 대량 전제로 설계한다.

## 결정

| 항목 | 정한 것 |
| --- | --- |
| 로케이션 코드 중복 범위 | **창고 안 고유를 유지** (스펙은 센터 안 고유였으나, 기존 데이터에서 이천센터 창고 3곳이 같은 코드를 쓰고 있어 사용자가 유지를 골랐다). 기본 로케이션 `DEFAULT`도 그대로 |
| 명칭 → 설명 | `location_nm` → `description`(200자). 코드와 같던 값은 비움 (코드와 다른 30건만 남음) |
| 한 칸 추가·수정 | **팝업 유지 + 확장** (사용자 결정): 기본 정보 / 위치 구성 / 용량 / 운영 속성 |
| 용량 단위 | **저장은 cm·kg, 화면에서 운영사 단위로 변환** (사용자 결정, `src/lib/units/dimension.ts`) |
| 구역 | 별도 표 `tb_zone`. 창고 수정 화면의 "구역" 표(EditableSubTable)에서 관리, 창고 저장과 같은 트랜잭션. 구역코드는 저장 후 불변 |
| 공통코드 | 분류용이라 운영사 공통코드: `ZONE_TYPE`·`LOC_TYPE`(1차), `LOCK_REASON`·`ABC_CLASS`(2차) |
| 열 정렬 칸 `row_sort` | 만들지 않음 — 일괄 생성은 0을 채워 글자 순서 = 숫자 순서, 정렬은 로케이션 코드 순 |

### 보고 요청 항목에 대한 결정

- **코드 검색 인덱스**: `location_cd`를 `COLLATE "C"`(글자 그대로 비교)로 바꾸고 `(center_id, location_cd)` 인덱스 하나로 앞부분 검색(`LIKE 'A-01%'` → 범위로 바뀜)과 범위 검색을 처리한다. 기본 정렬(en_US)은 하이픈을 무시해 범위 검색이 틀어질 수 있었다.
- **일괄 생성 트랜잭션**: 최대 5,000건(`src/config/locations.ts`)이라 **한 트랜잭션 + createMany**. 빠르고, 실패하면 전부 취소된다. 이미 있는 코드는 건너뛴다(`skipDuplicates`).
- **단위(lb·inch)**: 위 표 — DB는 cm·kg 하나라 검사·계산 규칙이 하나로 유지된다.
- **성능**: 2만 건 임시 DB에서 목록(정렬·50건·건수) 1페이지 24ms, 300페이지 81ms, 앞부분·범위 검색 5~6ms (실행 계획: 인덱스 사용 0.3~0.5ms).

### 코드 패턴 일괄 생성

- 입력: 센터·창고·**구역(필수)**, 열·단(·연) 범위와 자릿수, 패턴(`{ZONE}` `{ROW}` `{BAY}` `{LEVEL}` `{CELL}`), 공통 속성(유형·용량·운영 속성·혼적).
- 기본 패턴 `{ZONE}-{ROW}-{LEVEL}`, 창고 구분자(`loc_cd_separator`)가 없음이면 `{ZONE}{ROW}{LEVEL}`. 로케이션 코드에 쓸 수 있는 구분자는 하이픈뿐이라 창고 구분자도 하이픈/없음만.
- 범위가 둘 이상인 칸은 패턴에 그 토큰이 있어야 한다 (코드 겹침 방지). 미리보기: 만들 개수·처음·마지막 5개·건너뛸 개수. 결과: 생성·건너뜀 + [생성된 로케이션 보기].
- 한 칸 추가는 구역·열·단을 넣으면 같은 패턴으로 코드를 제안한다.

### 업무 규칙

- 센터·창고·구역 일치: 로케이션의 센터 = 창고의 센터, 구역 = 같은 창고의 구역 (서버 검사).
- 시스템 기본 창고에는 추가 불가. 시스템 기본 로케이션(`DEFAULT`, `system_yn`)은 설명·비고만, 사용 중지·삭제 불가.
- 사용 중지: 재고(수량 > 0)가 있으면 거부. 삭제: 재고 기록이 있으면 거부(되살리기 가능).
- 구역: 로케이션이 있으면 지울 수 없음, 재고가 있으면 사용 중지 불가.
- 유형 변경·다화주 혼적 Y→N의 재고 위반 검사는 자리만(`assertStockFitsRules`) — 재고·적치 기능 때 채운다.
- 운영 속성 상속: 적치·피킹·할당 가능은 NULL이면 창고 값 (`resolveLocationOps`·`getEffectiveLocationOps`, 상속 함수 파일 `effective-setting.ts`에 함께). 목록은 실제 적용값을 보여 준다.
- **`isLocationUsable(locationId, 'PUTAWAY' | 'PICK' | 'ALLOCATE')`**: 센터 운영중·창고·구역·로케이션 사용 중·잠기지 않음·실제 운영 속성까지 따진다. 입고 적치가 이미 이 함수를 쓴다 (선택지·저장 검사).

### 공통 부품·기능

- 새 부품 `ZoneSelect`(고른 창고의 구역만), `CodeRangeInput`(시작~끝).
