# 0078. 단위 기준정보 — 시스템 기본 단위 공유 · 유형 6가지 · 물리 단위 환산

- 날짜: 2026-11-17
- 상태: 채택
- 관련: 0034 (단위 코드 관리 — 이 결정으로 표·화면 구조를 **바꿈**), 0042 (품목 환산 함수), 0075 (로케이션 용량 표시 단위), 0039 (운영사별 데이터), 0030 (enum과 공통코드)
- 정의서: `docs/specs/unit.md` (표 이름은 `tb_unit` 유지)
- 코드: `src/lib/units/` (`units.ts` 저장 규칙, `unit-usage.ts` 사용처, `physical.ts` 물리 환산, `dimension.ts`·`display-units.ts` 표시 단위), `src/app/admin/master/units/`, `src/components/inputs/unit-select.tsx`

## 원칙

1. **단위는 두 층**이다.
   - 단위 기준정보: "BOX라는 단위가 있다", "KG는 중량 단위이고 소수 3자리까지 쓴다".
   - 품목별 포장단위 환산: "이 품목은 1 BOX = 24 EA" (`tb_item_unit`, 0041·0042).
   - 단위 기준정보에 고정 환산을 두는 것은 **물리 단위(중량·부피·길이·면적)뿐**이다.
2. **재고는 품목의 기본단위로만 저장**한다. BOX·PLT는 화면·출력·연동에서 바꿔 보여 주는 단위다. 소수 수량은 단위의 소수 자리수로 통제한다.
3. **시스템 기본 단위 + 운영사 추가 단위**. 화주·외부 시스템의 단위 코드(CS·CT·BX)는 단위에 별칭으로 두지 않고 외부코드 매핑(`ExternalCode` UNIT)에서 정한다.

## 결정

### 표 (`tb_unit`, 마이그레이션 `20261117200000_unit_master`)

| 칸 | 내용 |
| --- | --- |
| `operator_id` | **비어 있으면 시스템 기본 단위**. `system_yn = 'Y'` ⇔ 운영사 없음 (검사 조건) |
| `unit_type_cd` | enum `UnitType`: QTY·PACK·WEIGHT·VOLUME·LENGTH·AREA. 프로그램이 유형으로 환산·입력을 다르게 하므로 공통코드가 아닌 enum (0030, 사용자 결정). 등록 후 변경 불가 |
| `base_yn` · `base_unit_id` · `base_factor` DECIMAL(20,10) | 유형 기준단위(EA·KG·L·M·M2, 시스템 단위 중 유형마다 하나) / 1 이 단위 = 계수 × 기준단위 |
| `unit_nm_en` · `print_nm` · `std_unit_cd` · `description` · `ext_attr` JSONB · `remark` | 영문명 · 출력명 · UN/ECE Rec.20 표준코드 · 설명 · 확장속성(환산계수 변경 기록) · 비고 |

- 이름: 표·칸 이름은 `tb_unit`·`unit_cd`·`unit_nm`으로 유지하고(사용자 결정), 정의서도 맞춰 고쳤다. 원래 있던 칸(`decimal_cnt`·`system_yn`·`sort_seq`)도 그대로다.
- **DB 검사 조건**
  - 포장 단위는 환산계수·기준단위를 두지 않는다.
  - 수량 단위는 EA 외에 계수가 없다.
  - 물리 단위(기준단위 아님)는 기준단위·계수가 필수다.
  - 기준단위는 시스템 단위이고 계수 1이다.
  - 소수 0~6, 계수 > 0.
- **코드 중복**
  - 시스템 단위끼리: 부분 고유 `WHERE operator_id IS NULL AND del_yn='N'`.
  - 같은 운영사 단위끼리: 기존 부분 고유.
  - 시스템 코드와 같은 운영사 코드는 저장 때 검사한다.
  - 유형별 기준단위 하나: `WHERE base_yn='Y' AND operator_id IS NULL`.
- **외부 코드**: 고유 조건을 `(운영사, 시스템, 대상, 대상 키)`로 바꿨다. 공유 시스템 단위도 운영사마다 따로 매핑한다.

### 시스템 기본 단위 20개 (마이그레이션 시드 — 이후 추가·수정도 마이그레이션으로만)

| 유형 | 단위 (소수 · 계수 · 표준코드) |
| --- | --- |
| 수량 | **EA**(0·기준·EA), SET(0·SET), PAIR(0·PR) |
| 포장 | BOX(XBX), PACK(XPK), BAG(XBG), BDL(XBE), PLT(XPX) |
| 중량 | **KG**(3·기준·KGM), G(0·0.001·GRM), TON(3·1000·TNE), LB(3·0.45359237·LBR) |
| 부피 | **L**(3·기준·LTR), ML(0·0.001·MLT), CBM(4·1000·MTQ) |
| 길이 | **M**(3·기준·MTR), CM(1·0.01·CMT), MM(0·0.001·MMT), INCH(2·0.0254·INH) |
| 면적 | **M2**(2·기준·MTK) |

- 표준코드 확인 결과
  - EA는 EA와 C62 둘 다 유효해서 EA를 썼다.
  - 정의서 초안의 BX·PK·BG는 현행 목록에 없다. 대신 Rec.21 포장 코드에 X를 붙인 **XBX·XPK·XBG**를 쓴다.
  - BDL = XBE, PLT = XPX.
- **기존 운영사 복사본 옮기기**
  - 같은 코드의 시스템 단위로 품목 기본단위·환산단위·외부 코드 참조를 옮기고 복사본을 지웠다.
  - **CARTON**은 목록에 없어서 각 운영사의 추가 단위(PACK)로 남겼다(사용자 결정). 표준코드는 확인되지 않아 비웠다.
  - 새 운영사에는 단위를 복사하지 않는다(`provisionUnits` 제거).

### 운영사 분리 (prisma.ts)

- `SHARED_SYSTEM_MODELS = {Unit}`
  - 서버 액션 안에서 **읽을 때**는 "시스템 + 지금 운영사"를 본다. 고유 조건을 바깥에 두고 `AND`로 더한다.
  - **고치거나 지울 때**는 지금 운영사의 줄만 다룬다. 시스템 단위는 운영사가 실수로도 고칠 수 없다.
- 화면 조회 함수는 `sharedOperatorFilter(scope)`를 쓴다.
- 테스트 DB 비우기(`resetDatabase`)는 시스템 단위를 읽어 두었다가 같은 번호로 되살린다. 마이그레이션이 유일한 출처다.

### 저장 규칙 (`units.ts`, `unit-usage.ts`)

- 시스템 단위: 수정·삭제를 거부한다(FORBIDDEN). ~~사용 중지도 거부, 목록에서 고를 수 없음~~ → **0079: 운영사별로 사용 중지할 수 있다**(EA·BOX·PLT·표시 단위 제외).
  - 플랫폼 관리자의 시스템 단위 수정 화면은 두지 않는다. 시스템 단위는 마이그레이션으로만 고친다.
- 코드·유형은 등록 후 변경할 수 없다. 기준단위는 유형에서 자동으로 정해진다.
- **사용처 공통 함수** `findUnitUsage`
  - 검사 대상: 품목 기본단위·환산단위, 운영사 중량·길이 단위, ASN·검수 입력 단위.
  - 새 업무 표(주문·출고)는 `UNIT_USAGE_CHECKS`에 한 줄 더한다.
  - 삭제는 쓰는 곳이 없을 때만 할 수 있다. 사용 중지·환산계수 변경은 쓰는 곳을 알린다(notice).
- **소수 자리수 축소**: 이 단위가 기본단위인 품목의 수량(재고·재고 이력·ASN·검수·실사)에 더 많은 소수 자리가 있으면 막는다(`findDecimalOverflow`).
- **환산계수 변경 기록**: `ext_attr.baseFactorHistory`에 언제·누가·이전·이후를 쌓는다. 편집 화면에 보인다.

### 함수

| 함수 | 하는 일 |
| --- | --- |
| `convertPhysical(qty, from, to, decimals=10)` | 같은 유형 물리 단위끼리. **분수(BigInt 분자/분모)**로 계산하고 마지막에 한 번 반올림한다(계수 10자리라 0042의 6자리 고정 소수점보다 넓게). 수량·포장 단위나 다른 유형이면 오류("품목 환산을 써야 합니다") |
| `roundQty(qty, unit)` · `validateQty(qty, unit)` | 단위 소수 자리수로 반올림 / 넘으면 오류 문구 |
| `convertItemQty` | 품목 포장단위 환산 — 자리만 정의(0042 `toBaseQty`·`splitBaseQty`). 서버 조회 함수는 출고 작업 때 |

- 정의서의 `(qty, 단위코드)` 대신 단위 정보(코드·유형·계수·자리수)를 받는 순수 함수로 했다. 화면·서버 어디서나 돌고, DB 조회는 호출 측이 한다.

### 운영사 중량·길이 표시 단위 (마이그레이션 `20261117210000_operator_unit_ref`)

- `weight_unit_cd`·`length_unit_cd` 이름은 유지한다(사용자 결정 반영으로 정의서 수정).
  - 값은 단위 기준정보의 중량·길이 단위 코드다. 시스템 단위 또는 그 운영사의 단위면 된다(예: 근).
  - 고정 목록 검사(KG·LB / CM·INCH)는 **트리거**로 바꿨다. 길이도 VARCHAR(10)으로 늘렸다.
- 로케이션 용량은 cm·kg으로 저장한다.
  - 표시는 `getOperatorDisplayUnits` → `dimension.ts`(convertPhysical)로 한다.
  - 편집 팝업·일괄 생성·**목록의 최대 중량**까지 운영사 단위로 보인다.
  - 센터·창고 면적은 ㎡ 고정이다(운영사에 면적 단위 없음, 사용자 결정).
- 공통코드·상수 `WEIGHT_UNIT`·`LENGTH_UNIT`은 지웠다.

## 버린 안 · 남은 일

- **운영사별 복사본 유지**: 테넌트 예외가 없지만, 시스템 단위를 고칠 때 모든 운영사 복사본을 맞춰야 한다. 정의서의 "모든 운영사가 같은 코드"와도 어긋난다.
- **유형을 공통코드로**: 값에 따라 동작이 바뀌어 0030 규칙에 맞지 않는다.
- **2차**
  - 단위 편집 화면의 "외부 코드" 섹션: 지금 외부 코드 표에는 **화주 구분이 없다**(시스템별 하나). 화주별 매핑은 표 구조를 바꾸는 별도 작업이다.
  - 운영사 설정 화면의 중량·길이 단위 고르기(운영사 정보 2차 칸).
  - `convertItemQty` 서버 함수.
