# 0036. 공통 페이지 틀 (AppPage) — 목록·편집 화면 바깥 틀 통일

- 날짜: 2026-11-15
- 상태: 채택 (0031 "제한 폭 가운데 정렬 + 아래 저장 막대"를 대체)
- 관련: 0031 (입력 화면 틀), 0032 (목록 틀), 0023 (도움말)
- 가이드: `docs/ui-guidelines.md` "페이지 틀" · 코드: `src/components/app-page/`

## 배경

목록(MasterListPage)과 편집(MasterFormPage) 화면이 서로 다른 프로그램처럼 보였다 (사용자 지적). 2560px 창에서 잰 값: 제목 왼쪽 목록 280px / 편집 896px(가운데 정렬), 헤더 폭 2256 / 1024px, 주요 버튼 헤더 / 본문 아래 막대, 하위 표 [추가] 표 아래 / 목록 툴바 위.

## 결정 (사용자 결정: 추천안)

- 간격 토큰: 좌우·헤더-본문 24px(page), 카드·섹션 사이 24px(section, 편집 섹션은 32→24), 카드 안쪽 16px(card), 목차 200px, 편집 본문 최대 1040px.
- `AppPage`: 헤더 전체 폭·고정(상단 바 아래)·스크롤 그림자, 본문 `full`/`form`(목차 + 본문 왼쪽 정렬). 목록·편집 틀이 모두 이걸 쓴다.
- `PageHeader`: 제목·설명·`meta`, 버튼 순서 [도움말] → 보조 → 주. [도움말]은 지금처럼 메뉴 주소로 자동(별도 helpKey 없음).
- 편집 화면 [취소]·[저장]은 헤더로(스크롤해도 보임), 본문 아래 저장 막대 제거. 화면 파일은 `header` 속성만 넘긴다.
- `SectionToolbar`를 목록 그리드 툴바(왼쪽 "총 n건", 선택 건수)와 하위 표(왼쪽 "2 / 5명", 오른쪽 [+ 추가], 표 위)가 함께 쓴다. 아래쪽 페이지 영역은 "41–45 / 45건".
- 폼 정리: 줄바꿈 빈 칸 대신 `Field newRow`, 따로 처리하는 섹션에 "바로 적용" 표시, 화주사 기본 정보 줄 맞춤, 팝업·패널·도구 화면도 `FormGrid`/`Field`로 통일하고 `FormField`·`FormRow` 삭제 (`FormSection`은 도구 화면용 구분선 묶음으로 남김).

## 결과 (브라우저 측정, 2560px)

- 제목: 목록·편집 모두 x 280, y 80 / 본문 시작선 x 280 (전에는 편집 896).
- 편집 화면 1200px 스크롤 뒤에도 [저장]이 y 80에 그대로, 헤더 아래 구분선·그림자.
- 담당자 표 [+ 담당자 추가]가 표 위 오른쪽 끝(표 오른쪽 끝과 같은 x).
- **[도움말]의 x는 화면마다 다르다**: 버튼 순서가 [도움말] → 보조 → 주라서, 뒤에 오는 버튼들의 폭만큼 위치가 달라진다(목록 2245 / 편집 2303). 같은 자리에 고정하려면 [도움말]을 버튼 묶음 밖(예: 맨 오른쪽 끝 또는 제목 옆)으로 옮겨야 한다 — 사용자 확인 필요.
  - → **결정(2026-11-15, 사용자)**: [도움말]을 맨 오른쪽 끝에 고정. 순서는 보조 → 주 → [도움말].
