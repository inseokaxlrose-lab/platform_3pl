# 0010. 인증 라이브러리와 사용자·권한 DB 모델

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0001 (인증: M1에서 확정), 0003 결정 7 (권한 구조)

## 결정

### 인증: Better Auth 1.7

- 0001에서 미뤄둔 결정을 확정. 1.7.22가 Prisma 7·Next.js 16·Vitest 5를 지원함을 확인했다.
- 로그인 처리·세션·비밀번호 암호화를 라이브러리에 맡긴다 (직접 만들면 보안 실수가 생기기 쉬움).
- 대안 Auth.js: 아이디·비밀번호 로그인 지원이 약하고 세션·DB 연동을 더 직접 짜야 한다.

### 로그인: 아이디 + 비밀번호

- 현장 작업자는 회사 이메일이 없는 경우가 많다 → `username` 플러그인 (아이디 3~30자).
- Better Auth는 이메일 칸이 필수라, 이메일이 없는 사용자는 내부용 주소(`아이디@users.local` 형태)를 채운다 (사용자 관리 작업에서 구현).

### 회원가입: 끔, 관리자만 계정 생성

- B2B라 아무나 가입하면 안 된다 → `disableSignUp: true`. 계정은 운영사 관리자가 사용자 관리 화면에서 만든다.

### 사용자 정보 추가

| 칸 | 뜻 |
|---|---|
| `userType` | `OPERATOR`(운영사) / `CENTER`(센터) / `SHIPPER`(화주사). 데이터 범위 기준. 소속 센터·화주사 연결은 "데이터 범위 장치" 작업에서 |
| `isActive` | false면 로그인·사용 불가. 기록 보존을 위해 계정을 지우지 않고 막는다 |

Better Auth 표(user/session/account/verification)는 `npx auth generate`로 만들고, 필드 이름·구조는 바꾸지 않는다.

### 권한 DB 모델

| 표 | 뜻 |
|---|---|
| `permission_group` | 권한그룹 (이름 중복 불가) |
| `permission_group_permission` | 그룹에 들어 있는 권한 코드 |
| `user_permission_group` | 사용자 ↔ 그룹 (여러 개 가능) |
| `user_permission_override` | 사용자별 추가(GRANT)/제외(DENY). 같은 사용자·코드에는 하나만 |

- **권한 코드는 DB 표로 만들지 않는다.** 코드 한 곳에 목록으로 정의하고 DB에는 코드 글자만 저장한다. 메뉴·버튼은 코드와 함께 바뀌므로, 목록이 코드와 DB 두 곳으로 갈라져 어긋나는 것을 막는다. (저장 시 코드 목록에 있는 값인지 검사하는 것은 권한 코드 정의 작업에서)
- 삭제 규칙: 사용자가 남은 그룹은 삭제 불가(Restrict) / 그룹 삭제 시 그룹 권한 코드는 함께 삭제 / 사용자 삭제 시 그룹 소속·개별 예외 함께 삭제.

### DB 테스트

- DB 테스트 시작 전 테스트 DB에 `prisma migrate deploy`를 자동 적용한다 (`vitest.db-global-setup.ts`).
- `_test` 이름 안전장치는 마이그레이션 전에도 검사한다.
- 테스트마다 `resetDatabase()`로 모든 표를 비우고 시작한다.
