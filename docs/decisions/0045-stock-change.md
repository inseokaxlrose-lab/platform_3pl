# 0045. 재고 변경 공통 함수

- 날짜: 2026-11-15
- 상태: 채택 (M4 두 번째 작업 — 동시 처리 안전성 테스트는 다음 작업)
- 관련: 0044 (재고 모델), 0042 (단위 환산), 0041 (품목 관리 옵션), 0039 (멀티테넌트), 0028 (로케이션 쓰인 적 있음), CLAUDE.md "재고는 직접 수정 금지"

## 무엇을 만들었나

`src/lib/stock/stock-change.ts` — 재고 수량을 바꾸는 **유일한 통로** 세 개.

| 함수 | 쓰는 곳 | 이력 |
| --- | --- | --- |
| `receiveStock` | 입고 확정 | RECEIVE 한 줄 (+) |
| `moveStock` | 적치·이동 (같은 센터 안, 같은 품목·로트·유통기한) | MOVE_OUT(−) + MOVE_IN(+) 두 줄, 묶음 번호 = 나감 줄의 이력 키 |
| `adjustStock` | 재고 조정 (±) | ADJUST 한 줄, **사유 필수** |

- 부르는 쪽의 트랜잭션 `tx`를 받는다 → 입고 확정 같은 업무 저장과 재고 변경이 함께 저장되거나 함께 취소된다.
- 운영사 출입증(`createAction`·`runInContext`) 안에서만 동작한다(`requireOperatorId`). 다른 운영사의 로케이션·품목은 "찾을 수 없음".
- 수량은 글자로 받고(`'2.5'`) `convert.ts`의 BigInt 고정 소수점으로 계산한다. 품목 기본단위의 소수 자리를 넘으면 거부(EA 0자리 → 2.5 불가).
- 센터·창고·화주사·운영사는 로케이션·품목에서 채우고, 처리자는 지금 작업자(`currentActor`).

## 순서와 잠금

1. 로케이션·품목을 읽고 규칙 검사
2. 재고 줄 찾기 / 없으면 만들기: 직접 SQL `INSERT … ON CONFLICT DO NOTHING` — 동시에 두 요청이 같은 줄을 만들어도 오류 없이 하나만 생긴다(Prisma `create`는 고유 규칙 위반 시 트랜잭션 전체가 실패)
3. 줄 잠금 `SELECT … FOR UPDATE` — 여러 줄(이동)은 **항상 키 순서로** 잠가 교착을 막는다
4. 수량 계산 → 부족하면 거부 → 수량 저장 + 이력 한 줄

- **부족 판단**: 줄일 때는 `수량 − 할당`까지만 뺄 수 있다. 메시지에 현재·할당·뺄 수 있는 수량·요청을 보여 준다. 출발 재고 줄이 아예 없으면 빈 줄을 만들지 않고 부족.
- **이동 묶음 번호**: 이력은 고칠 수 없으므로(0044 트리거) 나중에 채울 수 없다 → 이력 키 시퀀스에서 `nextval`로 미리 받아 첫 줄의 키와 두 줄의 묶음 번호에 쓴다.

## 결정 (사용자 결정, 2026-11-15)

- **사용 중지된 로케이션·품목 — 늘리기만 막기(추천안)**: 입고·이동 도착·+조정은 거부, 빼기·이동 출발·−조정은 허용. 남은 재고를 정리할 수 있어야 하기 때문. 같은 이유로 "화주사가 이용하지 않는 센터"와 "로트·유통기한 규칙" 검사도 늘릴 때만 한다(줄이기는 이미 있는 재고 주소를 그대로 쓴다).
- **함수 밖 쓰기 차단 — Prisma 확장(추천안)**: `stock-write-guard.ts`의 허가증(`withStockWrite`, AsyncLocalStorage)이 없으면 `prisma.ts`가 재고·재고 이력 표의 등록·수정·삭제(`create`·`createMany(AndReturn)`·`update`·`updateMany(AndReturn)`·`upsert`·`delete`·`deleteMany`)를 DB에 가기 전에 오류로 막는다. 읽기는 자유. 허가증은 재고 변경 함수와 DB 규칙 자체를 확인하는 테스트에서만 쓴다.
  - 막지 못하는 것: 직접 SQL(`$executeRaw`), 다른 표를 통한 안쪽 관계 쓰기(`location.update({ data: { stocks: … } })`). 둘 다 쓰지 않는 규칙으로 지키고, 음수·할당 초과·이력 수정은 DB(0044)가 마지막으로 막는다.

## 그 밖의 규칙

- 로트·유통기한: 품목 설정(비어 있으면 화주사 기본값, `effectiveItemOptions`)에 따라 관리 품목은 필수, 아니면 넣으면 거부. 로트는 앞뒤 공백을 빼고 빈 글자는 null. 유통기한은 `'YYYY-MM-DD'`의 실제 날짜.
- 이동은 같은 센터 안에서만, 같은 로케이션으로는 불가.
- **쓰인 적 있음**: 재고 줄이 있는 로케이션·품목은 지울 수 없다(`findUsedLocationIds`·`findUsedItemIds`). 수량이 0이 돼도 이력이 남으므로 쓰인 것. ASN에 쓰인 품목은 M5에서 더한다.
