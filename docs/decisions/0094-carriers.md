# 0094. 운송사·운송 계약·화주 발송인 (M8 B1)

- 날짜: 2026-11-20
- 상태: 채택
- 관련: 0025·0068·0084 (기준정보 코드 3층·외부코드), 0039 (운영사 기본값 복사), 0038 (지우지 않고 숨김), 기준정보 누락 검토 1-5·1-6·2-5
- 코드: `src/lib/carriers/` (값 목록·송장번호·운송사·운송 계약), `src/config/defaults/carriers.ts`, `src/app/admin/master/carriers/`, `src/app/admin/master/carrier-contracts/`, 화주사 출고 설정
- 마이그레이션: `20261120150000_carriers`, `20261120151000_carrier_ext_code`

## 배경

출고 송장을 뽑으려면 "어느 택배사로, 어느 계약(고객코드·송장번호)으로, 누구 이름으로 보내는가"가 필요한데 기준정보가 없었다.

## 결정 (사용자 결정은 모두 추천안)

### 운송사 `tb_carrier`

- **운영사마다 한 벌**. 새 운영사에는 기본 7곳(CJ대한통운·한진·롯데·우체국·로젠 택배 + 자차·용차)을 `provisionOperator`가 복사하고, 기존 운영사에는 마이그레이션으로 넣었다.
  - 팔레트 종류(0083)처럼 시스템 공용 행으로 두지 않은 이유: 운영사마다 사용자 정의 코드·외부코드·송장 규칙을 따로 가져야 하고, 계약·화주가 키(FK)로 가리켜야 한다.
  - 기본값 복사는 "같은 코드가 없을 때만" — 운영사가 지운 운송사는 되살리지 않는다.
- 우리 코드(필수·불변, 택배사 약칭이 곧 연동 키라 체번하지 않음 — 단위·팔레트와 같음) + 사용자 정의 코드(운영사 안 고유) + 외부코드(외부코드 매핑 대상 `CARRIER` 추가).
- 운송 유형 `PARCEL`·`FREIGHT`·`OWN`·`CHARTER`, 체크디지트 규칙 `NONE`·`MOD7`(끝자리 = 앞자리 % 7) — 상수 + CHECK.
- 송장 자릿수(체크디지트 포함)·배송 조회 주소(`{invoiceNo}` 자리). 기본값의 자릿수·규칙은 흔히 쓰는 값이라 운영사가 계약서대로 고친다.
- 운송 계약·화주 기본 택배사에 쓰였으면 삭제 불가(사용 중지로 안내).

### 운송 계약 `tb_carrier_contract`

- 운송사 × 센터 × 화주(NULL = 센터 공용) + 택배사 고객코드·집하 점소·유효기간·상태·기본 여부.
- **송장 대역은 저장 + 검사만** (사용자 결정): 체크디지트를 뺀 **본번호**로 시작·끝·다음 번호. 본번호 자릿수가 운송사 규칙과 맞아야 하고, 같은 운송사의 다른 계약과 겹치면 거부. 실제 발번(다음 번호 쓰기)은 출고 작업에서 붙인다. 택배 운송사만 대역을 쓴다.
- 기본 계약은 같은 센터·화주 범위에 하나 — 새 기본을 저장하면 나머지를 내린다(DB 고유 조건 대신 코드로: 화주 NULL을 포함한 고유 조건은 표현식 인덱스가 필요해 Prisma 스키마로 관리하기 어렵다).
- 출고 때 찾는 순서 `findContractFor`: 화주×센터 → 센터 공용 (각각 기본 먼저), 오늘이 유효기간 안·사용 중인 계약·운송사만. 없으면 화주 기본 택배사.
- 메뉴: 기준정보 › **운송 계약**(별도 메뉴, 사용자 결정). 센터 직원은 소속 센터 계약만(데이터 범위 `centerId`). 권한 `master.carrier-contracts`(+엑셀), 운송사는 `master.carriers`. 기본 권한그룹: 센터 운영자 = 운송사 조회 + 운송 계약 전체.

### 화주 출고 설정 (`tb_shipper`)

- 발송인명(비우면 화주명)·발송 전화(비우면 대표 전화)·보내는 주소 방식 `CENTER`(기본)·`SHIPPER`·`CUSTOM`(직접 입력, 반품 회수지 겸용 — 사용자 결정)·기본 택배사.
- 직접 입력이 아니면 따로 넣은 주소는 저장하지 않는다. 사용 중지한 운송사는 새로 고를 수 없고, 이미 정해 둔 것은 그대로 저장된다.

## 버린 안

- **운송사를 시스템 공용 행으로**: 운영사별 코드·외부코드·FK가 꼬인다(위).
- **운송 계약을 운송사 수정 화면 안 표로**: 센터·화주 기준으로 찾기 어렵다(사용자 결정).
- **송장 대역 없이 고객코드만**: 대역을 미리 받는 택배 계약을 다룰 수 없다(사용자 결정).

## 남은 일

- 출고 작업에서 송장 발번(다음 번호 증가, 동시성), 택배사 연동(번호 받기·집하 요청), 송장 출력.
- 화주 로고(송장·명세서)는 출력 양식(B6)에서.
