# 0040. 운영사 정의서 반영 — 칸·코드 값·편집 위치

- 날짜: 2026-11-15
- 상태: 채택 (M2.5 4단계)
- 관련: 사용자 정의서 `docs/specs/operator.md`, 반영 결과 `docs/operator-columns.md`, 0024 (운영사 정보), 0030 (공통코드), 0038 (공통 칸), 0039 (멀티테넌트)

## 배경

사용자가 운영사(tb_operator) 컬럼 정의서를 확정했다. 정의서의 진행 방식(차이 보고 → 마이그레이션 초안 확인 → 반영)대로 진행했다.

## 결정 (사용자 결정: 모두 추천안, 2026-11-15)

- **코드 값 위치**: 플랫폼이 정하거나 프로그램이 동작을 바꾸는 값(운영사 유형·상태·사업자 구분·과세·요금제·과금·할당 규칙·중량/길이 단위·온도대)은 **상수** `src/config/operator-codes.ts` + DB 검사 조건. 공통코드는 운영사마다 따로라, 공통코드로 두면 운영사가 자기 요금제·상태 값을 바꿀 수 있게 되기 때문이다(정의서도 "없으면 상수"를 허용). 운영사가 고치는 분류인 담당 업무(`CONTACT_DUTY` → **`CONTACT_ROLE`**)·제공 서비스(`SERVICE_TYPE`)는 운영사 공통코드.
- **운영사코드**: 기존 운영사는 `DEMO`(예시물류)·`NARA`(나라물류), 그 밖은 `OP` + 번호. 등록 화면은 운영사코드를 받고, 관리자 아이디는 `admin.{운영사코드 소문자}`로 맞췄다(3c의 "아이디 뒷자리" 칸은 없앴다).
- **편집 위치**: 플랫폼 편집(`/platform/operators/[id]`)은 [1차] 전체 + 상태 변경 팝업. 운영사 자기 화면(`/admin/master/operator`)은 같은 폼(`src/components/operator/operator-form.tsx`)을 쓰되 운영사코드·유형·상태는 읽기 전용(입력 규칙에도 칸이 없다).
- **하위 표 감사 칸**: 담당자·제공 서비스·취급 온도대에는 두지 않는다. 운영사 저장 때 통째로 다시 만들어 등록자가 늘 "마지막 저장한 사람"이 되므로 의미가 없고, 0038의 "하위 표는 부모 이력" 규칙을 유지했다.
- **이름 변경**: 화면 주소 `/admin/master/company` → `/admin/master/operator`, 권한 코드 `master.company.*` → `master.operator.*` (권한그룹·사용자 예외에 저장된 코드, 사이드바 즐겨찾기 주소도 마이그레이션으로 옮겼다).

## 결과

- 마이그레이션 `_operator_spec`: 칸 46개 추가, TEXT 칸 11개를 정의서 길이로, 하위 표 2개, 검사 조건 13개(코드 모양·값 목록·Y/N·정산 마감일·숫자만 번호·정지/해지 사유 필수), 데이터 변환(운영사코드·계약시작일 = 등록일·CONTACT_ROLE 이름·운영사마다 SERVICE_TYPE·권한 코드). `_operator_menu_href`: 즐겨찾기 주소.
- 플랫폼: 운영사 목록을 정의서 4장대로(센터 수·화주 수는 칸이 아니라 조회할 때 센다), 편집 화면, 상태 변경 팝업(정지·해지 사유 필수, 운영으로 되돌리면 사유 비움), 등록에 운영사코드·유형. 플랫폼 편집 저장은 **대상 운영사의 출입증**(`asOperator`)으로 — 담당 업무를 그 운영사의 공통코드로 검사하고 작업 중인 운영사와 섞이지 않게. 편집 화면은 그 운영사의 공통코드를 불러와 폼에 넣는다(플랫폼 화면 틀에는 운영사 공통코드가 없다).
- 주소 검색 부품에 지번주소 알림(`onJibunAddress`, 선택)을 더해 `addr_jibun`을 자동 저장한다.
- 시드: 빈 DB에서 예시 운영사 담당자의 담당 업무가 코드가 아닌 글자('입고 문의')로 들어가던 문제를 `INBOUND`로 고쳤다.
- 검증: 빈 DB·개발 사본 적용 후 스키마 차이 없음(초안 확인 후 개발 DB 적용), 빈 DB 시드, 전체 테스트 535개(입력 규칙 — 값 목록·법인번호·개인이면 비움·코드·상태 사유, 운영사 자기 화면 — 1차 칸 저장·유형 못 바꿈, 폼 — 코드 읽기 전용·유형 잠금·플랫폼은 키 함께, 플랫폼 — 목록 칸·수정·다른 운영사 코드로는 저장 안 됨·상태 변경·권한). 브라우저: 운영사 자기 화면(코드·유형 잠금, 상태 배지, 개인 → 법인번호 칸 사라짐, [취소]로 되돌림 — 저장하지 않음), 예전 주소 404. 플랫폼 화면은 사용자 세션을 바꾸지 않으려고 별도 세션(curl)으로 편집·목록·등록 화면 확인 후 세션 삭제.
