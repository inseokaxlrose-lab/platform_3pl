## 표 `tb_putaway` (마이그레이션 `20261116130000_putaway`)

- 적치 한 번: 입고확정 라인, ASN, 품목, 출발(입고대기)·도착 로케이션, 로트·유통기한, 수량(기본단위), 재고 이력 묶음 번호, 일시·작업자.
- DB 검사: 수량 > 0, 출발 ≠ 도착.

## 규칙 (`src/lib/inbound/putaways.ts` `registerPutaway`)

- **입고 확정으로 생긴 재고만**: 입고확정 라인을 골라서 하고, 남은 수량(확정 − 적치) 안에서 일부만도 된다(부분 적치, 여러 로케이션으로 나눠서).
- 도착: **같은 센터의 일반 창고 로케이션**만(입고대기 창고·다른 센터 거부). 사용 중지 로케이션은 재고 변경 함수가 막는다.
- 재고 이동은 `moveStock`(나감·들어옴 두 줄 + 묶음 번호, 원본 `PUTAWAY` + ASN 번호), 입고확정 라인·ASN 줄의 적치 수량을 더한다(입고확정 라인은 조건부로 더해 동시에 해도 넘지 않게).
- 적치 상태: 하나라도 적치 → **부분적치**, 입고가 끝났고(확정완료·마감) 확정분을 모두 적치 → **적치완료**. 잔량 마감 때도 다시 계산한다(이미 다 적치했으면 마감과 함께 적치완료).
- 마감된 ASN도 확정된 재고는 적치할 수 있다.
- 전체를 `stockTransaction` 하나로. 권한: 화면 `inbound.putaway.read`, 등록 `inbound.putaway.confirm`.

## 화면

- `/admin/inbound/putaway`: 적치할 ASN 고르기(조건을 고르지 않으면 적치대기·부분적치이면서 확정이 있는 것).
- `/admin/inbound/putaway/[asnId]`: 적치할 재고(입고확정 줄마다 보낼 로케이션 검색 선택 + 수량, 기본 남은 전부) → [적치 등록] / 적치 기록.

## 추천안으로 정한 것 (검토 필요)

- 적치 상태 "적치완료"는 **입고가 끝난 뒤**에만(아직 더 들어올 ASN은 확정분을 다 옮겨도 부분적치).
- 로케이션 추천(빈 곳·같은 품목 위치)은 MVP에서 하지 않는다 — 작업자가 고른다.
- 적치 취소는 없다 — 잘못 옮겼으면 재고 이동·조정으로 바로잡는다.
