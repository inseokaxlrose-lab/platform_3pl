# 0072. 배송 센터 자동 배정 규칙 (배송권역이 겹칠 때)

- 날짜: 2026-11-16
- 상태: **대체됨** → 0076 권역설정 (우편번호별 배정표 하나로 교체, 2026-11-17 표·화면·판단 함수 제거)
- 관련: 0033 (센터별 배송권역 — 다른 센터끼리 겹침 허용), 0043 (거래처)

## 배경

다른 센터끼리 배송권역이 겹치는 것은 허용(0033)인데, 출고·수송 자동 분류 때 "겹친 N개 센터 중 어디로?"를 매번 사람이 정할 수는 없다.

예: **서울센터** = 서울 전체, **경기센터** = 경기 전체 + 서울 강남구. 화주사는 두 센터를 다 이용.
- 주문 1 (서울 강동구) → 서울센터만 해당 → 서울센터
- 주문 2 (서울 강남구) → 두 센터 모두 해당 → ?

거래처에 배송 센터를 지정하는 것만으로는, 거래처에 센터가 비어 있을 때 해결되지 않는다.

## 정한 것: 4단계 규칙 (위에서부터, 먼저 정해지는 단계에서 끝)

| 순서 | 규칙 | 예시 주문 2 (강남구) |
| --- | --- | --- |
| ① | **거래처 지정 배송 센터** (그 화주사 이용 센터, 사용 중일 때) | 지정 없으면 다음 |
| ② | **더 구체적인 지역 우선**: 시·군·구(5자리)로 지정한 권역 > 시·도 전체(2자리) | 경기센터가 강남구를 콕 집어 지정 → **경기센터** |
| ③ | **권역 우선순위 번호** (작을수록 먼저, 1~999, 기본 100) — 같은 수준으로 겹칠 때 | — |
| ④ | 그래도 못 정하면 **배정 대기** (후보 목록과 함께) — 사람이 고른다 (화면은 출고 때) | — |

- 후보는 늘 **그 화주사가 이용하는 센터(사용 중)의 사용 중인 권역**만.
- 주소는 거래처 `regionCode`(법정동 10자리) → 앞 5자리(시·군·구)·2자리(시·도)로 권역과 맞춘다.
- ②가 핵심: 서울 중 강남구만 굳이 따로 넣었다는 것 자체가 "강남구는 우리가 맡는다"는 뜻이라, 거래처에 센터가 없어도 대부분 자동으로 정해진다.

## 겹침은 주문 때가 아니라 설정 때 잡는다

- **배송권역 입력 화면**: 담당 지역을 고르는 대로 "다른 센터와 겹치는 지역"과 어느 쪽이 우선인지 바로 보여 준다 (저장은 막지 않음). 같은 수준·같은 번호면 "배정 대기가 됩니다, 우선순위 번호를 다르게"라고 빨갛게.
- **거래처 목록**의 "배송 센터" 컬럼: 규칙대로 정한 결과 — `서울센터 (지정)` / `경기센터 (자동)` / `배정 대기 (2곳)`(빨강). 출고 기능 전에 미리 확인할 수 있다.
- 데이터 범위 안의 권역끼리만 비교한다 (센터 직원은 소속 센터 권역만 보인다).

## 구현

- DB (`20261116170000_delivery_center_routing`): `tb_customer.delivery_center_id`(FK 센터, 선택), `tb_delivery_zone.priority_no`(1~999, 기본 100).
- 규칙: `src/lib/delivery-zones/routing.ts` (순수: `matchRegion`, `pickDeliveryZone`, `describeOverlaps`), `resolve-delivery-center.ts` (서버: 결과 `CUSTOMER`/`AUTO`/`PENDING`/`NONE` + 후보). 거래처 목록(`customer-list.ts`)도 같은 함수로 계산.
- 거래처 배송 센터는 저장할 때 서버가 "그 화주사의 이용 센터인지" 다시 검사한다.

## 출고 기능 때 할 것

- 주문(배송요청)마다 `resolveDeliveryCenter` 호출 → `PENDING`은 **배정 대기 목록**에서 사람이 고르고, [이 지역은 앞으로 ○○센터] 버튼으로 거래처 지정 또는 권역 우선순위를 함께 고친다.
- 필요하면 화주사별 기본 센터, 재고가 있는 센터 우선 같은 규칙을 ③과 ④ 사이에 더한다.
