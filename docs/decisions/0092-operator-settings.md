# 0092. 운영사 설정 (키-값) (M8 A6)

- 날짜: 2026-11-20
- 상태: 채택
- 관련: 0060 (재고 조회 임박 표시), 0081 (API 키), 0073·0080 (상속 설정 — 칸 방식, 이것과 별개), 기준정보 누락 검토 1-3
- 코드: `src/config/operator-settings.ts` (키·기본값·규칙), `src/lib/settings/operator-settings.ts` (읽기·저장), `src/app/admin/system/settings/`
- 마이그레이션: `20261120130000_operator_setting`

## 배경

정의서 여러 곳에 "설정값으로"라고 적은 값이 코드 상수로 흩어져 있었다. 그중 운영사마다 달라야 하는 값을 둘 곳이 필요했다.

## 결정

- `tb_operator_setting` (운영사, 키, 값 JSONB, 수정자·일시), 기본키 (운영사, 키). 운영사 표(prisma.ts `TENANT_MODELS`).
- 키 목록·기본값·검사 규칙은 코드 상수 `OPERATOR_SETTINGS`(개인 설정 tb_user_pref와 같은 방식). **행이 없으면 기본값**, 기본값으로 저장하면 행을 지운다. 저장된 값이 규칙에 안 맞으면(정의가 바뀐 경우) 기본값을 쓴다.
- 처음 둔 설정 두 가지:
  - **기본 임박 알림 일수**(`expiryAlertDays`): 품목에 임박 기준이 없을 때 재고 조회의 임박 판정에 쓴다. 비우면 이전처럼 만료만.
  - **API 키 최대 유효기간**(`apiKeyMaxDays`): 정하면 키 발급 때 만료일 필수, 오늘(한국 날짜)부터 그 일수 안.
- 화면: 시스템 > **운영 설정**(권한 `system.settings` read·update — 기존 운영사 슈퍼 관리자 그룹에 마이그레이션으로 추가, 새 운영사는 운영사 화면 권한 전체를 받는 슈퍼 관리자 정의대로).
- **상수로 남긴 값**(운영사마다 다를 이유가 없거나 법·성능 기준): API 1회 최대 500건, 요청 로그 본문 90일·로그 365일(모든 운영사를 한 번에 정리), 로케이션 일괄 생성 5,000개, 엑셀 업로드 1,000행, 비밀번호 규칙(0086).

## 버린 안

- **운영사 표에 칸 추가**: 설정이 늘 때마다 마이그레이션이 필요하고 운영사 표가 계속 넓어진다.
- **로그 보관 기간을 운영사 설정으로**: 정리 작업이 운영사별로 나뉘어 복잡해지고, 개인정보 보관 기준은 플랫폼이 지켜야 한다(검토 문서 3-4).
