# 0077. 화면 도움말 읽기 쉽게: 글 꾸미기 + 자동 촬영 화면 사진

- 날짜: 2026-11-17
- 상태: 채택
- 관련: 0023 (화면 도움말)
- 코드: `src/lib/help/remark-help.ts`·`help-images.ts`, `src/components/help/help-content.tsx`·`help-image.tsx`, `e2e/help-shots.spec.ts`

## 배경

도움말은 옆 패널에 작은 회색 글로만 나와, 권역설정처럼 긴 화면은 읽기 답답했다. 사진 위주로 바꾸는 안도 봤다.
- 사진은 패널을 열 때만 불러오고 한 장에 60~100KB라 실행 부담은 작다.
- 문제는 **낡음**이다. 화면이 바뀔 때마다 사진이 실제와 달라지고, 라이트·다크 두 벌이 필요하다.

## 결정

### 1. 글 꾸미기 (모든 도움말)

Markdown 표기만 쓰고, 화면에서 이렇게 그린다.

| 표기 | 화면 |
| --- | --- |
| `[저장]` (본문·제목 속 대괄호 1~30자, 링크·코드 제외) | 버튼 모양 칩 |
| `> [!TIP]` · `> [!NOTE]` · `> [!WARNING]` (GitHub 경고 문법) | 팁·참고·주의 상자 (아이콘 + success·info·warning 색 띠) |
| `1. 2. 3.` | 동그라미 번호 단계 |
| `## 단락` | 접고 펼 수 있음 (처음엔 펼침). 단락이 3개 이상이면 맨 위에 목차 칩 |

- remark 플러그인 2개(`remarkHelpCallout`, `remarkHelpButtons`)가 Markdown 나무를 바꾸고, 그리기는 `help-content.tsx`가 맡는다. HTML을 직접 끼워 넣지 않는 방식은 그대로다.
- 권한별 단락 거르기(0023)는 그대로다.
- 패널 폭은 576px(`sm:max-w-xl`)다.
  - 기본 Sheet 폭(`data-[side=right]:sm:max-w-sm`)이 더 구체적이라, 같은 조건(`data-[side=right]:`)으로 덮는다.

### 2. 화면 사진 (복잡한 화면만)

- 문서 표기: `![설명](/help/{메뉴 주소}/{이름}.png)`
  - 파일: `public/help/{메뉴 주소}/{이름}.png`(라이트)와 `{이름}.dark.png`(다크)
  - 화면은 테마에 맞는 한 장만 보여 준다(`dark:hidden`/`hidden dark:block`). `loading="lazy"`이고, 누르면 크게 보기다.
  - `/help/` 아래 `.png`만 그린다. 바깥 주소 사진은 설명 글자만 나온다(외부 추적·깨진 링크 방지).
- 사진 아래에 `① … · ② … · ③ …` 설명을 둔다. 번호는 사진 속 동그라미 번호와 같다.
- **촬영은 손으로 하지 않는다.** `npm run e2e:prepare` 뒤 `npm run help:shots`를 돌린다.
  - e2e 전용 서버·DB(포트 3100)로 화면을 연다.
  - 대상 둘레에 테마 색 테두리와 동그라미 번호를 얹는다.
  - 라이트·다크(`emulateMedia`) 두 장을 찍는다. 본문만, 첫 화면 높이까지다.
  - 평소 `npm run e2e`에서는 빠진다(`playwright.config.ts`의 `testIgnore`, `HELP_SHOTS`).
  - 새 사진은 `SHOTS` 목록에 한 줄을 더한다: 주소, 준비 동작, 번호 대상.
- **화면을 고쳐 사진 속 모습이 바뀌면** 같은 작업에서 `npm run help:shots`를 다시 돌려 사진도 커밋한다.
- 첫 적용은 3곳이다(사진 6장, 456KB): 권역설정 배정 탭, 센터 등록, ASN 등록(운영사).

### 3. 검사

`help-files.test.ts`가 문서 속 사진마다 다음을 검사한다.
- `/help/` 아래 `.png`인지
- **자기 메뉴 폴더**인지
- 라이트·다크 두 파일이 실제로 있는지

빠지면 `npm run help:shots` 안내와 함께 실패한다.

## 대안과 버린 이유

- **사진 위주(모든 화면)**: 가장 직관적이지만, 화면이 바뀔 때마다 28개 화면 × 2벌을 다시 맞춰야 한다. 검색·복사도 안 된다.
- **손으로 캡처**: 데이터·창 크기·테마가 매번 달라 모양이 들쭉날쭉하다. 다시 찍기도 번거롭다.
- **WebP·next/image 변환**: PNG 한 장이 60~100KB라 아직 필요 없다. 늘어나면 그때 바꾼다.
- **다이어그램 라이브러리(mermaid 등)**: 수백 KB 라이브러리가 필요하다. 지금 도움말은 순서 설명이 대부분이라 번호 단계로 충분하다.
