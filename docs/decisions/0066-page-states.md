# 0066. 화면 상태: 불러오는 중 · 오류 · 찾을 수 없음

- 날짜: 2026-11-16
- 상태: 채택 — **추천안으로 진행, 사용자 검토 필요**
- 관련: ROADMAP M7 "화면 다듬기 (빈 상태, 에러 메시지, 로딩)", 0036(페이지 틀)

## 정한 것

공통 부품 `src/components/common/page-states.tsx` 3개를 영역(운영사 `/admin`, 포털 `/portal`, 플랫폼 `/platform`)마다 Next.js 특수 파일로 연결한다. 사이드바·머리글은 그대로 두고 본문만 바뀐다.

| 파일 | 부품 | 보이는 것 |
| --- | --- | --- |
| `loading.tsx` | `PageLoading` | 제목 + 검색 + 표 모양의 뼈대(회색 막대). 화면이 덜컹거리지 않게 같은 자리를 잡는다 |
| `error.tsx` | `PageError` | "화면을 불러오지 못했습니다" + 오류 번호(digest) + [다시 시도] [처음으로]. **자세한 오류 내용은 화면에 보이지 않고 콘솔에만** |
| `not-found.tsx` | `PageNotFound` | "찾을 수 없습니다" — 없는 번호, 지운 데이터, 볼 수 있는 범위 밖 데이터 (`notFound()`) |

- 어느 영역에도 없는 주소는 최상위 `src/app/not-found.tsx` → [처음으로]는 `/`(로그인 상태에 따라 각 영역으로).
- 범위 밖 데이터도 "없음"과 똑같이 보여 준다 → 다른 화주사의 ASN 번호가 있는지조차 알 수 없게.
- 빈 목록 안내는 이미 `DataGrid`의 `empty`와 `EmptyState`로 화면마다 있어 그대로 둔다.
- 저장 실패 안내는 이미 `createAction` → `unwrap` → 알림 메시지로 공통 처리돼 있어 바꾸지 않았다.

## 알아 둘 것

- `loading.tsx`가 있으면 Next.js가 뼈대를 먼저 보내고 "찾을 수 없음"은 브라우저에서 바꿔 끼운다 → HTTP 상태가 404가 아니라 200으로 나간다. 로그인한 업무 화면이라 검색 노출 문제는 없어 그대로 둔다.
