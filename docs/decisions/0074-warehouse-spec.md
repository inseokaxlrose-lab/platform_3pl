# 0074. 창고 정보 확장 (컬럼 정의 반영, 유형 8개, 시스템 기본 창고, 운영 속성)

- 날짜: 2026-11-17
- 상태: 채택 (사용자 결정 — 아래 "결정")
- 관련: 0027 (창고), 0073 (센터 정보·대기 창고), 0030·0040 (공통코드 vs 상수), 0038 (논리 삭제), 0045 (재고 변경)

## 배경

창고는 코드·이름·유형(일반·대기 3종)·보관 조건만 있었다. 사용자가 창고 컬럼 정의(1차·2차)를 주었다.
창고는 센터 안에서 **용도와 재고 성격이 같은 공간의 묶음**이고, 유형에 따라
"재고를 출고에 할당할 수 있는가", "입고·출고가 되는가", "적치되면 기본 재고상태가 무엇인가"가 정해진다.

- **1차**: DB + API + 화면 — 유형·온도대·설명·정렬순서·동·층·면적·운영 속성(입고·출고·할당 가능, 기본 재고상태, 할당 우선순위, 기본 로케이션)·비고
- **2차**: DB + API만 — 층고·팔레트 보관능력·보관 방식·보세·위험물·관리 담당자·전용 화주사·로케이션 코드 접두어·구분자·확장속성

## 결정

| 항목 | 정한 것 |
| --- | --- |
| 창고 유형 | **플랫폼 상수**(`WAREHOUSE_TYPE`, `src/lib/warehouses/warehouse-codes.ts`) + DB 검사 조건. DB enum을 없애고 값 이름도 바꿈: `GENERAL`→`STORAGE`, `INBOUND_STAGING`→`INBOUND`, `OUTBOUND_STAGING`→`OUTBOUND`, `RETURN_STAGING`→`RETURN`, 새 유형 `QC`·`DAMAGED`·`VAS`·`CROSSDOCK` |
| 온도대 | DB enum `StorageCondition` → 글자 칸 + 운영사 온도대 상수 `TEMP_ZONE`(항온 포함). **센터 취급 온도대 안에서만** 고른다 |
| 시스템 기본 창고 | `system_yn` 칸. 센터 등록 때 자동으로 만드는 입고·출고·반품 대기 창고 = Y (기존 15개 보정). 대기 판단은 유형이 아니라 이 칸으로 |
| 창고코드 | **필수·불변**, 영문 대문자·숫자·밑줄 1~20자 (센터와 같은 방식, 비우면 시스템 코드로 채우던 방식은 없앰) |
| 상태 | ACTIVE(사용) / INACTIVE(사용 중지) — 로케이션과 같은 값 (상수 `WAREHOUSE_STATUS`) |
| 재고상태 | 상수 `STOCK_STATUS` (NORMAL·HOLD·DAMAGED·QUARANTINE). 지금은 창고의 기본 재고상태에만 쓴다. 재고 표 연결·할당 로직은 재고·출고 기능 때 |
| 보관 방식 | 분류용이라 **운영사 공통코드** `STORAGE_METHOD` (랙·평치·선반·복층·자동화 설비) |
| 전용 화주 | 스펙의 `dedicated_client_id` 대신 `dedicated_shipper_id` (이 프로젝트의 화주 = shipper, 화주사 표에 바로 외래 키) |

### 유형별 운영 속성 기본값

유형을 고르면 화면이 채우고 사용자가 고칠 수 있다. 이미 고친 값이 있으면 "유형 기본값으로 바꾸기 / 현재 값 유지"를 묻는다.

| 유형 | 입고 | 출고 | 출고 할당 | 기본 재고상태 |
| --- | --- | --- | --- | --- |
| STORAGE 일반 보관 | Y | Y | Y | NORMAL |
| INBOUND 입고대기 | Y | N | N | NORMAL |
| OUTBOUND 출고대기 | N | Y | N | NORMAL |
| RETURN 반품대기 | Y | N | N | HOLD |
| QC 검수·보류 | Y | N | N | HOLD |
| DAMAGED 불량 | Y | N | N | DAMAGED |
| VAS 유통가공 | Y | Y | N | NORMAL |
| CROSSDOCK 크로스도킹 | Y | Y | N | NORMAL |

출고대기는 이미 할당·피킹된 재고가 머무는 곳이라 다시 할당하지 않는다. 코드: `WAREHOUSE_TYPE_DEFAULTS`.

### 업무 규칙

- **시스템 기본 창고**: 삭제·코드·유형·명칭 변경·사용 중지 불가 (설명·정렬순서·비고만). 센터마다 유형별 1개 (부분 고유 인덱스 `tb_warehouse_one_system_per_center`), 대기 유형만·사용 중만 (검사 조건 `tb_warehouse_system_check`). 로케이션은 DEFAULT 하나만.
- **재고가 있으면**(수량 > 0) 유형·온도대 변경, 사용 중지를 막는다.
- **삭제**(논리 삭제)는 로케이션·재고 기록이 하나도 없을 때만. 그 밖에는 사용 중지를 안내. 목록 "삭제됨" → [되살리기].
- **온도대**: 센터 취급 온도대 중에서만. 반대로 센터에서 온도대를 뺄 때 그 온도대를 쓰는 창고가 있으면 거부한다. 센터 취급 온도대는 하나 이상 필수가 됐다 (기존 센터는 창고 온도대로 채움).
- **보세·위험물 구역**은 센터에 그 자격(`bonded_yn`·`hazmat_yn`)이 있을 때만 Y.
- **할당 가능 창고 안내**: 저장 후 센터에 출고 할당 가능한 사용 중 창고가 없으면 저장 결과에 안내(`notice`)를 붙인다 (막지 않음).
- **적치 대상**: 시스템 기본 창고가 아니고 입고 가능(Y)인 사용 중 창고 (예전: 일반 유형만).
- **기본 로케이션**: 이 창고의 사용 중인 로케이션만. 시스템 기본 창고는 DEFAULT 로케이션으로 자동 연결.
- 기본 창고 온도대: 센터 취급 온도대 중 상온, 없으면 상수 순서의 첫 번째. 하나도 없으면 상온을 센터에도 넣는다 (시드·테스트용 방어).

### 화면

- 편집: 섹션 기본 정보 / 위치·시설 / 운영 속성. 헤더 배지(기본·사용 상태)·센터·최종 수정, 보조 버튼 [로케이션 보기] [삭제] [사용 중지·다시 사용] (시스템 기본 창고는 앞의 것만).
- 목록: 센터(고정)·창고코드(고정, 기본 배지·설명) 등. 기본 순서 센터 정렬순서 → 창고 정렬순서 → 코드 (기본 창고 정렬순서 1·2·3, 새 창고 기본 10). 일괄 사용 중지·다시 사용·삭제에서 시스템 기본 창고는 고를 수 없다.
- 센터 편집 헤더에 [창고 보기].
- 새 공통 부품: `CenterSelect`(하나뿐이면 저절로 고름), `WarehouseSelect`(고른 센터의 창고만). 로케이션 목록 검색에도 적용. 로케이션 화면의 창고 선택지는 사용 중인 창고만, 정렬순서 순.
- 공통 기능 추가: `DataGrid`/`MasterListPage`의 `canSelectRow`(고를 수 없는 행), 검색 `custom` 칸의 `render`가 지금 입력 중인 조건 값(`values`)을 받는다, 입력 화면 저장 결과의 `notice`를 "저장했습니다." 뒤에 보여 준다.
