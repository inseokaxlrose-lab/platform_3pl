# 0038. 기준정보 공통 칸 — 등록·수정자, 동시 수정 막기, 상태, 논리 삭제

- 날짜: 2026-11-15
- 상태: 채택 (2a·2b·2c 적용, 2026-11-15)
- 관련: `docs/db-conventions.md` "공통 칸", 0037 (명명 규칙), 0015 (서버 액션 틀)

## 배경

운영사 컬럼 정의서가 모든 기준정보에 공통 칸(`status_cd`, `del_yn`, `created_at/by`, `updated_at/by`, `row_version`)을 둔다. 지금은 `created_at`/`updated_at`만 있고, 누가 고쳤는지는 운영사 한 곳만(`updated_by_id`) 남겼다. 두 사람이 같은 화면을 열어 저장하면 나중 저장이 앞 저장을 말없이 덮었다.

## 결정 (사용자 결정: 추천안, 2026-11-15)

- 3단계로 나눠 적용: 2a 등록·수정자 + 동시 수정 막기 → 2b `status_cd` → 2c 논리 삭제 + 되살리기.
- 대상 11개 표(사용자·권한그룹·센터·창고·로케이션·화주사·운영사·공통코드 그룹·공통코드·배송권역·단위). 하위 표는 부모 이력으로 본다. 사용자는 `del_yn` 없음.
- 등록·수정자는 **아이디(username)** 글자로 저장 (정의서대로). 화면 표시는 아이디로 사용자를 찾아 '이름 (아이디)'.
- 자동 기록: 기능 코드마다 작업자를 넘기지 않고, `createAction` → `runAsActor`(AsyncLocalStorage) → `prisma.ts` 쿼리 확장이 채운다. 빠뜨릴 수 없게 하기 위해.
- 동시 수정 막기: 화면이 불러온 버전과 DB 버전이 다르면 저장하지 않고 "다른 사람이 먼저 고쳤습니다. 새로 불러온 뒤 다시 저장해 주세요."
- 논리 삭제는 **되살리기 기능까지** (사용자 결정): 목록 상태 거르기에 "삭제됨", 골라서 [되살리기]. 같은 코드가 이미 쓰이고 있으면 거부.

## 2a 결과 (2026-11-15)

- 마이그레이션 `_audit_version`: 11개 표에 `created_by`/`updated_by`(기존 'system')·`row_version`(1). 운영사 `updated_by_id`는 아이디로 옮긴 뒤 삭제.
- 수정 화면·팝업 전부(센터·창고·화주사·배송권역·단위·공통코드 그룹/코드·권한그룹·사용자·운영사)가 버전을 보내고, 등록 결과에도 버전(1)을 돌려준다.
- 발견한 함정: Prisma 쿼리는 `await` 때 실행되므로 `runAsActor`가 결과를 안에서 기다려야 작업자가 남는다 (테스트로 발견해 고침).
- 검증: 빈 DB·데이터 복사본 적용 후 스키마 차이 없음, 전체 테스트 473개(공통 칸 자동 채우기·충돌·폼 버전 갱신 테스트 추가), 브라우저(두 번 연속 저장 성공, 다른 사람 저장 뒤 저장 → 충돌 문구, 운영사 "마지막 수정: 슈퍼 관리자 (admin)").

## 2b 결과 (2026-11-15)

- 마이그레이션 `_status_cd`: 9개 표의 `is_active` → `status_cd`(true → ACTIVE, false → INACTIVE) + 검사 조건. 권한그룹은 사용/중지 개념이 없고, 운영사는 4단계 `OPERATOR_STATUS`라 제외.
- 화면은 바꾸지 않았다: 사용 여부 true/false를 그대로 쓰고 DB 경계에서 변환 (Y/N과 같은 방식). 목록 정렬에서 "상태"는 이제 사용 → 사용 중지 순(글자 순).
- 발견한 함정: 타입 검사가 못 보는 곳 3가지(정렬 매핑 글자, 조건 목록 안 객체, 입력값을 통째로 저장하는 data) → 목록 상태 조건은 `statusWhere`로 한곳에 모으고, 저장은 `withStatus`로.
- 검증: 빈 DB·데이터 복사본 적용 후 차이 없음, 전체 테스트 476개, 브라우저(센터 상태 거르기 0건/2건, 임시 계정 사용 중지 → DB INACTIVE·수정자 admin·버전 2, 사용자 목록 "사용 중지" 거르기에 표시).

## 2c 결과 (2026-11-15)

- 마이그레이션 `_soft_delete`: 10개 표에 `del_yn`('N') + 검사 조건. 코드·이름 고유 9개를 "삭제 안 된 것끼리만"(부분 고유 인덱스)으로. Prisma `partialIndexes` 미리보기 기능을 켰다 — 켜면 손으로 만든 부분 인덱스(센터마다 입고대기 창고 1개)도 스키마에 적어야 지워지지 않는다.
- 지우기 6곳(로케이션·배송권역·단위·공통코드 그룹/코드·권한그룹)을 논리 삭제로. 외부 코드는 지운다(다른 항목이 같은 외부 코드를 쓸 수 있게). 배송권역의 담당 지역·권한그룹의 권한 목록은 되살릴 때를 위해 남기되, 지운 권역의 담당 지역은 "비어 있음"으로 본다.
- 자동 제외는 `prisma.ts` 확장(읽기·개수·수정·upsert). 관계 목록·`_count`·관계 조건은 `NOT_DELETED`를 직접 붙였다(센터 상세의 창고·권역, 창고 상세의 로케이션, 공통코드 목록, 담당 지역 검사).
- 되살리기: 목록 "삭제됨" 보기 + [되살리기] (로케이션·배송권역·단위·권한그룹), 공통코드는 [지운 항목] 팝업. 같은 코드 재사용·담당 지역 겹침·부모 그룹 삭제면 거부. 도움말에 "되살리기" 단락 추가, "되돌릴 수 없습니다" 문구 정리.
- 검증: 빈 DB·데이터 복사본 적용 후 차이 없음, DB에서 직접 "지운 같은 코드 여러 개 + 살아 있는 1개 허용 / 살아 있는 2개 거부 / 'X' 거부", 전체 테스트 481개(되살리기·코드 재사용·담당 지역 겹침·그룹 먼저 테스트 추가), 브라우저(임시 단위 삭제 → 목록에서 사라짐 → "삭제됨"에 보임 → [되살리기] → DB del_yn N·수정자 admin, 공통코드 [지운 항목] 팝업, 권한그룹 "삭제됨" 보기).
- 개발 팁: `prisma generate` 전에 개발 서버를 멈춘다. 켜 둔 채 바꾸면 옛 클라이언트 + 새 코드로 오류가 나고, 다시 켠 뒤 브라우저가 그 오류를 서버 기록에 늦게 보낸다.
