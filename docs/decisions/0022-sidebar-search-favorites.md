# 0022. 사이드바 메뉴 검색과 [전체 / 즐겨찾기] 탭

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0014 (화면 권한), 0015 (서버 액션, `'signed-in'`), 0021 (개인 설정 저장 방식)
- 코드: `src/components/app-shell/` (`app-sidebar.tsx`, `sidebar-nav-list.tsx`, `search-navigation.ts`, `filter-navigation.ts`, `sidebar-tab.ts`), `src/lib/navigation/`

## 결정

### 메뉴 검색

- 메뉴 이름에 검색어가 들어 있으면 찾는다 (대소문자·띄어쓰기 무시). **초성 검색**: `ㅍㅁ` → 품목, 글자와 섞어도 된다(`재ㄱ`).
- 묶음 이름이 맞으면 그 묶음의 메뉴를 모두 보여준다 (`입고` → 입고 메뉴 전부).
- 검색 범위는 탭과 관계없이 **권한 있는 전체 메뉴**. 검색 중에는 탭을 숨기고 결과만 보여준다.
- 키보드: `⌘K`/`Ctrl+K` 검색칸으로(접혀 있으면 펼침), `Enter` 첫 결과(열 수 있는 메뉴)로 이동, `Esc` 검색어 지우기.

### 즐겨찾기

- 메뉴 줄의 ☆(마우스를 올리면 보임)로 켜고 끈다. 즐겨찾기한 메뉴는 ★로 늘 보인다. "준비 중" 메뉴는 별이 없다.
- DB 표 `UserFavoriteMenu`(사용자 + 메뉴 주소)에 저장해 어느 PC에서나 같다. 추가한 순서대로 보여준다. 최대 30개.
- 메뉴 목록(`src/config/navigation.ts`)에 있는 주소만 받는다.
- **권한이 사라지거나 목록에서 없어진 메뉴는 화면에서만 숨긴다.** 기록은 남아서 권한이 돌아오면 다시 보인다.
- 별을 누르면 화면을 먼저 바꾸고 저장한다. 실패하면 되돌리고 이유를 보여준다.
- 서버 액션은 `'signed-in'`(로그인만 필요, 본인 것만). 레이아웃이 서버 액션을 사이드바에 prop으로 넘겨, 사이드바 부품은 서버 코드를 직접 부르지 않는다 (부품 테스트에서 가짜 함수로 바꿔 끼울 수 있게).
- 마지막으로 연 탭은 쿠키(`sidebar_tab`)에 기억해 서버가 처음부터 그 탭으로 그린다 (사이드바 접힘 상태와 같은 방식).

### 주의: 서버 부품은 'use client' 파일에서 값을 가져오지 않는다

- 처음에는 탭 쿠키 이름을 `app-sidebar.tsx`('use client')에 두고 서버 부품 `AppShell`이 가져다 썼다. 그러자 서버에는 글자 `'sidebar_tab'` 대신 "브라우저 부품 표시"가 들어와 쿠키를 찾지 못했다 (단위 테스트로는 안 잡히고 브라우저 확인에서 발견).
- 서버·브라우저가 함께 쓰는 값은 'use client'가 없는 파일(`sidebar-tab.ts`)에 둔다.

## 대안과 버린 이유

- **명령 팔레트(⌘K 팝업 창)**: 메뉴 수가 많지 않아 사이드바 안 검색으로 충분하다. 메뉴가 크게 늘면 다시 검토.
- **즐겨찾기를 브라우저 저장소에**: 다른 PC에서 유지되지 않는다.
- **즐겨찾기 순서 바꾸기**: 지금은 추가한 순서. 필요하면 나중에 (아이디어 보관함).

## 확인

- 테스트: 검색 규칙 6개, 즐겨찾기 탭 메뉴 고르기 2개, DB 5개, 사이드바 부품 8개.
- 브라우저:
  - `⌘K` → `ㅅㅇㅈ` → "사용자"만 남고 `Enter`로 이동했다.
  - 실제 마우스로 별을 눌러 추가하자 DB에 추가 순서대로 저장됐다.
  - 즐겨찾기 탭을 고른 뒤 다른 화면을 열어도 탭이 유지됐다.
  - `center.worker`는 권한 없는 메뉴가 즐겨찾기에서 숨겨졌고, 권한 있는 메뉴만 보였다. admin의 즐겨찾기는 섞이지 않았다.
