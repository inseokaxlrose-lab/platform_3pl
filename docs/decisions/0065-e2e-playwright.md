## 무엇을 확인하나

`e2e/inbound-flow.spec.ts` 한 개 시나리오로 MVP 한 바퀴를 실제 브라우저에서 돌린다.

1. 화주사(포털): ASN 등록 — 품목 E2E-WATER, BOX 10 (= 240 EA 환산 표시 확인)
2. 센터 작업자: 검수 240 EA + 로트·유통기한
3. 라벨 미리보기 1장 (240 EA ÷ PLT 1,440) — **인쇄 창은 열지 않는다**
4. 입고 확정 (기본 = 남은 전부)
5. 적치: 입고대기 → E2EGEN / E2E-01
6. 화주사(포털): ASN 목록 "확정완료", 내 재고(로트별)에 이번 로트 240 EA

사람마다 따로 로그인한 브라우저 창(컨텍스트)을 쓴다. 비밀번호는 `.env`의 `SEED_SAMPLE_PASSWORD`(코드·로그에 남기지 않음).

## 어떻게 돌리나

```
npm run e2e:prepare   # 처음 한 번 (여러 번 해도 안전)
npm run e2e           # 테스트
```

| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| DB | 개발 DB 이름 뒤에 `_e2e`를 붙인 **별도 DB** (`e2e/e2e-env.ts`) | 개발 데이터를 더럽히지 않는다. 지우지 않고 쌓아도 되게 로트번호를 실행마다 새로 만든다 |
| 준비 | `scripts/e2e-prepare.sh`: DB 만들기 → 마이그레이션 → 시드 → `e2e/setup-data.ts`(품목·창고·로케이션) | 시드에 없는 테스트 전용 기준정보만 따로 |
| 서버 | Playwright가 `next dev --port 3100`을 띄움, 빌드 폴더 `.next-e2e` (`NEXT_DIST_DIR`) | 평소 쓰는 개발 서버(3000)와 동시에 돌려도 서로 부딪히지 않는다 |
| 브라우저 | 설치된 Chrome 사용 (`channel: 'chrome'`) | 브라우저를 따로 내려받지 않는다 |
| 실행 | 순서대로 1개씩 (`workers: 1`) | 한 흐름이 앞 단계 결과에 기대므로 |

- Next.js가 `tsconfig.json`의 include에 `.next-e2e/types` 경로를 자동으로 넣는다 → 그대로 둔다(빼도 다시 들어감).
- 결과 폴더(`test-results`, `playwright-report`, `.next-e2e`)는 git·lint·prettier에서 제외.

## 요소 찾기 요령 (실패하며 알게 된 것)

- 옆 메뉴의 "즐겨찾기 추가" 버튼 이름에 메뉴 이름이 들어 있다 → 화면 버튼은 `/^입고 확정 \(/`처럼 앞부분을 고정해서 찾는다.
- 고르기 상자(`role="combobox"`)는 겉 글자가 접근성 이름이 되지 않는다 → id(`[id^="putaway-location-"]`)로 찾는다.
- 저장이 끝났는지는 상태 글자 대신 **성공 안내 문구**(`…로 확정했습니다`, `…건을 적치했습니다`)로 기다린다.

## 하지 않은 것 (나중에)

- CI(자동 빌드)에서 돌리기, 실사·조정·자료 추출 등 다른 흐름, 권한별 접근 거부 확인.
