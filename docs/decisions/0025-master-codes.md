# 0025. 기준정보 코드 체계: 우리 코드 + 사용자 정의 코드 + 외부 코드 매핑

- 날짜: 2026-11-13 (2026-11-20 0084로 갱신)
- 상태: 채택 — 처음에는 "시스템 코드(sys_cd) + 사용자 코드 + 외부 코드"였으나, **0084 ②에서 시스템 코드를 없애고 아래 구조로 바꿨다**. 외부 코드 입력 화면은 0068에서 별도 메뉴(외부코드 매핑)로 옮겼다.
- 관련: 0084 (체번·코드 3층), 0085 (체번 규칙 화면), 0068 (외부코드 매핑 메뉴), 0003 (도메인 모델), PRD 4장 기준정보

## 배경

- 기준정보(센터·화주사·품목·거래처 등)는 SAP·ERP 등 외부 시스템의 Master Data와 연동할 가능성이 높다.
- 3PL은 연동 상대가 하나가 아니다: 운영사 자신의 ERP/SAP + **화주사마다 각자의 ERP**(품목코드 체계가 화주사마다 다름).
- 라벨 바코드·문서 번호·재고 이력에는 바뀌지 않는 코드가 필요하다.

## 결정: 코드 3층

| 층 | 칸 | 예 (품목) | 정하는 쪽 | 변경 | 쓰는 곳 |
|---|---|---|---|---|---|
| 내부 키 | `*_id` (BIGINT) | `1201` | DB 자동 | 불변 | DB 관계 (화면에 안 보임) |
| **① 우리 코드** | `*_cd` | `GNS000001`, `SKU-001` | 사용자, **비우면 자동 체번**(0084) | **등록 후 불변** | 화면 검색·표시, 라벨·문서, 연동의 기본 키 |
| **② 사용자 정의 코드** | `*_cust_cd` | `ERP-A001` | 화주(또는 운영사 ERP) | 변경 가능 | 화주 시스템과의 대응, 연동 조회 키(`CUST_CD`일 때) |
| **③ 외부 코드** | `tb_ext_code` | SAP `1000` | 연동 또는 사용자 | 연동 상대별 | 연동 상대가 여럿일 때 상대별 코드 |

### ① 우리 코드

- 비우면 체번 규칙(`tb_numbering_rule`, `issueCode`)으로 자동으로 붙는다. 직접 넣을 수도 있지만 **자동 체번 모양은 직접 쓸 수 없다**(`isAutoPattern` — 나중 자동 발급과 겹치지 않게).
- 등록 후에는 바꿀 수 없다. 불변 코드가 따로 필요 없어져 시스템 코드를 없앴다.
- 중복 금지 범위와 자동 모양은 아래 표. DB 부분 고유(`del_yn = 'N'`)로도 막는다.

### ② 사용자 정의 코드

- 화주 시스템의 코드(거래처·납품처·품목) 또는 운영사 ERP의 화주 코드. 선택 칸, 같은 범위 안에서 중복 금지(값이 있을 때).
- 화주사의 **연동 조회 키**(`if_key_type_cd`)가 `CUST_CD`면 API·엑셀이 이 코드로 대상을 찾는다(`src/lib/master-code/if-key.ts`).

### ③ 외부 코드 매핑 표 (`ExternalCode`)

- 칸이 아니라 **표**로 둔다: 연동 상대가 늘어도 구조 변경 없이 행만 추가, 한 대상이 여러 시스템 코드를 동시에 가질 수 있다.
- 한 줄 = 연동 상대 + 대상 종류 + 대상 id + 외부 코드. 같은 연동 상대·같은 종류 안에서 외부 코드 중복 금지, 한 대상은 연동 상대마다 외부 코드 1개.
- 연동 상대 목록은 설정 파일(`src/config/external-systems.ts`). 입력은 **외부코드 매핑 메뉴**에서만 한다(0068 — 새 기준정보는 `external-code-targets.ts`에 대상 추가).
- 대상이 지워지면 매핑도 정리한다.

### 적용 범위

| 기준정보 | ① 우리 코드 (자동 모양) | 중복 금지 범위 | ② 사용자 정의 코드 | ③ 매핑 |
|---|---|---|---|---|
| 센터 | 필수 입력 (자동 없음) | 운영사 | ✗ | ✅ |
| 창고 | 필수 입력 (자동 없음) | 같은 센터 | ✗ | ✅ |
| 로케이션 | 필수 입력 (코드 자체가 위치, 예 `A-01-01`) | 같은 창고 — 스캔은 `창고코드.로케이션코드`(0084 ⑤) | ✗ | ✅ |
| 화주사 | `SH0001` | 운영사 | `shipper_cust_cd` | ✅ |
| 거래처 | `{화주 접두어}C000001` | 같은 화주사 | `customer_cust_cd` | ✅ |
| 납품처 | `{거래처코드}-01` | 같은 거래처 | `ship_to_cust_cd` | — |
| 품목 | `{화주 접두어}S000001` | 같은 화주사 | `item_cust_cd` | ✅ |
| 단위 | 표준 코드 (EA·BOX 등) | 시스템 + 운영사 | ✗ | ✅ |

- 화주 접두어(`code_prefix`, 2글자)는 화주사마다 정하고, 거래처·품목 코드가 한 번이라도 발행되면 바꿀 수 없다.

## 대안과 버린 이유

- **시스템 코드 + 사용자 코드 (처음 결정)**: 사용자 코드가 비면 시스템 코드를 쓰는 이중 구조라 화면·API·라벨마다 어느 코드를 쓸지 헷갈렸다. 우리 코드를 불변 + 자동 체번으로 두면 한 칸으로 충분하다 (0084).
- **우리 코드에 I/F 코드를 채움**: 연동 상대가 둘 이상이면 감당할 수 없고, 화주 코드 체계가 바뀌면 우리 코드도 바뀌어야 한다 → 사용자 정의 코드·외부 코드로 분리.

## 미룬 것

- 연동 상대 관리 화면, 매핑 일괄 업로드. (체번 규칙 관리 화면은 0085에서 만들었다.)

- 센터·창고 사용자 정의 코드는 0093에서 추가했다.
