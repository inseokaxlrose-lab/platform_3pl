# 0025. 기준정보 코드 체계: 시스템 코드 + 사용자 코드 + 외부 코드 매핑

- 날짜: 2026-11-13
- 상태: 채택 (사용자 결정: 추천안)
- 관련: 0003 (도메인 모델), PRD 4장 기준정보

## 배경

- 기준정보(센터·화주사·품목·거래처 등)는 SAP·ERP 등 외부 시스템의 Master Data와 연동할 가능성이 높다.
- 3PL은 연동 상대가 하나가 아니다: 운영사 자신의 ERP/SAP + **화주사마다 각자의 ERP**(품목코드 체계가 화주사마다 다름).
- 라벨 바코드·문서 번호·재고 이력에는 절대 바뀌지 않는 코드가 필요하다.

## 결정: 코드 3층

| 층 | 예 (센터) | 정하는 쪽 | 변경 | 쓰는 곳 |
|---|---|---|---|---|
| 내부 id | `cuid` | 시스템 | 불변 | DB 관계 (화면에 안 보임) |
| **① 시스템 코드** | `CT000001` | 시스템 자동 부여 | **불변** | 라벨 바코드, 문서 번호, 이력, 연동의 기준 키 |
| **② 사용자 코드** | `ICN` | 사용자 (비우면 시스템 코드로 채움) | 변경 가능 | 화면 검색·표시, 엑셀 업로드 |
| **③ 외부 코드** | SAP `1000`, ERP `W-ICN` | I/F 또는 사용자 | 연동 상대별 | SAP·ERP 연동 |

### ① 시스템 코드

- 형식: 종류 접두어 + 0을 채운 일련번호. 종류별 PostgreSQL 시퀀스로 번호를 매긴다 (동시에 등록해도 겹치지 않음). 번호가 건너뛰는 것은 허용한다(등록 실패 시).
- 공통 함수 하나로만 만든다 (`nextSystemCode('CENTER')`).

### ② 사용자 코드

- 영문 대문자·숫자·하이픈·밑줄, 종류별 길이 제한. 비우면 시스템 코드를 그대로 쓴다.
- 중복 금지 범위는 종류마다 다르다 (아래 표). DB 고유 규칙으로도 막는다.
- 화면: 목록에 사용자 코드를 크게, 시스템 코드를 작게 함께 보여주고, 검색은 둘 다 된다.

### ③ 외부 코드 매핑 표 (`ExternalCode`)

- 칸(`erpCode`)이 아니라 **표**로 둔다: 연동 상대가 늘어도 구조 변경 없이 행만 추가, 한 대상이 여러 시스템 코드를 동시에 가질 수 있다.
- 한 줄 = 연동 상대 + 대상 종류 + 대상 id + 외부 코드.
- 규칙: 같은 연동 상대·같은 종류 안에서 **외부 코드 중복 금지**, 한 대상은 연동 상대마다 **외부 코드 1개**.
- 연동 상대 목록은 처음에는 설정 파일(`src/config/external-systems.ts`)에 둔다: `SAP`, `ERP`. 화주사 ERP 연동이 생기면 화주사별 연동 상대(예: `GANA-ERP`)로 추가하고, 그때 관리 화면을 검토한다.
- 대상이 사라져도 매핑을 남기지 않도록, 대상 삭제(실제로는 대부분 사용 중지) 시 함께 정리한다.

### 적용 범위

| 기준정보 | ① 시스템 코드 | ② 사용자 코드 중복 금지 범위 | ③ 매핑 |
|---|---|---|---|
| 센터 | `CT` + 6자리 | 전체 | ✅ |
| 창고 | `WH` + 6자리 | 같은 센터 | ✅ |
| 화주사 | `SH` + 6자리 | 전체 | ✅ |
| 품목 | `IT` + 8자리 | 같은 화주사 | ✅ |
| 거래처 | `CU` + 8자리 | 같은 화주사 | ✅ |
| 배송권역 | `DZ` + 6자리 | 같은 센터 | ✅ |
| 로케이션 | ✗ (코드 자체가 위치, 예 `A-01-01`) | 같은 창고 | ✅ |
| 단위 | ✗ (EA·BOX 등 표준 코드) | 전체 | ✅ |

## 대안과 버린 이유

- **시스템 코드 + 사용자 코드에 I/F 코드를 채움**: 단순하지만 연동 상대가 둘 이상이면 감당할 수 없고, 사용자가 코드를 바꾸면 연동이 깨진다.
- **사용자 코드 자유 + 매핑 표 (시스템 코드 없음)**: 라벨·이력에 바뀔 수 있는 코드가 남는다.

## 미룬 것

- 연동 상대 관리 화면, 실제 I/F(파일·API 수신), 매핑 일괄 업로드.
