# 0060. 재고 조회 (위치별 · 품목별 · 로트·유통기한별)

- 날짜: 2026-11-16
- 상태: 채택 — **추천안으로 진행, 사용자 검토 필요**
- 관련: PRD 재고 관리 1 (위치·소유·로트/유통기한 기준, 임박 표시), 0042 (단위 환산), 0044 (재고 모델)

## 화면 `/admin/stock` (권한 `stock.inventory.read`, 엑셀 `stock.inventory.export`)

ROADMAP의 재고 조회 3가지를 **한 화면의 "보기 기준"**으로 만들었다(추천안).

| 보기 | 한 줄 | 칸 |
| --- | --- | --- |
| 위치별(기본) | 재고 줄(로케이션 + 품목 + 로트 + 유통기한) | 센터·창고·로케이션·화주사·품목·로트·유통기한(임박·만료)·재고·환산·할당·가용 |
| 품목별 | 화주사 + 품목 합계 | 화주사·품목·재고·**환산(큰 단위부터: 2 PLT · 5 BOX)**·할당·가용·재고 위치 수 |
| 로트·유통기한별 | 화주사 + 품목 + 로트 + 유통기한 합계 | 위 + 로트·유통기한(임박 D-n·만료 배지) |

- 조건: 보기 기준, 검색어(품목코드·품목명·바코드·로케이션·로트·화주사명), 센터, 화주사 / 상세: 창고(센터에 딸림), 유통기한(임박·만료), 수량 0 포함.
- 수량 0인 재고 줄은 기본으로 뺀다(줄은 이력 때문에 남아 있다).
- **유통기한 상태**(`src/lib/stock/expiry.ts`): 남은 일수 = 유통기한 − 오늘(한국 날짜). 0 미만 만료, 품목의 임박 기준 일수 이하 임박. 기준이 없는 품목은 만료만.
- 임박 거르기는 품목마다 기준이 달라 DB 조건으로 못 거른다 → 임박 조건일 때만 최대 1만 건을 읽어 거른 뒤 페이지를 나눈다. 만료는 DB 조건.
- 데이터 범위 `STOCK_SCOPE` = 센터 `centerId`, 화주사 `shipperId`. 화주 포털(M6 내 재고)도 같은 함수를 쓴다.

## 함께 고친 공통 부품

- 검색 조건 `segment`에 `allLabel`(값이 비었을 때 첫 버튼 이름, 기본 "전체") — 보기 기준의 기본 보기를 "위치별"로.

## 추천안으로 정한 것 (검토 필요)

- 3가지 조회를 메뉴 3개가 아니라 **한 화면 + 보기 기준**으로.
- 합계 보기(품목별·로트별)는 정렬을 고정(품목 → 유통기한 순). 위치별만 칸 정렬.
- 환산 표시는 품목의 환산단위로 큰 것부터 나누고 남는 것은 기본단위.
