## 결정

### 인증 계층 (사용자 로그인과 분리)

- `/api/v1/*`는 Next 라우트 핸들러다. `proxy.ts`(로그인 쿠키)는 이 경로를 보지 않는다.
- 모든 라우트는 `apiRoute()`로 만든다.
  - 순서: 요청ID → HTTPS(운영만) → 본문 읽기 → **키 인증** → 호출 한도 → 멱등 확인 → 처리 → 응답 봉투 → 로그(`after`).
- **키가 곧 신원**
  - 키 하나가 운영사·화주·환경·권한을 정한다. 본문의 화주코드는 믿지 않는다.
  - 처리는 운영사 출입증(`runInContext`, 작업자 `api:{식별부}`) 안에서 돈다 → `prisma.ts`가 이 운영사로 자동으로 거른다.
  - 서비스 계층에는 데이터 범위 `{ kind: 'SHIPPER' }`를 넘긴다. 포털과 같은 규칙이 된다(API 우선).
- **인증 순서** (`authenticate.ts`): 형식 → 식별부로 키 찾기 → 해시 비교(시간 일정) → 상태·만료 → 환경 → 허용 IP → 운영사 상태 → 화주 상태·API 사용 → 권한.
  - 키를 찾았지만 거부한 경우(폐기·만료·IP·상태)에도 로그에 화주·키를 남긴다 → 유출 의심 추적.
  - 최근 사용 일시·IP는 인증을 통과한 호출만 기록한다. SQL로 직접 써서 키 버전이 바뀌지 않게 했다(수정 팝업 충돌 방지).
- OAuth2(2차)는 `authenticate`만 바꾸면 된다. 키 → 컨텍스트 → 서비스 구조를 그대로 쓴다.

### 키 (`tb_api_client` · 권한 · 허용 IP · 이력)

- **형식**: `{test|live}_{식별부 8자}_{비밀부 40자}` (전체 54자).
  - 식별부는 헷갈리는 글자(l·o·0·1)를 뺀 소문자·숫자다.
  - DB에는 키 전체의 **HMAC-SHA256(`API_KEY_SECRET`) 해시**만 저장한다.
  - 키가 무작위 54자라 느린 해시(bcrypt)는 필요 없다. 대신 비밀값이 없으면 해시를 맞출 수 없다.
- **원문은 발급 응답에서 한 번만** 보인다. 발급 완료 팝업은 [복사]와 경고가 있고, "보관했습니다"에 체크해야 닫힌다(바깥 누르기·Esc 막음).
- **화주·환경별 사용 중 키는 최대 2개**다(교체 기간). 만료일이 지난 키는 셀 때·호출할 때 `EXPIRED`로 바꾸고 이력을 남긴다.
- 폐기는 사유가 필수이고 즉시 효력이다. **화주를 해지하면 키를 모두 폐기**한다(`changeShipperStatus`, 같은 트랜잭션).
- **이력** `tb_api_client_event`: `ISSUED`·`UPDATED`(바뀐 칸 이전→이후)·`REVOKED`(사유)·`EXPIRED`, 누가·언제. 수정 팝업 아래에 보인다.
- **권한(scope)** 상수 9개 (`api-codes.ts` + DB 검사 조건).
  - 발급 기본값은 조회·쓰기 8개다(재고 조회는 2차라 뺐다).
  - 화주 상태와 함께 본다.

| 화주 상태 | TEST 키 | LIVE 키 |
| --- | --- | --- |
| 준비중 | 됨 | `CLIENT_NOT_ACTIVE` |
| 운영중 | 됨 | 됨 |
| 일시정지 | 됨 | 조회만 (쓰기 권한 API는 `CLIENT_SUSPENDED`) |
| 해지 | 키 모두 폐기 | 키 모두 폐기 |

- `api_enabled_yn = N`이면 키가 있어도 `API_DISABLED`다.

### 공통 틀

- **응답 봉투**
  - 한 건: `{ requestId, result: 'SUCCESS', data }`
  - 등록(배열): `{ requestId, result: SUCCESS|PARTIAL|FAIL, summary, items[] }` (건별 `seq·docNo·result·id|errors[]`)
  - 오류: `{ requestId, result: 'FAIL', error: { code, message, field?, category } }`
  - TEST 키면 `dryRun: true`가 붙는다. HTTP 상태는 정의서 그대로(처리되면 200, 부분 성공도 200).
- **오류코드 카탈로그** `api-errors.ts` 22개. 문서 `docs/api-error-codes.md`와 테스트로 맞춘다.
  - 서비스 오류(`ActionError`)·입력 규칙 오류(Zod)는 자동으로 바꾼다(VALIDATION→`VALIDATION_FAILED` 등).
- **dry-run**: `writeTransaction(ctx, tx => …)`가 TEST면 끝까지 처리한 뒤 트랜잭션을 되돌린다. 자동 지정될 배송센터 같은 결과가 실제와 똑같이 계산된다.
  - 리소스 API는 저장 함수에 이 `tx`를 넘긴다(저장 함수가 따로 트랜잭션을 열지 않게 — 각 작업에서 맞춘다).
- **멱등**: `Idempotency-Key` 헤더 + 본문 해시 → `tb_api_idempotency`(24시간).
  - 같은 본문이면 처음 응답을 그대로 돌려준다(`Idempotent-Replayed: true`, 다시 처리 안 함). 다른 본문이면 409.
- **호출 한도**: 키별 1분 고정 구간 카운터 `tb_api_rate_bucket`. `INSERT … ON CONFLICT … RETURNING` 한 문장이라 동시에 와도 맞다.
  - 헤더 `X-RateLimit-Limit`·`Remaining`, 초과하면 429 + `Retry-After`.
- **요청 로그** `tb_api_request_log` + 건별 `tb_api_request_item`.
  - 응답 뒤(`after`) 저장한다. 요청 밖(테스트)에서는 바로 실행하고 `flushApiTasks()`로 기다린다.
  - 본문은 **개인정보를 가린 뒤** 저장한다(`mask.ts`): 이름·전화·주소·이메일 칸 이름으로 찾되, 품목명·센터명 같은 업무 칸은 그대로 두고, 키·비밀번호는 통째로 가린다.
  - 헤더(키)는 저장하지 않는다.
- **로그 보관 (제안 그대로 적용)**: 본문 90일 뒤 비움, 요약 1년 뒤 지움, 멱등 24시간, 지난 호출 한도 구간 5분. 별도 예약 작업 없이 로그를 저장할 때 서버마다 1시간에 한 번 정리한다.
- **요청ID** `req_{한국 날짜}_{무작위 16자}`: 응답 본문과 `X-Request-Id` 헤더에 들어간다.
- **HTTPS**: 운영(`NODE_ENV=production`)에서 `X-Forwarded-Proto`가 https가 아니면 `HTTPS_REQUIRED`다. 개발·테스트는 http를 허용한다.

### 엔드포인트 (① 단계)

- `GET /api/v1/me`: 키의 화주(코드·이름·상태)·키(이름·식별부·환경·권한·만료·한도)·이용 센터(기본 먼저)를 돌려준다. 권한이 필요 없다.
- `GET /api/v1/openapi.json`: OpenAPI 3.0 명세다. 키 없이 열람하고 비밀 정보는 없다.
  - 응답 모양은 Zod 규칙에서 `z.toJSONSchema`로 만든다(새 라이브러리 없음).
  - 화주 연동 API만 담고, 화면용 서버 액션과 섞지 않는다.
- 거래처·품목·ASN·출고요청 API는 정의서 8번 규칙대로 **각 기준정보·업무 작업에서** 이 틀 위에 만든다.

### 화면

- **화주사 편집 → "API 키" 섹션** (바로 적용 섹션)
  - 키 목록: 이름·환경·상태·만료 예정 배지·식별부·권한 수·허용 IP·한도·만료·최근 사용·발급·폐기 사유.
  - [키 발급]: 환경마다 2개가 차면 잠긴다. 해지 화주는 잠긴다.
  - 줄마다 [수정]·[폐기](사유 필수).
  - 발급·수정 팝업: 이름·환경(수정 불가)·권한 체크·허용 IP 표·만료일·분당 한도. LIVE인데 IP를 비우면 "IP 제한 권장" 경고. 수정 팝업에는 키 이력이 보인다.
- **연동 → API 키** (`/admin/integration/api-keys`): 모든 화주의 키 목록.
  - 검색: 화주·상태·환경·**만료 예정(14일)**.
  - 줄을 누르면 그 화주의 API 키 섹션으로 간다.
- **권한**: `integration.api-keys` (조회·등록=발급·수정=수정/폐기)다. 기존 운영사의 "슈퍼 관리자" 그룹에만 넣었다(마이그레이션). 서버는 전체 범위(운영사 사용자)만 받는다.
- **만료 알림**: 메일 기능이 없어 "만료 예정" 배지와 목록 조건으로 대신한다(정의서 허용). 발급 알림 메일은 TODO다.

### ② 단계: API 호출 이력 · 개발자 가이드

- **연동 → API 호출 이력** (`/admin/integration/api-logs`, 권한 `integration.api-logs` 조회·엑셀, 기존 슈퍼 관리자 그룹에 추가)
  - 기본 검색: 화주·기간·API 구분·결과. **기간을 비우면 최근 7일**이다(로그가 많아 전체 기간을 한 번에 보지 않는다 — 검색 칸 이름에 표시).
  - 상세 조건: 환경·키·요청ID·화주 문서번호(건별 결과에서)·오류코드(대표·건별)·HTTP 상태.
  - 컬럼: 요청 일시·화주·API 구분·환경·결과·전체/성공/실패·처리 시간·HTTP·오류코드·요청ID (키·IP·경로는 숨김).
  - **오늘 요약**은 목록 헤더의 meta 줄이다: 호출 수·실패율·429 수·실패 많은 화주 5곳. 화주 배지를 누르면 그 화주의 실패·부분 성공만 거른다.
  - 운영사 분리: 서버 액션 안이라 `prisma.ts`가 이 운영사 로그만 준다. **키 확인 전에 실패한 요청(키 없음·틀린 키)은 운영사를 몰라 어느 화면에도 보이지 않는다**(플랫폼 화면은 2차).
  - 로그 표는 화주·키와 관계를 두지 않는다(키를 지워도 로그는 남게). 이름은 조회할 때 붙인다.
- **상세** (`/admin/integration/api-logs/{요청ID}`): 요약(API·화주·키·IP·HTTP·처리 시간·오류코드·멱등 키·건수), 건별 결과, 요청·응답 본문(가린 값, 보기 좋게 줄바꿈).
  - 90일이 지나 본문을 비웠으면 그렇게 알린다.
  - **이 키의 최근 7일 호출** 링크가 있다. 화주사 화면 API 키 줄의 [호출 이력]도 같은 화면으로 간다(유출 의심 폐기 전 확인 — 정의서 9번).
- **개인정보 가리기 보강**: 칸 이름과 **부모 칸 이름**을 함께 본다.
  - `client.name`·`key.name`·`centers[].name`은 업무 정보라 그대로 둔다(부모가 정해진 업무 객체 이름과 정확히 같고, 칸이 name·email 같은 일반 이름일 때만).
  - `receiver.name`·`receiverName`·`customerName`(개인 구매자일 수 있음)은 가린다. 목록 껍데기(`items`·`lines`) 안도 마찬가지다 — 덜 가리는 것보다 더 가리는 쪽을 택했다.
- **개발자 가이드** `docs/api-guide.md`: 연동 절차(TEST → `/me` → 검증 → LIVE), 인증·키 보관·교체, 요청 규칙, 응답 봉투·건별 결과, 멱등, 커서 페이징·변경분 조회(`cursor`·`limit`·`updatedAfter` — 각 조회 API가 따를 규칙), 호출 한도, 하위 호환, 화주 상태별 동작, 문의 방법. 화주 포털 "개발자 센터"에서 열람하는 것은 2차다.
