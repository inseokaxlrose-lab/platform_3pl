# 0012. 로그인 / 로그아웃과 영역 접근

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0010 (Better Auth, 아이디 로그인, 회원가입 끔)

## 결정

### 흐름

- `/` → 로그인했으면 사용자 유형별 홈(운영사·센터 `/admin`, 화주사 `/portal`), 아니면 `/login`
- `/login` → 성공 시 `?next=`(원래 가려던 화면) 또는 홈 / 이미 로그인했으면 바로 이동
- 상단 바 사용자 메뉴 → 로그아웃 → `/login`

### 보안 규칙

| 규칙 | 구현 |
|---|---|
| 아이디·비밀번호 중 무엇이 틀렸는지 알리지 않는다 | 실패 문구 하나: "아이디 또는 비밀번호가 올바르지 않습니다." |
| 사용 중지 계정 차단 | 로그인: 세션 만들기 직전 `isActive` 검사(`databaseHooks`) / 로그인 중: `getCurrentUser`가 `isActive=false`면 로그인 안 된 것으로 처리 |
| 돌아갈 주소는 사이트 안·자기 영역만 | `safeNextPath`: `/`로 시작, `//`·`/\` 거부, 자기 영역 주소만 (`src/lib/redirect.ts`) |
| 영역 분리 | 다른 영역 사용자는 자기 영역 홈으로 (`requireUser(area)`) |

### 문지기 두 곳

1. `src/proxy.ts` (Next.js 16의 middleware): 로그인 쿠키가 없으면 화면을 만들기 전에 `/login?next=…`로. 쿠키 "존재"만 보는 빠른 1차 확인.
2. 레이아웃 `requireUser('admin' | 'portal')`: DB에서 세션·사용 여부·영역을 실제로 검사.

- 버튼·데이터 단위 권한 검사는 "서버: 권한 검사 공통 함수" 작업에서 서버 액션마다 한다 (레이아웃 검사만으로는 충분하지 않다).

### 계정 만들기

- `createUserAccount()` (`src/lib/users/`): 사용자 + 암호화 비밀번호를 한 트랜잭션으로. Better Auth 암호화 함수(`auth.$context.password.hash`)와 저장 형식(`providerId: 'credential'`)을 그대로 따른다.
- 아이디는 소문자로 저장(대소문자 무시), 화면 표시용 원래 아이디는 `displayUsername`.
- `server-only` 표시로 브라우저 코드에 섞이지 않게 한다. 테스트·스크립트에서는 빈 모듈로 대체하거나 `--conditions=react-server`로 실행한다.

## 확인

- DB 테스트: 실제 Better Auth로 로그인 성공·실패·사용 중지·대소문자·암호화 저장.
- 브라우저: 임시 계정 2개로 로그인 전 접근 → 로그인 화면(원래 주소 보존), 틀린 비밀번호, 화주사의 `/admin` 접근 → `/portal`, 로그아웃, 로그인 중 사용 중지 → 다음 이동에서 로그인 화면(무한 이동 없음). 확인 후 임시 계정 삭제.
