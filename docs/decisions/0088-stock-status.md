# 0088. 재고상태 — 재고 주소에 상태 포함 (M8 A2)

- 날짜: 2026-11-20
- 상태: 채택
- 관련: 0045 (재고 변경 공통 함수), 0044 (재고 이력), 0060 (재고 조회), 0074 (창고 기본 재고상태), 0087 (사유 코드 HOLD_REASON), 기준정보 누락 검토 2-1·3-1
- 코드: `src/lib/stock/stock-change.ts` (`changeStockStatus`, 주소의 `status`), `src/lib/stock/stock-status.ts`·`stock-status-schema.ts`, `src/lib/stock/stock-list.ts`, `src/components/stock/stock-status.tsx`
- 마이그레이션: `20261120090000_stock_status`

## 배경

창고에 기본 재고상태(정상·보류·불량·격리, 0074)는 있었지만 재고 줄에는 상태가 없어, 같은 창고 안의 특정 로트만 "출고 금지"로 묶거나 불량을 창고 이동 없이 구분할 수 없었다.

## 사용자 결정 (2026-11-20)

- **재고 주소에 상태를 넣는다** (추천안). 보류·격리는 로트 단위로 자주 생기고, 매번 창고를 옮기면 현장 작업이 늘어난다.

## 결정

- `tb_stock.stock_status_cd` (NORMAL·HOLD·DAMAGED·QUARANTINE, 상수 `STOCK_STATUS` + DB 검사). 고유키 `tb_stock_address_key` = (로케이션, 품목, 로트, 유통기한, **상태**).
- `tb_stock_txn.stock_status_cd`: 그때의 상태(주소 칸처럼 그대로 남김). 거래 유형에 `STATUS_CHANGE` 추가.
- **재고 변경 공통 함수**
  - 주소(`StockAddress`)에 `status`(비우면 NORMAL).
  - 입고(`receiveStock`): 상태를 안 주면 **창고의 기본 재고상태**.
  - 이동(`moveStock`): 도착 창고의 기본이 정상이 아니면 그 상태로, 정상 창고면 **출발 상태 그대로**(보류 재고를 정상 창고로 옮긴다고 풀리지 않는다).
  - 상태 변경(`changeStockStatus`, 새 함수): 같은 자리의 일부·전부를 다른 상태로. 나감(옛 상태)+들어옴(새 상태) 두 줄, 같은 묶음 번호. 할당된 수량은 못 바꾼다. 정상이 아닌 상태로 바꿀 때 사유 코드(HOLD_REASON) 필수.
  - 적치·실사 확정은 재고 줄의 상태를 그대로 넘긴다.
- **가용 수량은 정상 재고만** (보류·불량·격리는 0). 출고 할당도 정상만 쓴다(출고 기능에서).
- **재고 조회**: 상태 열·상태 조건, 합계 보기(품목별·로트별)도 상태별로 행을 나눈다. 위치별 보기에 [상태 변경](권한 `stock.inventory.update` — 기존 운영사의 슈퍼 관리자·센터 운영자 그룹에 마이그레이션으로 추가, 새 운영사는 기본 그룹 정의대로).
- 재고 이력: 상태 열, 상태 변경 유형, 사유는 HOLD_REASON 이름. 현재 재고 추출 자료에 재고상태 열.
- DB 검사 `tb_stock_txn_reason_check`를 "조정이면 사유 글자 **또는 사유 코드**"로 고쳤다(0087에서 사유 코드만 있는 조정이 막히던 것).

## 버린 안

- **창고로만 구분**: 보류할 때마다 보류 창고로 옮겨야 해 현장 작업·로케이션이 늘어난다.
- **재고 줄에 보류 수량 칸(hold_qty)만 두기**: 불량·격리처럼 상태가 여럿이면 칸이 늘고, 로트·사유별 이력을 남기기 어렵다.
- **정상 창고로 옮기면 정상으로 풀기**: 보류가 의도치 않게 풀려 출고될 수 있다. 푸는 것은 명시적인 상태 변경으로만.
