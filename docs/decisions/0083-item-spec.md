## 결정

### 단위는 레벨별 1행 (`tb_item_unit`)

- 레벨 `BASE`(기본단위, 환산수량 1, 필수)·`INNER`·`BOX`·`PLT`. 품목 안에서 레벨마다 1행, 같은 단위를 두 레벨에 쓸 수 없다 (`UNIQUE(item_id, unit_level_cd)`).
- 기본단위는 포장이 아닌 단위(수량·중량 등), 나머지 레벨은 포장 단위(PACK)만. 환산수량은 "이 단위 1개 = 기본단위 n개".
- 검증: 위 레벨일수록 커야 한다(BASE < INNER < BOX < PLT, 어기면 거부). 소수 자리는 기본단위를 따른다(EA 정수, KG 3자리). BOX가 INNER의 배수가 아니면 경고만.
- 기존 품목은 마이그레이션이 레벨을 정하고 BASE 행을 넣었다. 다른 기능(ASN·재고·라벨)이 "환산단위"를 읽을 때는 `level <> 'BASE'`로 거른다.
- 기본 입고·주문단위는 비우면 NULL = 자동 (입고 = BOX, 없으면 기본단위 / 주문 = 기본단위). 실제 값은 `loadItemUoms`.

### 규격·체적

- 규격은 cm·kg, CBM은 가로×세로×높이로 자동(고정 소수점). **체적은 BOX 규격 기준** — BOX 규격이 없으면 "체적 미등록".
- 밀도(총중량 ÷ CBM)가 10~5,000 kg/m³를 벗어나면 단위 오입력 의심 경고 (cm 대신 mm로 넣으면 체적이 1,000배).

### 팔레트 종류 (`tb_pallet_type`)와 PLT 계산

- 시스템 기본 행(operator NULL, T11·T12)을 모든 운영사가 읽고, 운영사 행이 같은 코드를 **덮어쓴다**(단위 0079와 같은 방식). 시스템 행은 고치거나 지울 수 없다. 운영사 기본 팔레트는 `tb_operator.default_pallet_type_cd`.
- 품목에 팔레트 종류·TI·HI(또는 팔레트당 박스 수)를 저장한다. 저장할 때 서버가 PLT 행을 계산해 넣는다(`auto_calc_yn = 'Y'`):
  - 환산수량 = 박스 수 × BOX 환산수량, 높이 = HI × BOX 높이 + 팔레트 높이, 중량 = 박스 수 × BOX 총중량 + 팔레트 자체 중량, 가로·세로 = 팔레트 규격.
  - 보낸 PLT 값이 계산과 다르면 계산값으로 바꾸고 `PLT_RECALCULATED` 경고. 권장 높이·최대 중량을 넘으면 경고(저장은 된다).
- 팔레트 규격을 바꿔도 기존 품목의 PLT는 **다시 저장할 때** 바뀐다(조용히 바뀌지 않게).

### 기한·LOT은 품목의 명시값 (0041의 "화주사 기본값 따름" 대체)

- 0041은 로트·유통기한을 NULL(화주사 값 따름)로 둘 수 있었다. 정의서는 품목마다 기한 종류·입력 방식·LOT 생성 방식까지 정하므로, **품목에 Y/N을 명시**한다. 새 품목 화면은 화주사 설정을 처음 값으로 채운다. 기존 NULL은 마이그레이션이 화주사 ?? 운영사 값으로 채웠다.
- 조건부 필수(입력 규칙 + DB 검사 조건): 기한 관리 → 기한 종류·입력 방식, 제조일 입력 → 총 기한 일수, LOT 관리 → 생성 방식. 관리하지 않으면 기한 칸은 비워 저장.
- 라벨 단위·재고할당 규칙은 지금처럼 "화주사 값 따름"(NULL)을 허용한다.
- **재고나 미완료 ASN이 있으면** 기본단위·기한/LOT/시리얼 관리 여부를 바꿀 수 없다(재고 구조가 바뀜). 환산수량 변경은 그 단위로 입력된 미완료 ASN이 있으면 막고, 바뀐 것은 `tb_item_unit_hist`에 남긴다.

### 바코드 (`tb_item_barcode`)

- 품목 1 : 바코드 N(최대 50), 바코드마다 단위·종류·대표 여부. 단위별 대표 1개(부분 고유 인덱스), 안 고르면 단위의 첫 바코드.
- EAN-13·EAN-8·UPC-A·ITF-14는 GS1 체크디지트를 검사한다.
- **같은 화주사 안에서만** 겹칠 수 없다(다른 화주사는 같은 바코드 허용). 품목을 지우면 바코드 행도 지워 다른 품목이 쓸 수 있게 한다.
- 옛 `tb_item.barcode`는 마이그레이션이 바코드 표(기본단위, 대표)로 옮기고 칸을 지웠다. 목록·재고·재고 조정 검색은 바코드 표를 본다.

### 상수 + DB 검사 조건

품목 유형·상태(단종 포함)·단위 레벨·기한 종류·입력 방식·LOT 생성 방식·바코드 종류는 프로그램이 값에 따라 동작을 바꾸므로 상수(`item-codes.ts`)와 DB 검사 조건으로 둔다(0040). 분류(category)는 자유 글자.

### 경고 (저장은 되고 알려 줌)

| 코드 | 뜻 |
| --- | --- |
| `VOLUME_MISSING` | BOX 규격(가로·세로·높이·총중량)이 없어 체적 미등록 |
| `DENSITY_SUSPICIOUS` | 밀도가 10~5,000 kg/m³ 밖 (단위 오입력 의심) |
| `PLT_RECALCULATED` | 보낸 PLT를 팔레트 적재 정보로 다시 계산함 |
| `PALLET_HEIGHT_EXCEEDED` / `PALLET_WEIGHT_EXCEEDED` | 팔레트 권장 높이 / 최대 중량 초과 |
| `UOM_NOT_MULTIPLE` | BOX 환산수량이 INNER의 배수가 아님 |
| `STACK_LIMIT_CONFLICT` | 최대 적층 단수보다 팔레트 단수(HI)가 많음 |

화면은 "확인할 것: …"으로 보여 주고, ③ API는 결과에 코드 목록으로 돌려준다.

### 환산 함수

- 순수 함수(`item-uom.ts`, 화면에서도 사용 가능)와 DB를 읽는 서버 함수(`item-convert.ts`)로 나눈다.
  - `toItemBaseQty` — 이 단위 수량 → 기본단위 (재고 저장 직전 반드시 사용). `convert.ts`의 `toBaseQty`(입수량을 직접 받는 함수)와 헷갈리지 않게 이름에 `Item`을 붙였다.
  - `convertItemQty` — 단위 간 환산. 대상 단위 자리수로 나누어떨어지지 않으면 오류, `remainder` 옵션이면 내림 + 나머지(기본단위).
  - `splitByUom` — 큰 단위부터 나누기 (1,000 EA → 1 PLT · 1 BOX · 16 EA).
  - `calcItemVolume` — 수량의 CBM·중량. BOX 규격 기준, 나머지는 낱개(BASE) 규격이 있으면 그것으로, 없으면 BOX를 비례로. BOX 규격이 없으면 `VOLUME_MISSING`.
- 한 품목으로 여러 번 계산할 때는 `loadItemUoms`로 한 번 읽고 `…In` 함수를 쓴다.

## ② 단계 — 목록·일괄 처리·엑셀 업로드 (2026-11-20)

### 사용자 결정 (모두 추천안)

| 항목 | 결정 |
| --- | --- |
| 엑셀 바코드 | 품목 시트에 **단위별 대표 바코드 칸**(기본단위·INNER·BOX·PLT). 바코드 시트는 두지 않음 (공통 업로드 틀은 입력 시트 1장) |
| 엑셀 수정 때 빈 칸 | **그대로 둠** (넣은 칸만 고침 — 거래처 업로드·API와 같음) |
| 팔레트 일괄 입력 | 계산할 수 없는 품목(BOX 없음 등)은 **건너뛰고 나머지 적용**, 건너뛴 품목·사유를 결과로 |
| 화주 포털 | **목록 개선만** 함께. 상태 일괄·팔레트 일괄·엑셀 업로드는 운영사 화면만 |

### upsert 서비스 (`item-upsert.ts`)

- 화주사 + 품목코드로 찾는다. 있으면 저장된 값(`itemInputOf`), 없으면 새 품목 처음 값(`item-defaults.ts` — 화면과 같은 값: 화주사 기한·LOT·시리얼 복사, 운영사 기본 팔레트) 위에 부르는 쪽의 `patch`가 **보낸 칸만** 덮어쓴다.
  - 엑셀은 평면 칸, ③ API는 단위·바코드 배열이라 덮어쓰는 방법을 부르는 쪽이 정한다.
- 입력 규칙으로 정리한 값이 전과 같으면 `UNCHANGED` (수정하지 않아 버전·이력이 늘지 않는다). 상태(단종 포함)도 함께 받는다.
- 저장은 화면과 같은 `createItemIn`·`updateItemIn` — 단위 검사·PLT 계산·경고·수정 제한이 모두 같다.

### 목록

- 정의서 6장의 칸·상세 검색. **체적 미등록** = BOX 행이 없거나 BOX 가로·세로·높이·총중량 중 하나라도 없음. **PLT 미등록** = PLT 행 없음.
- 상태 거르기에 단종. 상태 칸은 배지(사용·사용중지·단종), `isActive` 대신 `status`를 그대로 보낸다.

### 상태 일괄 변경

- 사용·사용중지·단종. 단종 품목은 새 입고예정(ASN)의 품목 고르기에서 빠지고, 넣으려 하면 "단종된 품목" 오류. 남은 재고 출고 허용은 출고 기능 때.

### 팔레트 적재 일괄 입력 (`item-bulk.ts`)

- 품목마다 따로 트랜잭션: 저장된 값에 팔레트 칸만 바꿔 `updateItemIn`으로 저장(일반 수정과 같은 길). BOX가 없거나 입력 규칙·업무 오류면 건너뛰고 사유를 모은다.
- 결과: 대상 수·적용 수·경고(높이·중량 초과 등) 품목 수·건너뛴 품목.

### 엑셀 업로드 (`item-upload.ts`, `item-upload-template.ts`)

- 1행 1품목 평면 형식. 단위는 코드로(BOX단위를 비우면 BOX, PLT는 시스템 PLT), 바코드 종류는 자리수로 짐작(13 → EAN-13, 14 → ITF-14 등, 나머지 화주 자체).
- 기한관리 Y만 넣으면 소비기한·기한일 입력, LOT관리 Y만 넣으면 입고 시 입력 (화면·새 품목과 같은 처음 값).
- 형식 오류(없는 화주사·단위 코드, Y/N·숫자, 같은 품목 두 줄)는 그 칸에, 업무 오류(입력 규칙·단위 순서·바코드 중복 등)는 그 행에. 미리보기는 같은 처리를 해 보고 되돌리며, 요약에 신규·수정·변경 없음·체적 미등록·팔레트 높이/중량 초과 건수.
- 오류가 하나라도 있으면 전체 등록 안 함(0049). 권한은 등록·수정 둘 다(거래처 업로드와 같다).

## 버린 안

- **새 표 `tb_item_uom`**: 이미 ASN·재고·라벨이 `tb_item_unit`을 읽고 있어, 표를 바꾸면 고칠 곳만 늘어난다.
- **PLT를 늘 직접 입력**: 팔레트 규격과 맞지 않는 값이 쌓인다. 적재 정보가 있으면 계산이 기준.
- **PLT를 늘 계산(직접 입력 금지)**: 적재 정보를 모르는 화주가 많아 등록이 막힌다.
- **바코드를 운영사 전체에서 고유**: 같은 상품을 여러 화주가 맡기는 경우를 막는다.
- **로트·유통기한 상속(0041) 유지**: 기한 종류·생성 방식까지 품목마다 달라 상속으로는 표현이 안 된다.
- **엑셀 바코드 시트 따로 (②)**: 공통 업로드 틀을 여러 시트로 넓혀야 한다. 대표 바코드는 칸으로 충분하고 여러 개는 화면·API로.
- **엑셀 빈 칸 = 지움 (②)**: 실수로 비운 칸이 규격·바코드를 지운다.
- **팔레트 일괄을 전부 아니면 전무로 (②)**: BOX 없는 품목 하나 때문에 나머지를 못 넣는다.
