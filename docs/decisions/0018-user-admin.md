# 0018. 사용자 관리 화면과 권한 상승 방지

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0010 (계정), 0013 (권한 계산), 0016 (데이터 범위), 0017 (권한그룹)
- 화면: `/admin/system/users` (목록), `/new` (등록), `/[id]` (수정 + 계정 관리)

## 결정

### 시스템 메뉴는 운영사 사용자만 (권한 상승 방지)

- `system.*` 권한(사용자·권한그룹·자료 추출)은 **운영사가 아닌 사용자에게 계산되지 않는다** — 그룹으로 받든 개별 추가로 받든.
- 이유: 센터 직원이 자기에게 "슈퍼 관리자"를 배정하는 권한 상승을 원천 차단. PRD상 권한 관리는 운영사 관리자의 일.
- 사용자 관리 서버 액션은 운영사인지 한 번 더 확인한다 (`requireOperator`).
- 브라우저 확인: 센터 직원에게 "슈퍼 관리자" 그룹을 배정해도 시스템 묶음이 보이지 않고, 주소를 직접 열면 "접근 권한이 없습니다".

### 계정 규칙

| 규칙 | 이유 |
|---|---|
| 아이디·사용자 유형은 등록 후 변경 불가 | 유형이 바뀌면 소속·데이터 범위가 통째로 바뀐다. 필요하면 새 계정 |
| 삭제하지 않고 사용 중지만 | 입고·재고 이력에 "누가 했는지"가 남아야 한다 |
| 자기 자신은 사용 중지 불가 | 마지막 관리자가 자신을 잠그는 사고 방지 |
| 사용 중지·비밀번호 초기화 시 기존 로그인 즉시 끊김 | 퇴사자·유출 대응 |
| 권한그룹은 사용자 유형에 맞는 영역만 | 운영사·센터 → 운영사 화면 그룹, 화주사 → 포털 그룹 |
| 소속 규칙은 등록·수정 공용 함수 | `src/lib/users/affiliation.ts` |
| 이메일이 없으면 내부용 주소(`아이디@users.local`), 화면에는 표시하지 않음 | Better Auth는 이메일 칸 필수 |

### 개발용 예시 조직

- 시드에 예시 센터 2곳(ICN 이천센터, GMH 김해센터)·화주사 2곳(GANA 가나식품, DARA 다라전자)을 추가. 코드 기준으로 없을 때만 만든다.
- 센터·화주사 관리 화면은 M2·M3.
