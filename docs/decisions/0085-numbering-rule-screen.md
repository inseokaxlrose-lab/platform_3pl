# 0085. 체번 규칙 관리 화면 — 운영사 재정의·겹침 검사

- 날짜: 2026-11-20
- 상태: 채택
- 관련: 0084 (체번 기반·코드 3층), 0025 (기준정보 코드 체계), 0038 (버전), 0083 (팔레트 종류 — 같은 시스템/운영사 공유 방식)
- 코드: `src/lib/numbering/numbering-rule-schema.ts` (입력 규칙·구조 검사, 화면·서버 공용), `numbering-rules.ts` (목록·저장·되돌리기·겹침 검사), `numbering-codes.ts`의 `previewCode`, `src/app/admin/system/numbering/`
- 권한: `system.numbering` (read·update), 마이그레이션 `20261120060000_numbering_permission` (기존 운영사 슈퍼 관리자 그룹에 추가)

## 배경

0084에서 체번 규칙 표에 운영사 행(재정의)을 둘 수 있게 했지만 넣는 화면이 없었다. 운영사마다 문서번호 접두어·자리수를 자기 업무 관례에 맞추고 싶어 한다.

## 사용자 결정 (2026-11-20, 모두 추천안)

1. **운영사 화면에서 재정의**: 메뉴는 `/admin/system/numbering`(시스템 > 체번 규칙). 시스템 기본은 보기만 한다(플랫폼 화면에서 고치지 않음).
2. **모양 칸만 편집**: 고정 접두어(영문 대문자 1~5자)·구분 문자(1자)·날짜(없음/YYMMDD)·구분자(없음/`-`/`_`)·자리수(2~8)·초기화 주기. **번호 범위(scope)와 접두어 출처(prefixSource)는 시스템 기본 그대로** — 범위를 바꾸면 카운터 키가 바뀌고, 접두어 출처를 바꾸면 화주 접두어·상위 코드 구조(0084 ②)가 깨진다.
3. **발급 후에도 변경 허용, 단 기존 코드와 겹치는지 검사**.

## 화면

- 목록: 대상 8개(검색 조건 없음 — `MasterListPage`는 조건이 없으면 검색 상자를 그리지 않는다), 번호 모양·다음 번호·범위·초기화·적용 규칙(시스템 기본/운영사 규칙)·발급 여부.
- 수정: `MasterFormPage` + `useMasterForm`. 바꾸는 즉시 미리보기(다음 번호·번호 모양·시스템 기본)를 화면에서 계산한다 — 서버가 준 재료(접두어 예, 초기화 주기별 다음 카운터, 운영사 타임존)로 순수 함수 `previewCode`.
- 저장하면 운영사 행을 만들거나 고친다(버전 검사 0038). [기본으로 되돌리기]는 운영사 행을 지운다.

## 검사

- **구조 검사** (`numberingRuleIssues`, 화면·서버 공용): 초기화 주기가 있으면 날짜 필수, 고정 접두어 모양, 가장 긴 번호(접두어 최대 길이 + 구분 문자 + 날짜 6 + 구분자 + 자리수)가 대상 코드 칸(VARCHAR) 길이를 넘지 않을 것.
- **겹침 검사** (`findCodeConflicts`, 저장·되돌리기 모두):
  - 카운터는 모양이 바뀌어도 이어진다(같은 범위·주기 키). 그래서 이미 자동 발급한 번호는 다시 나오지 않는다.
  - 위험한 것은 (가) 예전 모양에서는 자동 모양이 아니라 **직접 넣을 수 있었던 코드**와 (나) 초기화 주기를 바꿔 카운터가 1부터 다시 시작하는 경우다.
  - 그래서 범위마다 "새 앞부분(접두어+구분 문자+오늘 날짜+구분자)으로 시작하고, 나머지가 숫자이며 자리수 이상이고, 값이 그 범위의 현재 카운터보다 큰" 코드가 있으면 거부하고 겹치는 코드를 최대 5개 보여 준다. 지운(`del_yn='Y'`) 줄도 포함한다(DB 고유 인덱스는 지운 줄을 빼지만, 되살리기에서 부딪히므로).
  - 날짜가 있는 모양은 오늘 날짜 기준만 본다 — 다른 날짜의 번호는 그 날이 와야 나오고, 그때는 날짜가 다르다.

## 버린 안

- **발급 후 변경 금지**: 운영 중 접두어 하나 바꾸려 해도 막혀 운영사가 결국 시스템 관리자에게 DB 수정을 부탁하게 된다. 카운터가 이어지므로 겹침 검사로 충분하다.
- **범위·접두어 출처까지 편집**: 카운터 키·코드 3층 구조가 대상별 업무 의미와 묶여 있어 바꾸면 기존 번호와의 관계를 설명할 수 없다.
- **새 모양 적용 시 카운터를 1로 초기화**: 같은 모양의 옛 번호와 겹칠 위험만 늘어난다.
- **미리보기를 서버에 매번 물어보기**: 칸을 바꿀 때마다 요청이 나간다. 재료만 받고 화면에서 같은 순수 함수로 계산한다.
