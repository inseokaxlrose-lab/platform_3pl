# 0030. 공통코드 (코드 그룹 → 코드 2단계)

- 날짜: 2026-11-15
- 상태: 채택
- 관련: 0025 (기준정보 코드 3층 — 공통코드와는 다른 것), 0018 (시스템 메뉴는 운영사 사용자만), 0021 (그리드 설정)
- 화면: `/admin/system/codes` (권한 `system.codes`)
- 코드: `src/lib/common-code/`, `src/components/common-code/`, `src/app/admin/system/codes/`, `prisma/seed-codes.ts`

## 결정

### 구조

- **코드 그룹(`CodeGroup`) → 코드(`CodeItem`) 2단계** (사용자 결정: 하드코딩 대신 코드화해서 관리).
- 그룹: 그룹 코드(전체 고유, 예 `CONTACT_DUTY`)·이름·설명·정렬 순서·사용 여부·**시스템 그룹 여부**.
- 코드: 그룹·코드(그룹 안 고유, 예 `INBOUND`)·이름·설명·정렬 순서·사용 여부.
- **업무 표에는 코드 글자를 그대로 저장**한다 (예: 담당자 `duty = 'INBOUND'`). id보다 읽기 쉽고 외부 시스템과 주고받기 쉽다. 외래키를 걸지 않으므로 저장할 때 `assertCodeValues`로 검사한다.

### 무엇을 공통코드로 두나

- **분류·표시용 값만** 공통코드로 둔다 (담당 업무, 앞으로 화주 업종·품목 분류 등).
- **프로그램이 값에 따라 동작을 바꾸는 값은 enum으로 둔다** (창고 유형 `INBOUND_STAGING`, 보관 조건, 사용자 유형 등). 관리 화면에서 누가 지우거나 바꾸면 기능이 깨지기 때문.

### 규칙

- 그룹 코드·코드는 **등록 후 바꿀 수 없다** (업무 표에 저장된 글자가 가리키는 대상이 바뀌므로). 이름·설명·순서·사용 여부만 고친다.
- **사용 중지**: 새로 고르는 목록에서만 숨긴다. 이미 저장된 값은 이름으로 계속 보이고, 저장할 때도 그대로 둘 수 있다(`keep`).
- **삭제**: 그룹은 코드가 하나도 없고 시스템 그룹이 아닐 때만. 코드는 업무 표에서 쓰이지 않을 때만 — 어느 표가 어느 그룹을 쓰는지는 `code-usage.ts`의 등록표로 센다. **공통코드를 쓰는 칸을 새로 만들면 등록표에 추가**한다.
- **시스템 그룹**: 프로그램이 쓰는 그룹. 시드가 만들고(운영에서도 — 견본 데이터가 아님), 삭제·사용 중지할 수 없다. 시드는 "없으면 만들기"만 해서 화면에서 고친 이름·순서를 되돌리지 않는다.
- 시스템 데이터라 데이터 범위는 없다. 시스템 메뉴라 운영사 사용자만 권한을 가질 수 있다(0018).

### 화면에 나눠 주기

- 화면 틀(`AppShell`)이 요청마다 **사용 중인 그룹의 코드 전체**를 한 번 읽어 `CommonCodeProvider`로 나눠 준다. 화면은 `useCodeOptions('CONTACT_DUTY')`(다음 작업의 `CodeSelect`)로 꺼내 쓴다. 수백 개 수준이라 한 번에 읽어도 부담이 없고 화면에서 기다리지 않는다. 수천 개를 넘으면 그룹별 지연 읽기로 바꾼다.
- 관리 화면에서 저장하면 `router.refresh()`로 새 목록이 내려온다.

### 관리 화면

- 왼쪽 그룹 목록에서 **행을 누르면** 오른쪽에 그 그룹의 코드. 이를 위해 `DataGrid`에 `onRowClick`·`activeRowId`(고른 행 강조, Enter 지원, 행 안의 버튼·체크박스 클릭은 제외)를 추가했다.
- 등록·수정은 그룹·코드 공용 팝업. 코드 행을 누르면 수정 팝업, 삭제는 팝업 안에서 확인 후.
