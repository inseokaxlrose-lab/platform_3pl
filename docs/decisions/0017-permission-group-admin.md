# 0017. 권한그룹 관리 화면 (첫 업무 화면)

- 날짜: 2026-11-13
- 상태: 채택
- 관련: 0011 (권한 코드), 0013 (권한 계산), 0015 (서버 액션), 0016 (데이터 범위)
- 화면: `/admin/system/roles` (목록), `/new` (등록), `/[id]` (수정)

## 결정

### 권한그룹 영역(`area`: ADMIN / PORTAL)

- 그룹이 다루는 영역을 둔다. 체크 표에는 그 영역의 메뉴만 나오고, 사용자 배정 시 유형에 맞는 그룹만 고를 수 있게 한다 (사용자 관리 화면에서).
- **등록 후 변경 불가**: 바꾸면 체크한 권한이 모두 의미 없어진다.

### 권한 체크 표

- 메뉴(줄) × 동작(칸), 메뉴에 있는 동작만 체크박스. 묶음 전체·줄 전체 선택.
- 버튼 권한 체크 → 조회 자동 체크, 조회 해제 → 줄 전체 해제 (0013 5번 규칙을 화면에서도).
- 목록 화면이 아닌 입력 부품이라 DataGrid·`<table>` 대신 CSS 격자로 만든다.
- 서버도 같은 규칙(`normalizeGroupCodes`)으로 한 번 더 정리해 저장한다: 다른 영역·목록에 없는 코드 제거, 조회 자동 추가.

### 삭제

- 사용자가 남은 그룹은 삭제 불가 → "사용자 N명이 이 권한그룹을 사용 중입니다. 먼저 사용자에게서 그룹을 빼 주세요." (DB Restrict + 서버에서 먼저 확인해 이유 안내)

### 공통 장치 (이후 모든 목록 화면이 재사용)

- `toPrismaQuery` (`src/lib/grid/grid-query.ts`): 그리드 상태 → `{ where, orderBy, skip, take }`. 정렬은 허용한 컬럼만.
- `dataGridStateSchema`: 서버 입력 검사 (정해진 건수만, 검색어 100자 이하).
- 목록 조회도 `createAction`(권한 `*.read`)으로 만든다.

### 데이터 범위

- 권한그룹은 운영사 전체 설정이라 센터·화주사 범위를 적용하지 않는다.

## 개발용 슈퍼 계정 (`npm run db:seed`)

- "슈퍼 관리자" 그룹(운영사 화면의 모든 권한, 시드 실행 때마다 최신 목록으로 맞춤) + 운영사 계정.
- 아이디·비밀번호는 `.env`의 `SEED_ADMIN_USERNAME` / `SEED_ADMIN_PASSWORD` (코드·Git에 비밀번호를 두지 않는다). 기존 계정 비밀번호는 덮어쓰지 않는다.

## 확인

- DB 테스트: 서버 액션 8개 (정리 규칙, 이름 중복, 통째 교체·옛 코드 정리, 삭제 규칙, 목록, 권한 없음)
- 화면 부품 테스트: 체크 표 4개, 체크 규칙 단위 6개, 조회 도우미 5개
- 브라우저(슈퍼 계정): 목록 → 등록(조회 자동 체크 확인) → 저장 → 수정 화면 체크 상태 → 사용 중 그룹 삭제 차단 메시지 → 확인용 그룹 삭제
