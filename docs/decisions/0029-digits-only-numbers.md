# 0029. 사업자등록번호·전화번호는 숫자만 저장

- 날짜: 2026-11-15
- 상태: 채택 (0024의 "사업자등록번호 저장은 `000-00-00000` 모양"을 대체)
- 관련: 0024 (운영사 정보), 0026 (센터), 0025 (외부 시스템 연동)
- 코드: `src/lib/format/` (포맷 ↔ 숫자 변환), `src/lib/validation/common-fields.ts` (`optionalPhone`)

## 결정

- **DB에는 숫자만 저장하고, 하이픈은 화면에 보여줄 때만 붙인다** (사용자 결정).
  - 사업자등록번호 `2208112341` → 표시 `220-81-12341`
  - 법인등록번호 `1101111111113` → 표시 `110111-1111113` (아직 쓰는 화면 없음, 유틸만)
  - 전화·팩스·휴대폰 `021234567` → 표시 `02-123-4567`
- 입력은 하이픈·띄어쓰기를 넣어도 받아 주고, 입력 규칙(Zod)의 변환 단계에서 숫자만 남긴다. 그 밖의 글자가 섞이면 거부한다(숫자만 남기면 뜻이 바뀌므로).
- 포맷·검사 함수는 `src/lib/format/` 한 곳에만 둔다. 화면마다 따로 만들지 않는다.

### 전화번호 규칙 (`formatPhone`, `isValidPhone`)

| 앞자리 | 자릿수 | 표시 |
|---|---|---|
| 02 (서울) | 9~10 | `02-123-4567`, `02-1234-5678` |
| 0xx (지역·휴대폰·070) | 10~11 | `031-123-4567`, `010-1234-5678` |
| 050x (평생번호) | 11~12 | `0505-1234-5678` |
| 15xx·16xx·18xx (대표번호) | 8 | `1588-1234` |

- 이전 규칙(숫자 8~12자리)보다 엄격하다. `1234-5678` 같은 없는 번호를 막는다.
- 포맷 함수는 입력 중인 짧은 값도 자리까지만 끊어 보여준다(`0101` → `010-1`). 다음 작업의 입력 부품(PhoneInput 등)이 이걸 그대로 쓴다.

## 이유

- 외부 시스템(SAP·ERP, 0025)과 주고받을 때 형식 차이가 없고, 검색·중복 비교가 단순해진다.
- 표시 형식을 바꾸고 싶을 때 데이터를 고칠 필요 없이 함수 하나만 고치면 된다.

## 기존 데이터

- 마이그레이션 `digits_only_numbers`가 운영사·운영사 담당자·센터의 번호 칸에서 숫자 외 글자를 지운다(빈 글자가 되면 null). 표 구조는 바뀌지 않는다.
