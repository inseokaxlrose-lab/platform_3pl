# 0002. UI 방향과 공통 DataGrid

- 날짜: 2026-11-13
- 상태: 채택

## 배경

- 최신 트렌드의 깔끔하고 심미적인 UI를 원함
- 업무용 B2B라 화면 대부분이 그리드(표) → 그리드 품질이 곧 제품 품질
- 화면마다 표를 따로 만들면 모양·동작이 제각각이 되고, AI가 매번 다르게 만든다

## 결정 1. UI 방향

- shadcn/ui + Tailwind 기반 디자인 시스템을 먼저 정하고(색상 토큰, 글꼴, 간격) 모든 화면이 이를 따른다
- 스타일 키워드: 넓은 여백, 얇은 테두리, 절제된 색 (포인트 컬러 1개), 상태는 색 배지로 표시
- 라이트 / 다크 모드 지원
- 레이아웃: 왼쪽 사이드바 메뉴 + 상단 바 + 본문 (운영사 화면 / 화주 포털 공통 뼈대)
- 정보 밀도: 업무용이므로 표는 촘촘하게(행 높이 조절 옵션 제공), 나머지는 여유 있게

## 결정 2. 공통 DataGrid "라이브러리"

**TanStack Table(동작 엔진) 위에 우리만의 `DataGrid` 컴포넌트를 만들어** 모든 목록 화면에서 재사용한다.

비유: TanStack Table은 "엔진", 우리가 만드는 `DataGrid`는 엔진을 넣어 완성한 "자동차". 화면 개발자는 자동차만 운전(설정만 전달)한다.

### 위치

`src/components/data-grid/` 폴더 하나에 모아 라이브러리처럼 관리하고, 바깥에서는 `index.ts`로 공개된 것만 사용한다.

### 사용 모습 (목표)

```tsx
<DataGrid
  id='inventory-list'          // 사용자별 컬럼 설정 저장 키
  columns={inventoryColumns}
  data={rows}
  rowCount={total}             // 서버 페이지네이션용 전체 건수
  state={gridState}            // 정렬·필터·페이지 상태 (URL과 동기화)
  onStateChange={setGridState}
  enableRowSelection
  toolbar={{ search: true, export: true, columnToggle: true }}
/>
```

### 기능 단계

| 단계 | 기능 |
|---|---|
| 1차 (M0.5) | 정렬, 페이지네이션(서버 방식), 검색, 컬럼 숨김/표시, 행 선택, 로딩·빈 상태, 숫자·날짜·상태 배지 셀 서식 |
| 2차 (M2~M4 진행하며) | 컬럼 필터, 컬럼 너비 조절·순서 변경 ✅, 왼쪽 고정 컬럼, 설정 저장 ✅ (0021), 엑셀(CSV) 내보내기 ✅, 정렬·필터 URL 동기화 |
| 3차 (필요할 때) | 가상 스크롤(대량 데이터), 인라인 편집, 합계 행 |

### 원칙

- 화면에서 `<table>`이나 TanStack Table을 직접 쓰지 않는다. 기능이 부족하면 `DataGrid`에 기능을 추가한다.
- `/dev/grid` 쇼케이스 페이지에서 가짜 데이터로 모든 기능을 눈으로 확인할 수 있게 유지한다.
- 그리드 핵심 로직(정렬·페이지 상태 변환 등)은 Vitest로 테스트한다.

## 대안과 버린 이유

- **AG Grid**: 기능은 가장 많지만 고급 기능은 유료, 디자인을 shadcn 스타일에 맞추기 어렵고 무겁다.
- **MUI DataGrid**: 다른 디자인 시스템(Material)이 섞여 일관성이 깨진다.
- **화면마다 직접 표 작성**: 일관성·생산성 모두 나쁨.
