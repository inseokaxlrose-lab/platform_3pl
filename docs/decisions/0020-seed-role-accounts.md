# 0020. 개발용 역할별 권한그룹과 견본 계정

- 날짜: 2026-11-13
- 상태: 채택
- 관련: PRD 3장 (사용자와 역할), 0013 (권한 계산), 0018 (시스템 메뉴는 운영사만)
- 코드: `prisma/seed-roles.ts` (정의), `prisma/seed.ts` (실행), `prisma/seed-roles.test.ts` (검사)

## 결정

### 역할별 기본 권한그룹 (시드가 관리)

| 그룹 | 영역 | 권한 수 | 내용 |
|---|---|---|---|
| 슈퍼 관리자 | 운영사 화면 | 66 | 운영사 화면의 모든 권한 (운영사 관리자용) |
| 센터 운영자 | 운영사 화면 | 37 | 기준정보 조회 + 품목·거래처 관리, 입고 전체, 재고 조회·이력, 실사 등록·**확정** |
| 센터 작업자 | 운영사 화면 | 14 | 품목·로케이션·ASN·재고 조회, 검수·라벨·입고 확정·적치, 실사 **등록만** |
| 화주사 사용자 | 포털 | 10 | 포털 품목·ASN 관리, 내 재고 조회·엑셀 |

- 실사·조정은 "작업자 등록 → 운영자 확정" 2단계라서, 확정 권한을 센터 운영자에게만 준다.
- 시스템 메뉴는 슈퍼 관리자만 (0018).
- 시드를 실행할 때마다 위 그룹의 권한 목록을 정의와 똑같이 맞춘다. 화면에서 이 그룹을 고쳐도 다음 시드 때 되돌아가므로, 회사별로 바꿀 권한은 **새 그룹을 만들어서** 쓴다.
- 단위 테스트: 정의된 모든 코드가 권한 계산을 거쳐도 하나도 빠지지 않는지 검사한다. 조회 누락, 다른 영역 코드, 시스템 권한 섞임을 막는다.

### 견본 계정 4개

- `ops.admin`, `center.manager`(이천센터), `center.worker`(이천센터), `shipper.user`(가나식품).
- 공통 비밀번호는 `.env`의 `SEED_SAMPLE_PASSWORD`이고 코드에는 두지 않는다. 계정 규칙(8자 이상)을 그대로 따른다.
- 없을 때만 만든다. 이미 있으면 비밀번호·소속·권한을 건드리지 않는다.
- 비밀번호가 비어 있거나 `NODE_ENV=production`이면 건너뛴다. 운영 DB에 모두가 아는 비밀번호의 계정이 생기는 것을 막는다.

## 확인

- 시드 두 번 실행: 첫 번째는 4개 생성, 두 번째는 "이미 있음"으로 그대로 뒀다.
- 4개 계정으로 로그인했을 때 사이드바 메뉴가 역할대로 보였다. 센터 운영자는 시스템 메뉴만 빠졌고, 센터 작업자는 현장 메뉴와 ASN 조회만 보였다. 화주사 사용자는 `/portal`의 포털 메뉴 4개만 보였다.
