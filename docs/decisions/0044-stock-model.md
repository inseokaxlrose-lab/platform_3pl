# 0044. 재고 · 재고 이력 DB 모델

- 날짜: 2026-11-15
- 상태: 채택 (M4 첫 작업 — 재고 변경 공통 함수는 다음 작업)
- 관련: 0003 결정 4 (재고의 주소), 0039 (멀티테넌트), 0041 (품목), 0042 (단위 환산), CLAUDE.md "재고는 직접 수정 금지 · 기본단위로 저장 · 로트·유통기한은 품목 설정에 따름"

## 구조

| 표 | 한 줄 | 주요 칸 |
| --- | --- | --- |
| `tb_stock` (재고) | 재고 주소 하나의 지금 수량 | 운영사, 센터·창고·로케이션, 화주사·품목, 로트번호·유통기한(안 쓰면 null), 수량 `stock_qty`·할당 `alloc_qty` (기본단위 DECIMAL(18,3)), 버전 |
| `tb_stock_txn` (재고 이력) | 수량이 바뀐 한 번 | 같은 주소 칸(그때 모습), 유형 `StockTxnType`(RECEIVE·MOVE_OUT·MOVE_IN·ADJUST), 변동 `chg_qty`(±)·변동 후 `after_qty`, 묶음 번호 `txn_group_id`, 원본 문서(`ref_type_cd`·`ref_id`·`ref_no`), 사유, 일시, 처리자 |

- 센터·창고·화주사는 로케이션·품목에서 정해지지만 조회가 빠르도록 함께 둔다. 맞춰 넣는 것은 재고 변경 공통 함수의 일.
- 수량이 0이 돼도 재고 줄은 남긴다 — 이력이 그 줄을 가리킨다(외래 키 Restrict).
- 두 표 모두 운영사 거르기 대상(`TENANT_MODELS`). 공통 칸(등록·수정자)·논리 삭제는 없다: 기준정보가 아니고, 누가 바꿨는지는 이력의 처리자가 남긴다.

## 결정 (사용자 결정, 2026-11-15)

- **재고 주소 고유 — 빈 칸도 같게(추천안)**: `로케이션 + 품목 + 로트 + 유통기한`에 `NULLS NOT DISTINCT` 고유 인덱스. 로트·유통기한을 안 쓰는 품목은 null이라 보통 고유 규칙으로는 같은 주소가 두 줄 생길 수 있다. Prisma 7 구조 파일은 이 옵션을 적을 수 없어(Prisma 8에서 지원) 구조 파일엔 같은 이름의 `@@unique`를 두고 마이그레이션 SQL에서 옵션을 붙였다. `migrate diff`는 이 차이를 보지 않는다(차이 0 확인).
- **이동 이력 — 나감·들어옴 두 줄 + 묶음 번호(추천안)**: 로케이션별 이력 조회가 단순하고 로트·유통기한별 합계가 늘 맞는다.
- **할당(출고 예약) 수량 — 지금 둔다**: 출고는 MVP 이후지만 칸과 규칙(0 이상, 수량 이하)을 미리 둔다.

## DB가 막는 것 (마지막 안전장치)

- 수량 0 이상, 할당 0 이상·수량 이하, 로트번호 빈 글자 금지(쓰지 않으면 null).
- 이력: 변동 수량 0 아님, 변동 후 0 이상, 조정(ADJUST)은 사유 필수.
- **이력은 고치거나 지울 수 없다**: `BEFORE UPDATE OR DELETE` 트리거가 오류를 낸다(테스트의 TRUNCATE와는 상관없다).

## 검증

- 빈 DB·개발 사본 적용 후 스키마 차이 없음(고유 인덱스가 실제로 NULLS NOT DISTINCT인지 확인). DB 규칙 테스트 6개(같은 주소 두 줄 거부·로트/유통기한이 다르면 허용, 음수·할당 초과·빈 로트 거부, 수량을 할당보다 작게 못 줄임, 이력 규칙, 이력 수정·삭제 거부, 이력이 있는 재고 줄 삭제 거부).
