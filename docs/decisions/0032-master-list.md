# 0032. 기준정보 목록·검색 화면 공통 틀 + 센터 목록 적용

- 날짜: 2026-11-15
- 상태: 채택
- 갱신: 2026-11-15 — 여기서 미뤘던 플랫폼 "운영사 목록"(멀티테넌트)은 M2.5에서 만들었다: `/platform/operators` (0039·0040)
- 관련: 0002 (DataGrid), 0021 (그리드 사용자 설정), 0031 (입력 화면 틀), 0030 (공통코드), 0016 (데이터 범위)
- 가이드: `docs/ui-guidelines.md` "목록·검색 화면" · 견본: `/dev/components`
- 코드: `src/components/master-list/`, `src/components/data-grid/`, `src/lib/grid/`, `src/app/admin/master/centers/`

## 결정

- **틀**: `MasterListPage`(헤더·검색·그리드) + `SearchPanel`(조건 정의 배열, 기본/상세) + `useListQuery`(URL 동기화·조회). 그리드는 새 라이브러리 없이 기존 `DataGrid`에 기능을 더했다.
- **URL이 상태의 원본**: 조건·페이지·건수·정렬을 쿼리스트링에 둔다. 뒤로 가기·공유·새로고침에 같은 결과. 기본값은 URL에 넣지 않는다. 정렬을 모두 푼 상태는 `sort=none`.
- **조회 규칙**: [조회]·Enter로만 적용, 조건 변경 시 1페이지, 마지막 요청만 반영(서버 액션은 중간 취소가 안 돼 늦은 응답을 버린다), 같은 요청 진행 중이면 다시 보내지 않음, 서버 액션이 예외로 실패해도 오류 상태로 끝냄.
- **목록 API 형식**: 기존 그리드 상태에 `filters`(키 → 글자)와 `exportAll`을 더한 `listQuerySchema`. 조건 해석은 서버의 순수 함수(`list-filters.ts`).
- **DataGrid 추가 기능**: 셀 서식(사업자번호·전화·Y/N·공통코드·소수·단위, 말줄임), 서식별 기본 정렬(숫자 오른쪽, 코드·날짜·상태 가운데, 글자 왼쪽), 왼쪽 고정 컬럼(그린 뒤 너비를 재서 위치를 정함), 기본 숨김, 링크 컬럼, 오류·다시 시도, 지금 보는 범위 표시.
- **엑셀**: CSV → **.xlsx (exceljs, 사용자 결정)**. 버튼을 누를 때만 불러온다(동적 import). 현재 조건 전체(최대 1만 건)를 보이는 컬럼·순서대로, 숫자는 숫자 칸·코드는 이름. 1만 건 초과는 서버 생성 방식으로 바꾼다(제안만).
  - exceljs 4.4.0의 하위 패키지(uuid·minimatch·deepmerge)에 npm audit 보통(moderate) 경고가 있다. 브라우저에서 파일을 쓰는 용도라 영향이 작다고 보고 유지, exceljs 새 버전이 나오면 올린다.
- **컬럼 설정 저장**: 이미 서버 저장(0021)이라 localStorage 단계는 두지 않았다.
- **권한**: 신규 등록·일괄 처리·엑셀은 page.tsx에서 권한을 계산해 넘기고, 서버 액션이 다시 검사한다. 센터에 엑셀 권한 `master.centers.export`를 더했다.
- **[목록] 버튼**: 목록이 마지막 주소를 세션 저장소에 기억, 상세의 `BackToListButton`이 그 주소로 돌아간다.
- 옛 `SearchPanel`(자유 배치, 견본에서만 사용)은 지웠다.

## "운영사 목록" 대신 센터 목록에 적용한 이유

요청은 플랫폼 관리자용 "운영사 목록"(멀티테넌트)이었지만, 이 시스템은 **운영사 1곳 전용**(PRD, 0024 `id='default'`)이라 운영사 목록·tenant 구분이 없다. 운영사 코드·상태·유형·요금제·계약종료일·센터 수·화주 수 칸도 없다. 멀티테넌트 전환은 모든 표·로그인·범위를 바꾸는 제품 결정이라 별도 설계로 미루고, 공통 틀은 센터 목록에 먼저 적용했다 (사용자 결정).

## 센터 목록

- 검색: 기본 = 검색어(코드·시스템 코드·이름·주소) · 상태(사용/사용 중지) · 대표 전화 / 상세 = 센터장 · 창고 보관 조건(여러 개) · 등록일.
- 컬럼: 센터 코드(고정·링크) · 센터명(고정) · 시스템 코드(숨김) · 주소 · 대표 전화 · 센터장 · 센터장 연락처(숨김) · 상태 · 창고 수 · 등록일 · 수정일시(숨김). 기본 정렬 센터 코드.
- 일괄 처리: 사용 중지 / 다시 사용 (운영사만, 대상 건수 확인).

## 옮기기 (2026-11-15 완료)

- 창고·로케이션·사용자·권한그룹 목록도 이 틀로 옮겼다 (공통코드 화면은 그룹→코드 2단 구조라 제외).
- 틀 보강: 검색 조건 **이어지는 고르기**(`options`를 함수로, `dependsOn`: 센터 → 창고 → 구역, 앞 조건을 바꾸면 뒤 조건을 비움).
- 엑셀 권한(`export`)을 창고·로케이션·사용자에 더했다(사용자 결정). 권한그룹은 건수가 적어 엑셀·일괄 처리 없음.
- 일괄 처리: 창고(입고대기 창고가 섞이면 사용 중지 거부), 로케이션(사용 중지·다시 사용·삭제), 사용자(자기 자신 사용 중지 거부, 사용 중지하면 로그인 끊음).
- 로케이션 목록 주소 조건은 `?warehouseId=` → `?warehouse=`(창고 상세의 [로케이션 관리] 링크도 함께).
- 고친 문제: 화면이 그릴 때마다 조건 정의 배열을 새로 만들면 조회가 반복될 수 있던 것(조건 키·종류 글자로 비교).
